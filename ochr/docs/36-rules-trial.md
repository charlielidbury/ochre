## 3. The relations (R) and why each parameter is there

`Conv.lean` defines, one constructor per paper rule:

- `ConvV E G gs`: conversion. `refl` ([Conv-refl], by `E.v`), `unit` ([Conv-unit]: the head rules applied to `unitTop v`, `unitTop w`, where `E.unit` allows). `ConvH`: the head rules: `refl`; [Conv-cong] for `succ`, `tRef`, `tInd`, `tEq`, `borrow`, `ind` (recorded parameters compared only when `E.ignoreParams = false`), `sealed` (by `ConvT`), `piCong` (same captures, readings by `RdEq`, code by `ConvT`); [Conv-pi] (`G.pi`); [Conv-fun] (`fn`: both function values, Π-types read off the globals `gs` or the code by `fnTyOf` and convertible, captures convertible, and `G.fn`). `ConvL`, `ConvT` (one constructor per term former, mirroring `convT`), `ConvTL`.
- `EqTo E G gs Γ A a b P`: "`Eq(A, a, b)` computes to `P`": `disjBot` ([Eq-disj] at `⊥`), `refl` ([Eq-refl] by `ConvV`), `succ` and `inj` ([Eq-inj]; `inj` takes the parameters `eqArgs` picks, the declaration from `Γ`, the index fields convertible for a dependent constructor, the field types from `G.fieldTys`, and `EqL` for the field equations, conjoined by `andList`), `disj` ([Eq-disj]), `stuck` ([Eq-stuck], no side condition: it is sound outright). Nondeterministic where the paper's clauses are ordered; every rule is sound on its own.

The parameters:

- `Syn` (the untyped parts): `v`, `t` (the syntactic equalities [Conv-refl] uses on values and terms), `unit` (where [Conv-unit] may rewrite), `ignoreParams`. The machine's instance `Syn.machine` is `==` (`Value.beq`, `Term.beq`: binder names AND recorded constructor parameters ignored), the unit laws everywhere, parameters ignored. They are parameters because the paper's conversion is untyped and the model typed: the machine's instance does not keep meanings on ill-typed values (section 4), so the instance part A can be proved for is not the one part B produces, and the bridge is a typing fact (section 6).
- `Premises` (the abstract premises): `fn` ([Conv-fun]'s generic call), `pi` ([Conv-pi]'s generic arguments, with its same-class and same-row checks, which are decisions read from the unknowns' frozen readings), `fieldTys` ([Eq-inj]'s field types at the parameters and the earlier fields). Each is a computation the paper does not define by rules. Part A assumes their soundness (`PremSound`); part B instantiates them with "the machine's run of exactly that sub-computation succeeded from a state the comparison reached" (`machPremisesR R st`). So their soundness is a statement about machine runs from reached states: for the function rules the bookkeeping is moved into the premise, not removed.
- `gs` (Σ's globals, for a global's declared Π-type) and `Γ` (the declarations, for [Eq-inj]): what R reads of the state, and all it reads.

## 4. Three of the area's statements are false

1. **`conv_sound_stmt`** (`Counter.conv_sound_stmt_false`, kernel-checked, at every run context admitting the start state). `Eq(Nat, And(True, Nat), Nat)` and `Eq(Nat, Nat, Nat)` are convertible to the checker ([Conv-unit] inside the `Eq`, the state unchanged), both are members of `Prop`, and they mean different propositions. The statement's only hypothesis on the values is membership at the top, which says nothing about the values inside an `Eq`. A typing gap, not bookkeeping.
2. **`mkEqM_step_stmt`** (`Counter.mkEqM_step_stmt_false`, kernel-checked). `Eq(Nat, ⊥, σ₀)` computes to `False` ([Eq-disj] at `⊥`), while `σ₀`, which the state does not reference, may be sent to `moved` by the assignment, so the statement asks `False` to mean `moved = moved`. The statement has no hypothesis on the sides. The fix in C: each side is `⊥` or a whole member of `A` (`SideOk`), and its constructor values are of data declarations (membership cannot give this: two constructors of a `Prop` inductive both mean `⋆`). **The caller in `EqJAsm` cannot supply it**: `side_step` gets from `eval_step` only that a side means the reference run's result; no statement anywhere concludes that the value an evaluation returns is a member of its type.
3. **`convPi_sound_stmt`** (`EmptyDomain.convPi_sound_stmt_false_of_run`). A comparison keeps the η-records its private copy made (`restoreKeep`, D37), and a typed run inside the copy (a parameter type or codomain evaluated at the generic arguments) refines a generic argument of a one-constructor type in place (D93). Over `inductive E1 := MkE1(e : Empty)` comparing `Π(x : E1). match x { MkE1(e) => Nat }` with `Π(y : E1). Nat` succeeds and leaves `σ₀ := MkE1(σ₁)`, `σ₁ : Empty`; `Refd.eta` makes `σ₁` referenced and `TypedAssignment.mem` asks a member of the empty type, so no extension makes the state after `Good` and `ExtOk` is false. The model side is kernel-checked; the machine run is a hypothesis, discharged by `#guard`, because the kernel cannot evaluate a run that reaches `firstLiveLoanOnPath` (well-founded recursion). Also seen at a real program's hole (`conv P2 Q2`, `conv F3 G3`). For the plain case the lead asked about, `Eq(Π(x : Empty). Nat, F, G)`, the comparison leaves the unknown and no record, and the `st.Refd σ` guards make it owe nothing. A bookkeeping fault; fixed by full restore (section 5).

A fourth is suspected and unchecked: the machine's `==` ignores recorded constructor parameters, so two closures or types differing only in a nested constructor's recorded parameters compare equal; whether such a pair can mean different things is the `HWT` question of section 6.

## 6. The typing gap

Membership of a value in a type says nothing about the values inside it that do not decide that membership: `Eq(A, a, b)` is a member of `Prop` whatever `a` and `b` are; an inductive type applied to anything is a type. Conversion compares component by component, so its soundness needs every component typed.

**`HWT K ρ φ T v`** (`Typed.lean`): `v` is a (partly moved) member of `T`, and each component a former reads is hereditarily well typed at the type the former expects: an `Eq`'s type at a universe and its sides at its type; an inductive type's arguments and a constructor value's recorded parameters at the parameter types (so `And`'s arguments are propositions); a constructor value's fields at the field types of its record (`T.dataRec?`); captures at their recorded types. For code (closures, Π-closures, sealed programs) it can only say that each written value is typed at SOME type (`HWTerm`), because which type a position of a term expects is a typing judgement for terms. `vBad_not_hwt` (kernel-checked): it excludes counterexample 1.

**Strict meanings** (assessment only; no model change in this trial). If every former's meaning were `err` unless its components are typed, then "has a level" would give what conversion needs for type values, and for code it would be stronger than `HWT` (it checks a value at the type its position is actually read at), while unread positions need no typing (a convertible counterpart reads the corresponding position at the same point, so it does not read it either). It would not reach decisions (section 7) or an unknown nothing references that the assignment sends to `moved`. The clauses that would have to become strict, in `meanV`/`Value.mean` and the matching `runT` clause:

1. `Eq(A, a, b)` (`.tEq`, `runT .eq`): `err` unless `⟦A⟧` has a level and each side is `moved` or a whole member of `⟦A⟧` (partly moved is too weak: D84's sides are `⊥` or whole).
2. `D(ā)` (`.tInd`, `runT .tind`): `err` unless each argument is a member of its parameter type (`K.dm.paramTy d i earlier`); this makes `And`'s arguments propositions.
3. `C(ā; v̄)` (`.ind`, `runT .ctor`): `err` unless the recorded parameters are members of the parameter types.
4. `&A` (`.tRef`): `err` unless `⟦A⟧` is a data type (D48).
5. Π-types (`runT .pi`, `runBinds`/`codOf`, so `.tPi`): `err` unless every domain and the codomain have a level at every argument tuple (today an error domain gives the function type over the empty carrier, which has a level and one member).
6. `(t : A)` (`runT .ascribe`): `err` unless the result is a member of `A` (today passed through).
7. The frames of closures and Π-closures (`capsState`): `err` unless each capture is a member of its recorded type.
8. `Id(A, t, u)` (`runT .id`): the sides at `A`.

Already strict: application (decoding at the domain code), closures (a member or `err`, `closureL_mem`), `Sem.succ`, sorts above the bounded levels, a bare constructor read with no data hint.

## 7. The decisions finding

**The observation** (`DecProbe.lean`). `F (n : Nat) : Unit := ()` and `H (n : Nat) : TF(Z) := ()` with `TF(n) := match n { Z => Unit, S _ => Nat }` are convertible, but the declared reading of `F` is `pi(unit)` and of `H` `pi(other)`, so the calls `F(0)`, `H(0)` read `unit` (a copy, η) and `other`; the checker accepts `let x = F(0); Mk(x, x)` and rejects `let x = H(0); Mk(x, x)`. This is intended by the rules (D80: copy and η read from declared types; a type `Unit` only by computation is not `Unit`), so the question is only the proof's: the model's run reads the decision table at terms, and convertible terms need not get the same decisions, so the smallest invariance [Conv-cong] on code would need ("decisions agree on terms that differ only by convertible embedded values") is false of the checker's decisions. The existing congruences do not cover the case: `run_congr` (`RunCongr.lean`) varies the future, `run_congrA` (`AssignCongr.lean`) the assignment, `SubstAbs` replaces one unknown by a value of the same meaning and run type under `DecInvariantAbs`.

**Why it is benign: the invariant** (`ShapeSweep.lean`, every recorded state of the suite: 76,568 states; 625,140 sealed programs; 68,500 closures and Π-closures).

- Every sealed program has [Close]'s shape (`closeCall` is the only maker): cells `let c = u` or `let c = (u : T)`, then the head call `f(ā)` marked as head, with `f` a value and each argument a value or a borrowed cell `&c`; then nothing, or `; peek(c)`, or `let r = f(ā); *r := v; peek(c)`, or `let r = f(ā); peek(*r)`. No exception.
- Closure and Π-closure code holds values only as an inlined proof `(⋆ : T)` ([Capture]), a stuck block function's binder types and codomain (possibly written with their sort, `(h : (False : Prop))`), and a `J` block's statements (type, endpoints, motive: `J Nat σ0 0 MN (⋆ : …) t`). 72 closures in 14 declarations hold values outside the first two kinds, all of the third.
- `conv` applies [Conv-cong] on code only to sealed programs (`.sealed t, .sealed u => convT`) and to Π-closures' code in the `piCong` fast path; closures' code only by `==`.

What the model's run reads of an embedded value at those positions: at a [Close] text, the call's erasure class and whether it returns a borrow (equal for convertible heads: [Conv-pi] compares both), whether the call's declared result reads `Unit` (can differ, `F` against `H`, but only by η at `Unit`, which maps a member of `Unit` to itself), whether an argument is a borrow (equal for convertible values), the cells' readings (cells are only borrowed and peeked, so no copy decision on them is exercised). Values at type positions reach the meaning only as types (a binder read `Unit` is again only η); `J`'s statements run on copies whose results are discarded. Such a text arises in accepted code: the generic run of `let f : Π(m : Nat). TF(Z) = FS; f(n)` gives `⌈FS(σ0)⌉`, whose head reads `unit` as a value though the call was made at `other`. No accepted pair with different meanings and no false equation was found. That the decisions read at those positions are the ones listed is from reading `Run.lean`; the positions themselves are from the sweep.

**The congruence part A needs, on the invariant**:

- sealed programs: two [Close]-shaped texts `t`, `u` with `ConvT t u` whose embedded values pairwise run alike (`ValAlike`) run alike (`TermAlike`), provided the head call's result at its arguments is a member of its codomain (what makes the η step harmless);
- Π-closures compared by `piCong` and closures compared by `==`: code that is `==` up to binder names and recorded parameters runs alike when the recorded parameters of corresponding embedded constructor values agree in meaning (the `HWT` point: they are pinned by the types of their positions) and the decisions ignore binder names and recorded parameters (`Decide.valueDecl`/`valTypeDecl` read neither).

## 8. Part B: what was proved, the idioms, what was awkward

`RefineConv.lean`: by induction on fuel over a conjunction of five predicates (`AllOK R n`: `conv`, `convList`, `convT`, `convTList`, `convFn`), each saying: from any state `R`-related to the comparison's start, the state after is `R`-related too, and a `true` answer is a derivation of `ConvV Syn.machine (machPremisesR R.rel st₀) st₀.globals`. `R : StateRel` is reflexive, transitive and keeps the globals; instances `StateRel.reach` (`Reach`: `KeptAfter`, globals, comparison stack) and `StateRel.same` (equality, the full-restore target form). `GenericKept R`, the only assumption: runs of `convPi` and of `convFnRun` keep `R` (with full restore, trivially true). It took about 470 lines and a few hours, almost all mechanical, with no model in scope; comparable work on the existing statements would have carried `Good`, `CtxOk` and an assignment through every case for no use, since B never reads them.

Idioms that worked:

- `unfold Ochr.conv at h` gives the `do` block with the fuel match already reduced at `n + 1`; then `split at h` on each `if`/`match`.
- `Runs.bind_inv`, `runs_pure_inv`, `runs_get_inv`, `runs_err_false`, `runs_lookupInd_inv` (all in `Steps/DropOne.lean`); `runs_exhausted_false`, `runs_lookupGlobal_inv`, `runs_funType_inv` (in `RefineConv`).
- `simp only [Bool.and_eq_true, beq_iff_eq] at hb` turns `(n == m && x) = true` into equations for `String`, `Nat`, `Bool`, `Option Nat`; `Place`'s and `Value`'s `==` stay as `= true` (no `LawfulBEq`), which is what the relation's constructors take.
- Every sub-call goes through the induction hypothesis with the same `st₀`, so no monotonicity lemma for the premises is needed.
- For the `unitTop` step: `generalize unitTop v = v' at h unitD` before splitting the `match`.

Awkward:

- `obtain ⟨rfl, rfl⟩ := runs_get_inv h0` substitutes in an unpredictable direction (the start state got renamed); use the induction's relation hypothesis rather than state names afterwards.
- `split` on a `match` over a local variable substitutes it and gives no equation hypothesis.
- A lemma stated with my own `match` does not rewrite the machine's `match` (different matcher constants): for `conv`'s fallback I split the two inner matches and simplified instead (`split at h <;> split at h <;> simp only [...]`).
- The kernel cannot evaluate machine runs that reach `firstLiveLoanOnPath` (well-founded recursion), i.e. any run through a match; small runs without one go through `⟨#[], _, _, rfl⟩` or `decide +kernel`.

The rule log: in this area the machine fires only `EqDisj`, `EqStuck` and `EqInj` (dependent constructors only), as text lines (`fire`, `Rules.lean`), and none of the conversion rules. For a small checker to rebuild a derivation the log would have to carry, at each comparison, the rule and the components compared ([Conv-refl], [Conv-unit], each [Conv-cong] former, [Eq-refl] and so on). The function rules' premises cannot be checked by a small checker without re-running the generic call, so for them the machine stays trusted (or the checker re-executes it).

## 10. Interim verdict (if the trial stopped here)

Against docs/35's conditions:

- *"The rule-soundness statements mention none of tables, copies, flags, fuel or extended decisions."* **Met for the first-order rules; not met for the function rules.** A's statements have no machine state. But the soundness of [Conv-fun]'s and [Conv-pi]'s premises, which is their whole content, is a statement about machine runs from the states the comparison reached: there the bookkeeping is moved, not removed. [Conv-pi]'s same-class check reads the unknowns' frozen readings. [Eq-inj] at inherent growth needs an extended assignment.
- *"The false statements this area produced could not have been written in the new form."* **Mostly met.** Of D75's: "a conversion leaves the state unchanged" becomes B's explicit conclusion and, with full restore, true; "nothing said about the state after" cannot be omitted from B; the tail flag and "a type's evaluation started from the wrong state" cannot be written in A at all. But factoring the area found three more false statements, two of which are not bookkeeping: missing typing hypotheses that the old form had too and that the new form makes visible because each rule lists what its soundness needs.
- *"The link from the machine is mechanically checkable from an extended log, or a syntactic argument visibly smaller than the sixteen pieces."* **Met for `conv` as an argument:** B for all of `conv` is proved, model-free, in a few hours. Not as a log: the machine logs none of the conversion rules, and the function rules' premises cannot be checked without re-running the generic call.
- *Failure: "the rules need the machine's state to be stated at all."* **Not for the rules themselves** (values, declarations, globals); **yes for the function rules' premises** once instantiated.
- *Failure: "the link from the machine is as large as the present proof."* **No:** visibly smaller and easier.

**Interim verdict: a qualified success with one major correction to the claim.** The split is real and cheap where it applies: B is easy without a model, and A's statements are clean and each lists exactly what its rule needs. But the claim is oversold in two ways. First, the function rules keep the machine's bookkeeping in their premises.
