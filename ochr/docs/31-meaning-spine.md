## Milestone 1: the meaning of a state

### D1. Typed elements, not ZFC's untyped tuples (`Sem.lean`)

docs/18's model is ZFC: a constructor value means a tagged tuple, a function a set of pairs, all in one `V_κ`. Lean has no analogue of a small universe closed under its own function space: an inductive type cannot hold functions on itself (Cantor, or simply positivity), and a universe of first-order trees whose leaves are elements of arbitrary small types is one Lean level too big to be its own leaf type. Both were tried on paper before writing (`Sem.lean`'s header records the argument). The one encoding that keeps `Π` small is the typed one of `Ochr/Model/Slice.lean`: a type means a Lean type holding only its good elements, and a function value means a Lean function on the carriers of its domain and codomain.

So the semantic domain is:

- `TyM`, the meaning of a type value: a proposition (`prop P`), a carrier at Lean level 0, 1 or 2 (`ty0`, `ty1`, `ty2`), a universe `univ l` (`⟦sort l⟧`, kept symbolic so its elements, type values, are recognised by their level), or `err`.
- `Sem`, the meaning of a value, *tagged by its carrier*: `el0 (A : Type) (a : A)`, `el1`, `el2`; `ty T` (a type used as a value); `proof` (`•`); `moved` (`⊥`); `ctor ty c fs` (see D3); `err`.
- Membership `s ∈ₛ T` is the tag's equality with `T`'s carrier (`Sem.mem`): `el0 A a ∈ₛ ty0 B` iff `A = B`; `proof ∈ₛ prop P` iff `P`; `ty T ∈ₛ univ l` iff `T.level = l`.

Consequences, each a departure from docs/18 the provers must know:

- **Convertible types must have equal Lean carriers.** Conversion soundness for types says `⟦T⟧ = ⟦T'⟧` as `TyM`, i.e. Lean type equality of carriers. It is provable where the plan's (V1)–(V9) say conversion holds: the meaning is a function of the components (Π by `funext` + congruence, `And(True, P) ≡ P` by `propext`, a type function's call by the stabilisation lemma of `Slice.lean` §4). It is *not* decidable, and the semantics uses it classically (`Sem.as` decodes an element by comparing tags with `Classical.propDecidable`), so everything in `Ochr.Meaning` is `noncomputable`.
- **Constructor values' recorded parameters are read, and missing ones are read off the position's type** (D8 below), since the carrier of `D(ā)` depends on `ā`.
- **A borrow type means its content type** (`⟦&A⟧ = ⟦A⟧`): a place holding `borrow_ℓ w` means `⟦w⟧` and its declared type is `&T`, so membership needs the content's carrier. The model therefore validates `Eq(Type₀, &A, A)`. That is harmless only if the checker never *refutes* it, which (WF8) in `WF.lean` pins down: `&` occurs only at the top of a stored type, an abstract value's type or the goal (RULES §1, D48 (2)), never inside a value or deeper in a type, so no reachable state holds the type value `Eq(Type₀, &A, A)` at all. The step lemma for `evalCore (.ref A)` (which rejects a nested `&`) and for `evalCtor`/`tind` are where (WF8) is preserved.

Rejected alternatives: (i) a `fn` constructor storing the domain and codomain as `TyM`s with the function on their carriers: needs `El : TyM → Type` inside the constructor of `Sem`, induction–recursion; (ii) a universe of codes with `El`: the same, or a syntactic universe, which is not the set model; (iii) Mathlib's `ZFSet`: faithful to ZFC and extensional, but a new dependency on a project that imports Lean core only, and without inaccessibles `Type₀` has no set to mean. (iii) is the one to revisit if type-equality casts make the step lemmas unbearable.

### D2. Levels: bounded at `Type₁` (universes in Lean [Q1], `Bounded.lean`)

Lean's universes cannot be indexed by a number, so the model fixes the levels a program may write. The statement to mechanise is `Ochr.Consistency.consistencyBounded`: `consistency` with the extra hypothesis `LevelsBelow 2 q`, no `sort l` with `l > 2` written in `q` (`Prop`, `Type₀`, `Type₁`). Types the checker *computes* reach one level higher (`Type₂`, the type of `Type₁` and of `Π(A : Type₁). Type₁`), which `TyM.univ 3` supports as a universe whose elements are only type values; nothing quantifies over it, so it needs no carrier. Carriers: `ty0 : Type` for `Type₀`, `ty1 : Type 1` for `Type₁` (`Prop` and `Type₀` themselves, Π over them), `ty2 : Type 2` for `Type₂`-sorted Π-types that a parameter can have without `Type₂` being written (`f : Π(A : Type₁). Type₁`). `Sem : Type 3`.

Every example in the suite satisfies the bound (`Prelude.decls` by `#guard`; no example writes `Type₂`), and `Type₁` is used (`Functions.lean`: `Pow (X : Type) : Type₁ := Π(a : X). Prop`), so the bound cannot be 1. Raising it is one constructor in each of `TyM`, `Sem` and the carrier functions; the uniform `consistency` is not a target of the mechanisation.

### D3. `⊥` is `moved`, a definite value; partly moved data is an untyped tuple (D84)

Under D84, `⊥` means "definitely moved", the same at the generic call and at every instance; `eq(⊥, ⊥)` is `True` and `eq(⊥, v)` is `False`. In the model `Sem.moved` is a constructor equal only to itself (`Sanity.moved_definite`), and `Eq`'s meaning is equality in `Sem`.

A constructor value some field of which was moved out (`Pair(⊥, 5)`, which every match that moves a field out leaves) lies in no carrier, so it cannot be `el0`; it means `ctor ty c fs`, an untyped tuple, and a whole, well-typed constructor value is `el0` of its carrier (`DataModel.ctorM`; since D25 an ill-typed one is a tuple too, not `err`). Equality then agrees with the checker's injectivity and disjointness rules in every case: two partly moved tuples are equal iff their fields are; a whole and a partly moved value are never equal (`eq(⊥, v) = False`).

The order `⊑` (`Sem.le`): `moved` below everything, `ctor` componentwise, equality otherwise. Under D84 it is **not** an information order on observations (`moved` is definite); it is the proof device the main theorem needs: the checker's state after an early end (`Pick`) has the holder `⊥` where the reference keeps the borrow, and at a whole leaf `⊑` is equality (`Sem.le_eq_of_whole`). The lead's note that the information order "remains only for borrows ended early and similar over-approximations that are never observed" is recorded as an obligation on the step lemmas: no observation reads a position an early end forgot (borrow holders are never owners, so `Obs.footprint` never lists them).

Membership for a possibly partly moved binding is `DataModel.pmem`: `moved`, or some whole member with parts moved out (`MovedOf`). As first defined, through `Sem.le`, it was false of every partly moved tuple (D24).

### D4. The data model is an interface (`Data.lean`); the construction is milestone 2's

User inductive types need a generic small carrier per declaration and parameter tuple, with dependent fields (telescopes), Fording equations, type-function fields and nesting (`Rose(A) := Node(v : A, kids : List(Rose(A)))` is in the suite). The spine fixes the interface the step lemmas use, `DataModel`: `car`, `pack`, `tag`, `fields`, `rank`, and the least-fixed-point laws (`tag_pack`, `fields_pack`, `pack_fields`: every element is a constructor applied to its fields; `pack_isSome`: packing succeeds iff each field is a member of its field type at the earlier fields; `rank_lt`: recursive fields have smaller rank, for guarded recursion). `fieldTy`, the meaning of a field's declared type at parameters and earlier fields, is part of the interface because the laws are stated with it; the assembly must show it agrees with the reference run's reading of the declaration.

Planned construction (milestone 2, the model beyond the slices [Q2]): the stage construction of `Slice.lean` §4 on carriers, `stage (k+1) ps := Σ c, telescope of field carriers with recursive occurrences at stage k`, by recursion on `k` *as a function of the parameters*, so that non-uniform parameters (D71) cost nothing, and the carrier as the colimit (`Σ k, stage k ps` modulo the stage embeddings, a `Quot`). Nesting needs the nested earlier inductive's stages to be re-run at the new parameter; whether to translate nesting to mutual recursion (as Lean's kernel does) or to interleave the stages is the one open choice. `Prop`-sorted declarations are the truncation `Nonempty (car d ps)` of the same fixed point, so `False`, `True` and `And` need no separate clause.

The library's `Pair`, `False`, `True`, `And` are modelled by hand (`libModel`; its laws are left to provers). `Nat` and `Unit` are not declarations and mean `Nat` and `Unit` directly.

### data-generic: choices (`DataGeneric.lean`)

The generic construction of D4, branch `spine-data-generic`. The choices it made, and the obligations they leave the assembly:

- **The input is a signature of codes** (`Sig`), one per declaration in program order: the constructors' arities, the sort, which parameters are nestable, and for each field a code of its declared type (`PCode`) as a function of the parameters and the earlier fields. A code is `ext T` (a closed small type: everything mentioning neither the declaration nor a nestable parameter, so equations, type-function fields, `Nat`, and earlier inductives at fixed arguments), `par j` (nestable parameter `j`), `self fx tys` (an occurrence of the declaration: fixed parameters `fx`, and a type code `tys j` at each position, used at nestable positions, so non-uniform nested recursion like `NL(Pair(A, A))` is covered), or `nest e fx tys` (an occurrence of the earlier declaration `e`, whose type codes may contain the declaration). The assembly reads codes off the field-type terms and must show that a code read at the colimit (`interp`) is the reference run's reading of the term. That needs docs/18 (I1)–(I6) and three well-formedness facts: type codes only at nestable positions; `ext (tyOf s)` at positions taking a fixed parameter `s`; and the field-type term reading only earlier *closed* fields.
- **Masking.** A field's code sees the earlier fields through `mask`: a closed field's meaning, `err` for a recursive, nested or parameter-typed one. This is what makes the telescope independent of the stage, because a recursive field's meaning differs between stage `k` and the colimit. It is sound because no accepted field type reads such a field. Reading one would need the declaration, or a nestable parameter, written outside a whole field type, which (I1), (I2) and nestability forbid (`SelfEq`, `Loop` are rejected).
- **Nesting is read through the earlier declaration's own carrier, not translated to mutual recursion.** The run reads `List(Rose(A))` as `dm.tyM List [ty (dm.tyM Rose [A])]`, so the field's type must be `List`'s carrier at `Rose`'s carrier. A mutual translation gives an auxiliary type that is only isomorphic to it. Identifying the two would mean defining `List`'s carrier at a `Rose`-carrier parameter by recovering `A` from the carrier, which is D8's `paramsOf` problem again (carriers do not determine parameters). So stage `k + 1` of `Rose` holds `List`'s carrier at `Rose`'s stage `k`, and the colimit argument needs `List` to be functorial in its nestable parameters and finitary: an element over the colimit comes from some stage. That is the interface `NModel` (map, raw meaning relative to the leaves, a predicate on leaves, `lift`, `directed`). The construction *produces* one for every declaration (`nmodel`), so the program's declarations are modelled in order (`progModel`, `progEnv`), and `progEnv_car` says that a later `nest i` reads declaration `i`'s own carrier.
- **Leaf environments and blanking.** A carrier is built at parameters `ps` and a leaf environment `Z : Nat → TyM` (the nestable parameters' types). Codes see `ps` with the nestable positions blanked to `err`, so the carrier depends on a nestable parameter only through its `par` leaves, and is functorial in it with no hypothesis on the codes. The data model takes `Z = envOf ps`.
- **The colimit's equality is raw meaning, relative to a raw meaning of the leaves.** Members of different stages are identified when their raw meanings (`sraw`: constructor and fields' raw meanings, `Sem.ctor` trees) agree, read with the canonical leaf raw. A nested field's raw meaning reads its leaves through the outer declaration's raw meaning, so `NModel.raw` takes the leaf raw as an argument. The master lemma `sraw_rel` (equal raws under related leaf raws stay equal under any related pair) makes this well defined on the quotient and coherent under nesting.
- **`Prop`-sorted declarations** are the same fixed point. An occurrence of one stores `PLift (Nonempty _)`, so a field's meaning is `•` and `pack (fields x) = x` holds. The leaves of the hidden witness are reached existentially (`allLB`), which is what `lift` and `directed` need for a proposition nested in one with a recursive constructor.
- **Field types are cut to `small`** (`Type₀` carriers and propositions; anything else becomes `err`, which has no members), so that `pack` succeeds exactly on members (`gPack_isSome`). This agrees with the run wherever (I6) holds. libModel does the same with its parameters.
- **The rank is the first stage** (`crank`). The rank law is proved on the core carrier (`crank_self`): a field whose code is `self fx tys`, read at that occurrence, has a smaller rank. The interface's `rank_lt` uses the declared-occurrence form the lead adopted (the carrier-equality form is false for `Pair(Pair(Unit,Unit),Unit)`). `recArgs` returns the occurrence's parameters (`occFrom`: the fixed parameters, with the type codes' meanings at the nestable positions) only when the interface carrier there is literally the core carrier the field lives in. That guard is classical, and `gRecArgs_wf` is the bridge: for a well-formed occurrence (fixed parameters blank at the nestable positions, type codes `ext (tyOf s)` at the others) the guard holds. Nested paths (`Rose` → `List` → `Rose`) are not covered by `rank_lt`; that is the semantic [Rec]'s documented gap.
- **`fieldData`, `paramData` and `paramTy` are passed through from the signature.** They are the assembly's readings of the declared types (the structured hints of D8 revised), unused by the construction. `pack_congr` is not part of the interface (dropped with D8's structured hints).
- **Decision (spine, 2026-11-10): parameters carry their own structured hint.** `FieldsFaithful`'s data part is unprovable at a parameter-typed field (`Pair`'s `fst : A` at `A := List(Nat)`): the run's hint carries `("List", [⟦Nat⟧])` from the parameter's structured type, while `fieldData d ps` sees only the carrier, and recovering a declaration from a carrier is D8's problem (false for two declarations of equal carrier). So the parameter hint is to be recorded, not recovered: a parameter's `TyS` keeps its `data` (`Option (String × List TyS)`, D8(c)), and `fieldData` at a `par j` field returns parameter `j`'s data. The run already threads structured hints for fields; the parameters get the same treatment. To do in the assembly; not yet wired.
- **Assembled** as `genericModel (Γ : Prog)`, where `Prog := List (IndDecl × Sig)` is in program order. It covers a declaration that is the program's declaration of its name, with the signature's arities and sort. Declaration `i` is `declDM` at `progEnv` (the models before it). `#print axioms genericModel`: propext, Quot.sound, Classical.choice.

### D5. Code-dependent meanings go through `CodeMeaning` (`Value.lean`)

Globals, closures, Π-closures, sealed programs and deferred D82 types mean "what running code means", which is milestone 2's reference run (the meaning of code, part of [Q2]). `Value.mean` takes a `CodeMeaning` (`global`, `sealed`, `clo`, `pi`, `paramTy`), so the first-order meaning is fixed and checked now, and the reference run will define `Value.mean` and the run in one mutual structural recursion over `Term`/`Value` and prove it agrees with `Value.mean C` at its own `C` (the knot-tying lemma). The run never re-runs a callee's body (it applies the callee's meaning), so it is structural; a recursive `fix` means its guarded fixpoint by well-founded recursion on `DataModel.rank`.

### D6. The meaning of a state and its shape (`State.lean`)

`MState.mean ρ st : Mean` is `(positions, future ↦ position ↦ Sem, shape)`, as docs/27 Def. 2: a lent place means its final content `φ ℓ`, a holder its current content, `⊥` means `moved`. The shape (which position holds the borrow of which label) is a partial map thanks to (WF1). `Mean.semEnd r l` is [End] on meanings and is below (`semEnd_below`, proved); `Mean.forget` is a drop or a capture by move (proved below); `Mean.dependsOn m p l` is what the reference run's [Access] ends.

The reference run's [Access] will end exactly the labels a place's meaning depends on, where the checker ends every label whose loan *occurs* in the content; the step lemma is that the checker's extra ends are below and commute (by WF3's acyclicity).

**The relevance table** (which `MState` fields `⟦Ω⟧` reads) is `State.lean`'s module docstring, with `MState.Core` the relevant projection and `mean_core` the theorem that the rest is irrelevant: read are `env` (values, frame structure; stored types for membership), `inds`, `absTy`, `goal`, `neutrals` and `etaRefs` (conditions on `ρ`), and `globals` through `CodeMeaning.global`. Irrelevant: counters and bounds (`nextLoan`, `nextAbs`, `nextRecUid`, `depth`), caches and logs (`classCache`, `constDecls`, `cfg`, `locs`), and inputs of decisions (`refs`, `recStack`, `convStack`, the declared-type reader's flags, the run-mode flags, `placeLog`). `placeLog` was flagged and resolved: on branch `d84` (both 6400a1d3 and the redesign in progress) the drop at the join and a block's captures are decided statically by `Decide.jdMoves`, from syntax and declared types, and the arms' log is kept only for an internal assertion that never fires. So the log is irrelevant to the meaning and feeds no decision; the reference run's join reads `jdMoves` (to confirm against `origin/d84` when it is written).

### D7. Well-formedness and membership (`WF.lean`)

(WF1)–(WF4) and (WF7) are stated on `MState` as the plan has them, and (WF8), `&` only at the top of a type (D1); (WF5) is `ArgsLoanFree env ws`, a property of a call's argument array, not of a state; (WF6) is split: its naming half (every `σ` in Ω, Δ or the goal has a type in Δ; labels and `σ`s are below their counters) is `WF6`, its typing half is membership. `TypedFuture`: each live borrow's final content lies in its holder's declared content type. `TypedAssignment`: `ρ σ ∈ₛ ⟦Δ(σ)⟧_ρ`, plus the path condition for `neutrals` (`ρ σ = ⟦n⟧_ρ`) and `etaRefs`. `Membership`: under every typed future, every position with a stored type holds a `pmem` of it; Δ's types and the goal are types. `Good ρ st` is the hypothesis of the main theorem. Stored types are read under the constant future `err`, since no stored type holds a live loan (docs/27 Lemma 5; to be a WF clause or a lemma of the skeleton).

### D8. Constructor values without recorded parameters are read at the type of their position (`Value.lean`, `Data.lean`)

`ps = []` constructor values are reachable: `Machine.evalCtor`'s untyped path (around line 2331) builds `.ind ty c h evs ws` with `evs` the parameters *written* in the source; inferred parameters are filled only on the typed path, and untyped runs (sealed-program re-normalisation, callee bodies, D85's runtime) put such values into states. The checker reads their type from the position (D49 (4), `indValType?` when `ps.isEmpty`). A WF clause "constructor values record their parameters" would therefore be false (the lead's review, 2026-11-09).

Chosen: the lead's option (a). `Value.mean ρ φ hint v` reads a value *at a type*, and only a constructor value with `ps = []` of a parameterised type uses the hint: `DataModel.paramsOf d hint` picks, classically, parameters whose carrier is the hint's (`paramsOf_car`: `car d ps = A`), so the element is tagged with the position's carrier and membership holds. The hint is the binding's stored type (`Env.hintAt`, equal to `MState.posTyM` where there is one, `hintAt_posTyM`), a field's type at the earlier fields (`DataModel.fieldTy`, threaded through `Value.meanFields`), a parameter's type (`DataModel.paramTy`, through `Value.meanParams`), or an equation's type; a temporary's hint is `err`, and the step lemmas for in-flight values supply the type the context requires. Everything else ignores the hint, so docs/18's V2 holds in the sense that a constructor value's meaning is determined by its type, recorded or not. Not chosen: (b) inferring parameters from the fields (undetermined for `Nil`); (c) a checker change recording inferred parameters in untyped runs, which would be a separate, verdict-neutral lane and would let the hint go away; worth doing later for simplicity, not needed for soundness.

A subtlety to carry into milestone 2: two parameter lists with the same carrier must pack the same fields to `HEq` elements (a `pack_congr` law on `DataModel`, to add when the generic construction is written), so that the choice in `paramsOf` is immaterial.

### D10. The run is per-future (`Run.lean`; m2-proofs' counterexamples)

m2-proofs refuted the first substitution lemmas in Lean: the run read every position under the constant future and never recorded its own labels in `shape`, so a hole or inert loan read `err` and a borrow the run made could never be ended. Now `run K ρ φ hint t : SState → Option (Res × SState)` with `Res := Sem × TyS` is the run **at the future `φ`**: every read of a position evaluates its `SVal` at `φ` (a free label means `φ l`; a match on a free hole picks its arm at `φ`), the run's own labels are recorded in `shape` at the position that comes to hold the borrow (`pushBindShaped` for a `let`; a result's label travels in `TyS.label`), ended by `access`/`endLabel` (= `Mean.semEnd`) before they are read, and a `let`'s drop ends the label its binding holds. The meaning of a configuration `(Ω, t)` is `fun φ => run K ρ φ hint t (Ω's sstate)`, result and state read at `φ`; that is the reference Mean every step lemma compares with. A sealed program's run starts its label counter above its loans (`emptyState n`). `meanV`'s `.tPi` clause wraps in `.ty`; capture types are read at the ambient `φ` (types are future-free at reachable states, so `meanV_congr` uses the `hasLoan` form of its hypothesis, which looks inside `rd`). `CodeMeaning.global : String → Sem × TyS` (a global's Π-shape), and `piShapeOf` computes a closure's or Π-closure's shape from its term, used by `.val`, `codeMeaning.paramTy` and `Steps/Call.calleeRes`. `Decisions.joinMoves` takes the entry-moved set (`movedPlaces`), as d84's `jdMoves` does. (Superseded by D18: `codeMeaning K ρ φ` ignored its assignment and future arguments, on the belief that `Value.mean` is read only at the state's own; it is not, and `codeMeaning K` now passes both through.)

### D11. The join drop follows `Machine.dropAtJoin`; Prop constructors mean `⋆` (mono-lemmas, prog-decisions)

mono-lemmas showed `joinDrop_below` false at field places (a field set to `moved` makes the value a `ctor`, never below an `el0`) and listed four differences from d84's `dropAtJoin`. `joinDrop` now accesses the place first, leaves copy places (by the declared reading), proofs and places already `⊥` alone, ends a borrow held at a dropped root, and sets the place to `moved`; the match step lemma compares the checker's post-state with the run's (both after their drops), so it needs no "below its input" claim. `Sem.updAt`'s overlapping patterns mean it has no equation lemmas (unfold with `Sem.updAt.eq_def`); a prover who needs them should split the `Nat` case into its own function. prog-decisions found that a constructor of a `Prop`-sorted inductive went through `ctorM` where the checker gives `⋆` (D42): `run`'s `.ctor` and `meanV`/`Value.mean`'s `.ind` now mean `.proof` for `d.sort = 0`, the fields run as statements. m2-proofs' counterexample file is archived verbatim as `Ochr/Meaning/Regress/CE_82394c1a.lean` (not built; each example is to become a positive check against the current run).

Open: a bridge from `WF3 st.env` to mono-lemmas' semantic `SWF3 (st.sstate …)` needs a future-locality law on the run (a sealed program's, closure's or Π-closure's meaning reads the future only at the loans it contains) — `meanV_congr` in its `hasLoan` form is that law for values; the run-level form (`run φ t s = run φ' t s` when `φ`, `φ'` agree on `t`'s loans and the state's live and free labels) is to be stated in `Lemmas.lean`. prog-decisions reports a checker bug, not the spine's: `Decide.sortOf` reads a Π-term's domain through `declSort → declOf false`, so `Π(f : Π(x : Nat). Prop). Nat` gets declared sort 1 but computed sort 2, and `def T : Type₁ := Π(f : Π(x : Nat). Prop). Nat` is rejected with the INTERNAL [D55] message; pinned by `DecisionsSanity.piSort_nested` on their branch.

### D12. Closures at their declared sort; proof calls are `⋆` (prog-decisions' review)

The `.fix` clause built `el0 (piCar0 …)` whatever the Π's sort, so a proof-valued function and a polymorphic function (`id (A : Type) (x : A) : A`, in `Type₁`) meant elements outside their types' meanings. Now the clause reads the sort (`Decisions.piSort`, D55): at `Prop` the closure means `⋆` and its type is the proposition `piProp`; at `Type₀` it is `el0 (piCar0 …)`; at `Type₁`/`Type₂` its type is `ty1 (piCar1 …)`/`ty2 (piCar2 …)` but its *value* is `err` until a level-1/2 `mkTele` (parameters decoded at `el1`/`el2`, type arguments by `dec1`) is written: an open gap, visible rather than silent. ### D29. Static lending in the reference run; the relation without early ends (fifth lead, 2026-11-19)

Main's D90 and D91 (`ochr/core/DECISIONS.md`) made when a borrow ends a decision every run of the checker shares: a place lent to a returned borrow holds a fill over it ([Lend]: a sealed program over the hole, or the new value form `lent_k v`, `Value.gloan`), a non-tail match and a computing `J` first access what the stuck block would capture ([Entry]), a stuck block does that before its arms are checked (D91), and `movedPlace` ends the loans of a fill before generalising it. So the generic call and every instance have the same borrows live, lending the same places, at every point (D90's alignment property, A1 to A4). Until now the reference run ended a borrow by what a place's meaning DEPENDS on, the checker by its loans, and the relation carried the gap: a list `E` of borrows the checker ended early, the loan witness `Wit` (D27) to pin the reference state where an early-ended label has another value, and a plan full of lemmas about both (D25, D27, D28). This entry makes the reference read lending the static way the checker does, and drops all of that.

**1. What `lent_k v` means.** The meaning of `v`; the mark has no meaning of its own (`Value.mean (.gloan _ w) = Value.mean w`). Where `v` holds the hole (`lent_k loan_k`, or the content with `loan_k` lower down) the hole is read from the future like any loan, so the place means its final content where `k` points into it and its current content elsewhere, which is the function of the future a sealed fill over `k` means at that instance. A mark says which borrow may point at a place; it is read by [Access] and [End], never by a meaning, `Eq` or conversion (D90: they never meet one).

**2. What the reference state carries, and its rules.** `SState.lent : Nat → List Site`, with `Site = (position, path, fill?)`: for each label, the places it is lent at. A plain borrow (`&p`) has one site, not a fill; a returned borrow has fills. The reference's [Access] reads only these sites, never a meaning.
- *[Borrow]* `&p` at `(pos, ψ)`: the fresh label's sites are `[(pos, ψ, plain)]`.
- *[Access]* of `(pos, ψ)`: end, in label order and to a fixpoint, every live label with a site `(pos, ψ', _)` whose path is a prefix of `ψ` or extends it (at, over or under the place; paths are compared by field, `.proj i` and `.field g` naming the same field). For a match (the tag only: `accessPath` and `accessNeutralHead`) only sites at a prefix of `ψ`, the place itself included. Before an assignment, at a root holding a borrow written whole, nothing (D67). This is `firstLiveLoanOnPath` (a loan, a mark, a sealed program on the path) with `accessInside` (the loans, marks and holes inside), read off sites. The read after it is at the state's closed future (every live label fixed to its holder's content), as a read that skips [Access] already was (D14).
- *[End ℓ]*: on meanings as before (`semEnd`). On sites, `lendV (.ended ℓ to)` with the substitution: each site `(r, *::π, f)` of any label, `r` being ℓ's holder, is replaced, for each site `(q, ψ, f')` of ℓ, by `(q, ψ, fill)` if `f'` is a fill (the whole place passes to the labels of ℓ's content, as a mark or a sealed fill's holes do) and by `(q, ψ ++ π, f)` if it is plain (a loan is replaced by the content, so a reborrow's loan lands at its own path); ℓ keeps no site. This is D90's transfer: a reborrow of `*ℓ` that outlives ℓ keeps every place ℓ was lent.
- *[Lend]* (rule 1): a call whose declared result is a borrow gives the fresh result label the union of its borrow arguments' sites, each a fill, and consumes the arguments, whether the checker runs the call or closes it off. A call with a data result consumes them.
- *[Entry]* (rule 2): a non-tail match, and `J`'s transported term, first access each place the stuck block would capture (a new aligned decision `Decisions.blockCaps`, the checker's `blockCaptures` in the checker's order; D90's obligation 1 is the content of its alignment statement), as data. For a match whose declared type is a borrow, the sites of the borrow variables it would take by move are snapshot before the arm; after the arm and the join, the result label gains a fill at each place it would take by `&` and at each snapshot site.
- *Tail position*: `run` carries a tail flag, as the checker's `checkTail` and its untyped runs' `tailNext` do: set for a function's body, passed to a `let`'s body, a sequence's tail, the arms of a tail match and the one arm of a match on a proof, false everywhere else (`J`'s transported term and a sealed program's re-run included). A tail match has no entry (D90's `G4`).
- *The block*: the reference never forms one (it reads the tag of the scrutinee's meaning). The checker's block (D91: entry, then the arms, then the block call, a rule-1 call when it returns a borrow) ends and lends exactly what the reference's non-tail match clause does.
- *Ends the reference used to leave to the checker* ("below" in the audit), now made, since the two must hold the same live borrows at every point: a discarded borrow at `t; u` ends (`dropValue`); at a `let`'s end a binding holding no borrow ends the live labels with a site at it (D65, `endLoansOfTopBind`); a closure's captured places are accessed, oldest first, before they are moved (`capture`); the join's drop of a place first accesses, whole, the shortest strict prefix of it that holds a site of a live label (`movedPlace`'s access of a lent parent, point 5 f), then the place.

**3. The one-sided invariant.** At a related state, the content of a place at a path reads the future only at non-live labels and at live labels with a site comparable with that path. It is not a clause: it follows from the readings clause (the reference's meaning is the checker's value's at every compared future, and the compared futures leave every live label free) and from a path-local form of `meanV_congr` (a value's meaning at a path reads the future only at the loans, marks and holes at comparable paths), which holds for hint-free values (point 5 e). So after an access the content reads no live label, and the reference's read at the closed future is the checker's read. The core lemmas do not need it: the access consults no meaning, and a read at the closed future is congruent in the future (`closedFuture_read`), so `run_congr` loses its dependence machinery (`obsDep`, `access_FT`) rather than gaining an invariant. Two clauses of the checker's well-formedness go with it, read off D90 and owned by the steps that keep them: (WF12) under a fill only fills (every site strictly under a fill of a live label belongs to a label with a fill at or above it: a call lends places borrowed whole, and anything that later reaches under a fill ends it first), and (WF3) on sites (no label is lent inside its own holder's content, transitively), which makes the ends within one access commute.

**Everything the reference run does reads its state only at futures that agree with the run's off the live labels**: an access reads sites, a read is at the closed future, [End] reads the holder at the same future with the ended label updated, a call's backward functions are read at the arguments' labels. Those are exactly the futures the readings clause compares. So the relation determines the run, and no witness is needed to pin the reference where an early-ended label has another value: there are no early-ended labels, and where a non-live label has another value the run never looks.

**4. The relation** `Rel K ρ φ π st s`:
- *skel*, *fresh*: as before.
- *holders*: a binding holds the borrow `l` in the checker exactly when it holds `π l` in the reference; a borrow a temporary of the checker holds (a value in flight) is held under `π l` by a temporary of the same frame with the same content, and no temporary of the reference holds a label the checker does not hold; `π` is injective on the checker's live labels. So the live labels correspond one to one.
- *sites*: for every live label `l` of the checker, the reference's sites of `π l` are the checker's sites of `l` (`sitesOf`: its loans not inside a fill of `l`, its marks, the sealed programs among whose holes it is), compared as sets.
- *readings*: `SimEq` at every future that agrees with `φ` off the reference's live labels, with no early ends: bindings equal position by position, temporaries by label. A moved part is the meaning `moved` on both sides, so the moved places are the same.

**5. The cases that broke earlier designs.**
- (a) *`Regress/CondDep.lean`* (an injective backward function making the dependence on `m` conditional on `j`'s content). The reference's access no longer asks what a place depends on, so the conditional dependence cannot make it end anything the checker does not. At the reachable form, `k`'s End hands both `j` and `m` a fill at `x` on both sides, and both accesses of `x` end both. The unreachable form (the checker holding the constant `c` at `x`) has no site at `x`; the readings clause, at futures that leave `j` and `m` free, makes the reference's `x` constant, so nothing reads `m` there either.
- (b) *A reborrow outliving the borrow it came from* (D90's `Census2.G8`): `r = Pick(n, &a, &b)` gives `k` fills at `a` and `b`; `s = &(*r).0` is plain at `(r, *.0)`; `r`'s scope ends. [End k] re-roots `s`'s site through `k`'s fills: `s` now has fills at `a` and `b`, on both sides (the checker hands `k`'s marks, or the holes of its sealed fills, to `s`). Reading `b` ends `s`, at the generic call and at `n = 0` alike.
- (c) *A fill re-normalised in a split world* (`Regress/RenormHoles.lean`, D90's `Census3.SplitKeeps`). ### D31. The reference reads data by its declaration's name, not by its carrier (fifth lead, 2026-11-19; fixed)

**Finding (kernel-checked, `Regress/DataOfChoice.lean`; a model fault).** Found attacking L2, the drop's write of `⊥` at a path. The reference finds its way inside a constructor value through the value's TYPE MEANING: the tag a match reads (`indTag`), a field read (`Sem.follow`, `Sem.stepField`), a write or drop at a path (`Sem.updAt`) and [Rec]'s rank all decode the value's meaning through `TyM.dataOf`, the first declaration of `Γ` whose carrier is the type's, with parameters chosen classically (`DataModel.paramsOf`). Carriers do not determine declarations: two declarations can have equal carriers, which Lean can neither prove nor refute for two types of the same size, and a data model may make true. Then the reference decodes the value as the other declaration's.

The file's model satisfies every law of `DataModel` and covers both declarations of `B1 := T1 | F1`, `B2 := F2 | T2`, each with the carrier `Bool`, `B1` storing `T1` as `true` and `B2` storing `T2` as `true`. Field reads, writes and drops read the other declaration's fields and write its name into the result the same way. So every step lemma that finds its way inside data is false at this model, and unprovable at the generic one: a proof would have to refute that an earlier declaration's carrier equals the value's, which Lean cannot do for two types of the same size.

**Fix (done).** Decode by the type's structured data, `TyS.data`: the declaration's name and its parameters' meanings, which a binding's type (`Value.strS`, `Value.tyData`, through `&` too) and a field's hint (`DataModel.fieldData`) already carry (D8). `TyS.dataDecl` finds the declaration by name; `Sem.follow`, `Sem.step`, `Sem.stepField` and `Sem.updAt` take a `TyS` and give a field its `TyS` (`fieldHint`: the hint `Value.meanFields` reads the field at); `indTag`, `obsAt`, `tagOf`, `contentOf`, `setContent`, `borrowPlace` and `dropAt` pass the position's `TyS`. The four core lemmas are again proved with no `sorry` (standard axioms); the change to their proofs was the signature only. `Regress/DataOfChoice.lean` now shows the fixed match reading `T2` as constructor `1` (`tag_right`) and keeps the fact the counterexample rested on (`carrier_names_B1`); the counterexample itself is kept, unbuilt, in `Regress/DataOfChoice_189132fd.lean`. Left as they were: [Rec]'s rank keeps `dataOf` (a parameter's type is a `TyM`; a wrong rank only shortens the recursion's guard, so the run fails where the checker succeeds: an adequacy gap, not a false proposition), and a field read's result type was still `.plain` (its data dropped), which after the fix left a binding of a read field with no declaration to decode it by, so `let y = x.1; y.0` failed in the reference: `contentOf` now gives a field the structured type `Sem.follow` gives it (its declaration's hint, with data), with no label (same day; the core lemmas unchanged).

What the fix rests on. Decoding at the type's data is the value's own decoding when the value's recorded parameters mean the type's data parameters (`fieldsOf_ctorM`); a constructor value recording no parameters reads them from the hint already. That is a typing fact of the checker (it converts a constructor's type to the position's parameter by parameter), to be a clause of `Good` (data agreement) kept by the steps. Two parameter lists of equal carrier within one declaration (`pack_congr`, D8's note) are then never compared. ### D32. Data values describe themselves (fifth lead, 2026-11-20; decided: (a); BUILT)

**The root.** Two faults in two days share one cause: the model reads a data value with information from somewhere other than the value. D31 guessed the declaration from the carrier; `Regress/PartialMoveDep.lean` (accepted `JK`) computes a field's type from its siblings after one of them is moved, and the reference's drop into the field then does nothing where the checker's writes `⊥`. The checker does neither: a constructor value records its own declaration and parameters (D88, D89), and an open value's field is typed by its content. In Lean's own model (docs/33 entries 3, 4, 14; Carneiro §6.4) a type means a tagged code, and an element of an inductive type is a ZFC tree, which describes itself; only our encoding, where an element is an opaque inhabitant of a Lean carrier (`el0 (car d ps) x`), lost that. Decoding such an element needs `(d, ps)` from outside, and a cast between equal carriers is not provably the identity on fields, which is why every route so far has needed an invariant (WF13) or a guess.

**The options, and what each does.**
- **(a) Self-describing data values.** A constructor value means `dat d ps c fs`: its declaration, its parameters' meanings, its constructor and its fields' meanings, whole or partly moved alike (it replaces both `el0`-packing and the `ctor` tuple). A data type means a code naming `d` and `ps` (the data part of (c)), whose decoding is the carrier `car d ps`; membership is "packs at the code" (`DataModel.pack`), and carriers are met only where a Lean function on carriers is applied (`dec`/`enc` at Π boundaries, which need the code at the codomain, so a call's result must carry its data: the data half of the call-result redesign). Navigation (tag, field read, write, drop) reads only the value. Partial moves: fixed, since a field is decoded by itself, never through a type computed from moved siblings. Deleted: (WF13), `DataAll`, `DataOn`, `WholeAlong`, `dataOn_of_wf13`, the open-dependent-value residual, D31's `dataDecl` navigation, and [Rec]'s `dataOf` (the rank is the packed element's). Cost: `Sem` and `TyM` become mutual (`TyM.data` holds `List Sem`); `ctorM`, `fieldsOf`, `MovedOf`, `pmem`, `Sem.mem` and `Apply`'s `dec`/`enc` change; `DataGeneric` is untouched (carriers are still built, as the codes' decodings). Re-proof: the four core lemmas where they unfold data meanings (`RunCongr`'s constructor and match cases, `RunSubst`, `HintIndep`), `mean_updAt_bot` (simpler: no hint conditions), the toy models in `Mono`, `DataOfChoice`, `SiblingAccess`, `PartlyMoved`; the relation's form is unchanged. Estimate: a few days.
- **(b) A type skeleton per position, written by content.** The reference keeps, beside each position's meaning, the checker's typing by content (declaration and parameters at each constructor), set by writes. Partial moves: fixed. It removes `WholeAlong` and the residual but replaces (WF13) by a new clause of the relation (the reference's skeleton is the checker's values' recorded types), and every state operation carries the skeleton through the core lemmas. It duplicates in the reference what the checker's values already record; it is not Lean's way.
- **(c) Types as codes closed under every former.** `TyM` becomes a family of codes indexed by their decodings (Π's code holds a function from arguments to codes). It closes the faults where a call's result, a computed function type and a field read lose structure (the audit's A11, A12, A18), and `TyS`'s optional fields go. Partial moves: NOT fixed: a field's code is still computed from its siblings, and Lean has no moves. It does not remove (WF13)'s parameter half either: an opaque carrier element still needs its type's parameters to be decoded. Cost: the largest (every `TyM` consumer, `Apply`, `Pi`, `Apply1`).

- **(d) Tighten the checker's join drop** (the team lead's option): `dropAtJoin` performs a move's checks, computing the place's type, so a field whose type reads a moved field cannot be dropped any more than moved. The reading behind it is right for MOVES: every other navigation into such a field computes its type and refuses (`PartialMoveDep`'s `Direct`, `JKRead`, `JGen`: "[Read] n was moved out"; [Repack] computes field types too). Other places that act at a path without computing a type do not decode in the reference: the access (`accessPath`/`accessInside`) is mirrored by sites only (D29); D65's ends at a `let`'s end and a frame's pop act on whole bindings; [End] writes back by fixing the future. So `dropAtJoin` is the one hole for moves, and (d) would reject only drops into a field whose type reads a moved field: Rust has no such types, and the direct forms of that code are already rejected; `JK` would be rejected like its unknown-`k` form, which aligns the two. With (d), `WholeAlong` holds at every navigation the reference must mirror. BUT (d) does not reach OPEN values made by a WRITE: `Regress/OpenWriteDep.lean`, `OWK` (accepted): the index is rewritten whole (`w.0 := S(S(Z))`), then `(w.1).1` is read; the checker types `w.1` by its content (`Pk(S(w0))`), the reference decodes it at the hint from the current earlier fields (`Pk(2)`). The earlier field is whole, so this is not a move case, and (WF13) as restricted to fields after whole earlier fields is FALSE there (now restricted to the top constructor, `WF.lean`; `dataOn_of_wf13` to paths entering one constructor). So under (d), as now, decoding by the position's type is not the value's own decoding at every place the reference navigates; only (a) or (b) cover open values.
- **Call results, under any option that decodes by type.** A data call's result is typed `.plain B` (`callOfL`, `Run.lean` line 426): no data. Since D31, a match or a field read on a `let`-bound call result therefore fails in the reference (`DataOfChoice.indTag_plain`, kernel-checked), where before it decoded by the carrier guess. So the data half of D22's call-result redesign (a call's result takes its data, and shape, from the callee's declared result type) is not a later row under (c), (d) or the current model: it is needed now. Under (a) navigation does not need it, but encoding a Lean function's result as a self-describing value needs the codomain's code, which is the same redesign.

**Recommendation: (a), with the data part of (c) it requires (the call-result redesign's data half included), now; the Π part of (c) with the rest of the call-result redesign.** (d) is a sound tightening that makes a known and an unknown scrutinee agree, but it is not needed under (a), and it does not by itself make decoding by type correct (`OWK`). (a) is the value-side half of Lean's model (tagged codes for types, self-describing trees for elements); (c) is the type-side half, and needs (a) or (WF13) beside it for data. (b) is rejected: it maintains by hand what (a) gets from the value. On which departs from Lean less: Lean's model looks at a value only through its type, and its elements describe themselves (ZFC trees); (a) keeps the second and is what lets the first stay harmless with moves and open values; (b) adds state Lean has no counterpart for. With (a) nothing beyond Lean's theory is needed for moves: a partly moved value is a tree with `⊥` leaves. Lean's theory has no moves, so the one choice (a) adds is that a partly moved or ill-typed (open) constructor value is still a `dat`, outside its type's code but navigable.

**Decision (team lead, 2026-11-20): (a), with the data part of (c), call results' data included.** Option (d) (the join's drop performing a move's checks) was considered and is not needed under (a): it would remove an asymmetry worth remembering, `JK` accepted at a known scrutinee and rejected at an unknown one, but it is not sufficient alone (`OWK`), and the checker is left alone.

**The sweep of `Good`'s read-off clauses, first: not buildable from what the checker records.** The `located` mode records, per term, the term's value and type (`Note.value`), a tail term's goal, a rule fired, and at a hole `?` its goal and the bindings of the top frame and frame 0 (`Note.hole`). It does not record Ω at a term: no temporaries, no lower frames, no unknowns' types, no goal or records, so none of (WF11) (no stored type or record holds a loan), (WF12) (under a live fill only what ending it reaches) or "no live fill above a moved or proof part" can be evaluated on recorded states (liveness alone needs every position). What is missing is one opt-in note: the whole `MState` (or its `env`, `absTy`, `goal`, `neutrals`, `etaRefs`) at each located term, behind a `Config` flag that is off in every verdict-bearing run. That is a checker-lane change; with it the harness is a fold over the log with Bool mirrors of the three clauses (and of WF1, WF2, WF4, WF8, WF10). Holes alone give a handful of top-frame states, too few to count as a sweep.

**Design note for (a) (before code).**
- *Definitions.* `TyM` and `Sem` become mutually inductive. `TyM` gains `data (name : String) (ps : List Sem) (A : Type) (unpk : A → Nat × List Sem)`: a data type is its declaration's name and parameters' meanings, decoding to the carrier `A` with `unpk` reading an element's constructor and fields (`Sem` occurs positively). `DataModel.tyM d ps` is `data d.name ps (car d ps) (fun x => (tag x, fields x))` for a data declaration (a `Prop` declaration stays `prop (Nonempty (car d ps))`). `Sem.ctor` is replaced by `dat (name : String) (ps : List Sem) (c : Nat) (fs : List Sem) (el : Option ((A : Type) × A))`: every constructor value, whole or not, with its declaration, parameters, constructor and fields; `el` is its carrier element when it is whole and of its type (`ctorM` packs: `some ⟨car d ps, x⟩`), `none` when partly moved or open. ### D33. Three read-off clauses restated after the sweep (fifth lead, 2026-11-21)

The sweep (main d26ee93c: `Config.recordStates`, `lake exe sweep`, adversarial probes with `--probes`; dev tooling, `Sweep.lean`) evaluated Bool mirrors of `Good`'s syntactic clauses on 68,541 states the checker records over the suite's 2,094 declarations, and on 512 states of `SweepProbes.lean`. - **(WF8).** OLD: "`&` occurs only at the top of a declared type: a borrow type is the whole stored type of a binding, the whole type of an abstract value or the whole goal, with `A` borrow-free, and no `tRef` occurs inside any value of Ω, inside a type, or inside the parameters a constructor value records" (`∀ v ∈ values, ¬ v.typeHasRef`, and `&` only at the top of stored types, unknowns' types and the goal). ### D34. What `movedPlace`'s exits need: the checker's own typing, read off and swept (fifth lead, 2026-11-21; proposed)

`movedPlace` re-roots a dropped place to its parent when the parent holds nothing it refines (`MovedPlace.exit_abs`, `exit_sealed`, `exit_other`). The proof must show the parent then holds `⊥` or `⋆`, and that an unknown or a sealed program there has the parent's declared one-constructor type. Nothing in `Good` says this: it is syntactic typing, and membership is semantic (the model reads `&A` as `A`, so even a borrow can be a member of a data type there). The facts the exits need, read off the checker:
- (M) every mark outside a sealed program is of a live borrow ([End] removes its marks), so a parent holding a mark is a fill;
- (U) an unknown at a place declared an inductive `D(…)` has a type `D(…)`;
- (V) a place declared an inductive holds one of its constructor values or a stand-in (`⊥`, `⋆`, an unknown, a sealed program, a loan, a mark);
- (R) a place declared a borrow type holds a borrow, `⊥` or a loan (so the `*` step exists unless it is `⊥`);
- (A) a constructor value has its constructor's fields (so a field step from a constructor of the declared type exists);
- and an alignment: where a place's declared reading is an inductive, the checker's `placeType?` gives that inductive (`Decide.placeDecl` against the machine's typing; for `exit_sealed`).

Swept (`Sweep.lean` on spine, candidates, not clauses of `Good`): no violation in the suite's 68,541 states or the probes' 512. Premises in the suite: a mark in 306 states; a binding of an inductive type holding an unknown in 38,301; a constructor field declared `E(…)` holding an unknown in 20,350; a binding declared an inductive in 43,530; a binding declared a borrow type in 20,624. ### D35. Do ends and accesses create unknowns? (fifth lead, 2026-11-21; open question)

`endBorrow_step_stmt` and `access_step_stmt` conclude the relation, `Good` and (through `access_ctx`) the context under the SAME run context and assignment. ### D9. The run's types carry the Π-shape (`Run.lean`, `TyS`)

Applying a function value needs its Π-shape (`PiParam`s and `PiOut`): neither the opaque carrier `ty0 (piCar0 …)` nor the value can give it back, and recomputing it from the callee's Π-type *value* means running that value's domain terms, which are not subterms of the call, so `run` could not stay structurally recursive. ### Conventions an implementer must keep

- **Totality and `err`**: every semantic function is total; an ill-formed input means `Sem.err`/`TyM.err`/`none` (the run fails with `none`). Never add a `partial` or an axiom; everything is `noncomputable` and uses `Classical` freely (`open Classical` in Apply/Places/Run).
- **Futures**: a position's meaning is `SVal := Future → Sem`; read a value that is future-free under `noFuture`; `Future.upd`/`updList` fix labels; ending a label is `endLabel` (the holder forgotten, every meaning reads the label as the holder's current content). A fresh label comes from `freshLoan`; a borrow result carries its label in `TyS.label` so a call can fix its lender's future.
- **Hints (D8)**: `run hint t` and `meanV φ hint v` read a value at the type its context expects; pass `.err` when there is none; only `ps = []` constructor values use it. Field hints come from `fieldTy`, parameter hints from `paramTy`, argument hints from the callee's shape.
- **Shapes (D9)**: a Π-type's shape travels in `TyS.shape`; a function value's result carries none (gap (ii) below).
- **Statements** run on a copy: `SM.onCopy`. Which terms are statements is `Decisions.flags`, never a check of the value.
- **Open recursion**: everything that runs code must be in `Run.lean`'s mutual block, structurally recursive on `Term`/`Value`; a call to `run` on a lambda-bound term (e.g. inside `List.map`) is rejected by the termination checker: write a mutual list helper (`runDoms`, `runArm`, `runFields`, …) instead. `Nat.rec` with a `run body` call inside its step is accepted (the `fix` clause's stages).
- **Checker names shadowed**: the run's `readPlace`/`borrowPlace` shadow `Ochr.readPlace`/`Ochr.borrowPlace`; qualify the checker's in statements.
- **No Mathlib**: `List.Forall₂` etc. are unavailable; the project imports Lean core only.

### The `fix` clause (filled) and its spec

A closure `fix self (x̄ : Ā) : B by xⱼ := body` formed in state `s` means `el0 (piCar0 ps [] PUnit out) F` (or `err`), where `ps := runDoms s ds` (each domain term run in `s` extended by the earlier parameters; `&A` marks a borrow parameter with content type `A`), `out` is the codomain term's meaning per prefix (`.ref U` for a borrow result), and `F := mkTele ps [] PUnit (fun fs => some ((), fs)) out g`. `g args` runs `body` in `s` extended by `self` (type `ty0 piT`, value `selfM`) and the parameters (each at its `dom` of the prefix; a borrow parameter's holder's value is the argument's content), at the codomain hint; then ends every label ≥ the label counter at formation (the frame pop ending the body's borrows) and reads each borrow parameter's holder for its final content; `retLabel` is the result's `TyS.label`. Non-recursive: `g := bodyAt .err`. Recursive: `g args := stage (rankOf args + 1) args` with `stage 0 := fun _ => none`, `stage (k+1) := bodyAt (closureOf (stage k))`, and `rankOf` the `DataModel.rank` of argument `j` through the carrier of its parameter type (a `Nat`'s value). Forming moves non-copy captured places (`Decisions.copy` of their reading). **Not done**: `SBinding.recBound` is unused (the guard is realised by the stages); a `WellFounded.fix` formulation was dropped because the carrier holds total functions only and a "restricted" element cannot be built. The stabilisation lemma for a decreasing body (stage `k > rank` agrees with stage `rank + 1`) is the semantic form of [Rec] and is a milestone-3 statement (`Steps/Call.lean`, `recCheck`'s accepting direction).

### The knot and what could go wrong

`codeMeaning K` packages `meanV K` as a `CodeMeaning`, reading at the assignment and future it is passed (D18; as first written it ignored them, a definition fault); `meanV_eq_mean` says `Value.mean K.dm (codeMeaning K) K.Γ ρ φ hint v = meanV K ρ φ hint v`. It is well founded because `meanV` is defined *inside* the mutual block by structural recursion (a sealed program's run is on the term inside the value; a closure's on the term inside the value), so `codeMeaning` is a plain definition after the block, not a fixpoint. Risks: (1) `K.C.global` must be the program meaning (`Program.lean`, implementer prog-decisions) and is the one truly external input; (2) `meanV`'s `.tPi`/`.clo` clauses run the term in `stateOf (capsState (capsVals φ caps) (capsTys φ rd))`, which has no declared readings beyond `rd`'s and no label counter, so a closure whose code reads a capture's declared type for copy-or-move must find it in `rd` (D82 says it does); (3) `codeMeaning.paramTy` reads the Π-type value's shape through `run … (.val P) emptyState`, which goes through `meanV (.tPi …)` and loses the shape (a `.val` result has `shape := none`): **this is wrong as written** and must be fixed by computing the shape from the `tPi`'s term as the `.pi` clause does (make a `piShapeOf` helper in the block returning `Option (List PiParam × PiOut)` for a `tPi caps (pi hs ds c) rd`, and use it both in `.pi`'s result and here). The same helper is what `Steps/Call.lean` needs to state the callee's shape from its type value.

### Known gaps (all recorded above; collected)

(i) recursive-call guard realised by stages only, `recBound` unused; (ii) a call returning a function gets no shape (extend `PiOut.data` with an optional shape); (iii) `runDoms`/`fix` bind parameters without declared readings (`decl := .other`), so a type-level `match` reading a parameter's copy-ness reads `other`; (iv) match access uses read mode, not match mode (reference ends at most what the checker does; harmless for the step lemma); (v) a borrow parameter whose holder the body moved reads `moved` as its final content; (vi) `codeMeaning.paramTy` loses the shape (see the knot); (vii) `capsState` frames have `nextLoan := 0`, so labels created inside a sealed program's re-run could collide with the outer state's in the *statement* of a step lemma comparing them (the run's labels are its own; a step lemma should compare up to the fresh labels it creates); (viii) `MState.sstate` sets no `recBound`; (ix) `Env.hintAt` reads `lazyTy` through `CodeMeaning.paramTy` (fixed with piShapeOf in 059d7906); (x) closed: closures at every level through `Apply1.lean` (D12); residual: `Prop`/`Type₀` as elements of `Type₁` do not decode at level 2; (xi) `movedPlaces` lists whole top-frame variables, where d84's `botPlaces` lists sub-places too.
