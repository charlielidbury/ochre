## Milestone 1: the meaning of a state

### D1. Typed elements, not ZFC's untyped tuples (`Sem.lean`)

docs/18's model is ZFC: a constructor value means a tagged tuple, a function a set of pairs, all in one `V_κ`. Lean has no analogue of a small universe closed under its own function space: an inductive type cannot hold functions on itself (Cantor, or simply positivity), and a universe of first-order trees whose leaves are elements of arbitrary small types is one Lean level too big to be its own leaf type. Both were tried on paper before writing (`Sem.lean`'s header records the argument). The one encoding that keeps `Π` small is the typed one of `Ochr/Model/Slice.lean`: a type means a Lean type holding only its good elements, and a function value means a Lean function on the carriers of its domain and codomain.

So the semantic domain is:

- `TyM`, the meaning of a type value: a proposition (`prop P`), a carrier at Lean level 0, 1 or 2 (`ty0`, `ty1`, `ty2`), a universe `univ l` (`⟦sort l⟧`, kept symbolic so its elements, type values, are recognised by their level), or `err`.
- `Sem`, the meaning of a value, *tagged by its carrier*: `el0 (A : Type) (a : A)`, `el1`, `el2`; `ty T` (a type used as a value); `proof` (`•`); `moved` (`⊥`); `ctor ty c fs` (see D3); `err`.
- Membership `s ∈ₛ T` is the tag's equality with `T`'s carrier (`Sem.mem`): `el0 A a ∈ₛ ty0 B` iff `A = B`; `proof ∈ₛ prop P` iff `P`; `ty T ∈ₛ univ l` iff `T.level = l`.

Consequences, each a departure from docs/18 the provers must know:

- **Convertible types must have equal Lean carriers.** Conversion soundness for types says `⟦T⟧ = ⟦T'⟧` as `TyM`, i.e. Lean type equality of carriers. It is provable where the plan's (V1)–(V9) say conversion holds: the meaning is a function of the components (Π by `funext` + congruence, `And(True, P) ≡ P` by `propext`, a type function's call by the stabilisation lemma of `Slice.lean` §4). It is *not* decidable, and the semantics uses it classically (`Sem.as` decodes an element by comparing tags with `Classical.propDecidable`), so everything in `Ochr.Meaning` is `noncomputable`.
- **Constructor values' recorded parameters are read, and missing ones are read off the position's type** (D8 below), since the carrier of `D(ā)` depends on `ā`.
- **A borrow type means its content type** (`⟦&A⟧ = ⟦A⟧`): a place holding `borrow_ℓ w` means `⟦w⟧` and its declared type is `&T`, so membership needs the content's carrier. The model therefore validates `Eq(Type₀, &A, A)`. That is harmless only if the checker never *refutes* it, which (WF8) in `WF.lean` pins down: `&` occurs only at the top of a stored type, an abstract value's type or the goal (RULES §1, D48 (2)), never inside a value or deeper in a type, so no reachable state holds the type value `Eq(Type₀, &A, A)` at all. The step lemma for `evalCore (.ref A)` (which rejects a nested `&`) and for `evalCtor`/`tind` are where (WF8) is preserved.

Rejected alternatives: (i) a `fn` constructor storing the domain and codomain as `TyM`s with the function on their carriers: needs `El : TyM → Type` inside the constructor of `Sem`, induction–recursion; (ii) a universe of codes with `El`: the same, or a syntactic universe, which is not the set model; (iii) Mathlib's `ZFSet`: faithful to ZFC and extensional, but a new dependency on a project that imports Lean core only, and without inaccessibles `Type₀` has no set to mean. (iii) is the one to revisit if type-equality casts make the step lemmas unbearable.

### D2. Levels: bounded at `Type₁` (universes in Lean [Q1], `Bounded.lean`)

Lean's universes cannot be indexed by a number, so the model fixes the levels a program may write. The statement to mechanise is `Ochr.Consistency.consistencyBounded`: `consistency` with the extra hypothesis `LevelsBelow 2 q`, no `sort l` with `l > 2` written in `q` (`Prop`, `Type₀`, `Type₁`). Types the checker *computes* reach one level higher (`Type₂`, the type of `Type₁` and of `Π(A : Type₁). Type₁`), which `TyM.univ 3` supports as a universe whose elements are only type values; nothing quantifies over it, so it needs no carrier. Carriers: `ty0 : Type` for `Type₀`, `ty1 : Type 1` for `Type₁` (`Prop` and `Type₀` themselves, Π over them), `ty2 : Type 2` for `Type₂`-sorted Π-types that a parameter can have without `Type₂` being written (`f : Π(A : Type₁). Type₁`). `Sem : Type 3`.

Every example in the suite satisfies the bound (`Prelude.decls` by `#guard`; no example writes `Type₂`), and `Type₁` is used (`Functions.lean`: `Pow (X : Type) : Type₁ := Π(a : X). Prop`), so the bound cannot be 1. Raising it is one constructor in each of `TyM`, `Sem` and the carrier functions; the uniform `consistency` is not a target of the mechanisation.

### D3. `⊥` is `moved`, a definite value; partly moved data is an untyped tuple (D84)

Under D84, `⊥` means "definitely moved", the same at the generic call and at every instance; `eq(⊥, ⊥)` is `True` and `eq(⊥, v)` is `False`. In the model `Sem.moved` is a constructor equal only to itself (`Sanity.moved_definite`), and `Eq`'s meaning is equality in `Sem`.

A constructor value some field of which was moved out (`Pair(⊥, 5)`, allowed by D53 inside a borrow) lies in no carrier, so it cannot be `el0`; it means `ctor ty c fs`, an untyped tuple, with the invariant that a whole constructor value is always `el0` of its carrier (`DataModel.ctorM` decides by wholeness). Equality then agrees with the checker's injectivity and disjointness rules in every case: two partly moved tuples are equal iff their fields are; a whole and a partly moved value are never equal (`eq(⊥, v) = False`).

The order `⊑` (`Sem.le`): `moved` below everything, `ctor` componentwise, equality otherwise. Under D84 it is **not** an information order on observations (`moved` is definite); it is the proof device the main theorem needs: the checker's state after an early end (`Pick`) has the holder `⊥` where the reference keeps the borrow, and at a whole leaf `⊑` is equality (`Sem.le_eq_of_whole`). The lead's note that the information order "remains only for borrows ended early and similar over-approximations that are never observed" is recorded as an obligation on the step lemmas: no observation reads a position an early end forgot (borrow holders are never owners, so `Obs.footprint` never lists them).

Membership for a possibly partly moved binding is `Sem.pmem`: `moved`, or below some whole member.

### D4. The data model is an interface (`Data.lean`); the construction is milestone 2's

User inductive types need a generic small carrier per declaration and parameter tuple, with dependent fields (telescopes), Fording equations, type-function fields and nesting (`Rose(A) := Node(v : A, kids : List(Rose(A)))` is in the suite). The spine fixes the interface the step lemmas use, `DataModel`: `car`, `pack`, `tag`, `fields`, `rank`, and the least-fixed-point laws (`tag_pack`, `fields_pack`, `pack_fields`: every element is a constructor applied to its fields; `pack_isSome`: packing succeeds iff each field is a member of its field type at the earlier fields; `rank_lt`: recursive fields have smaller rank, for guarded recursion). `fieldTy`, the meaning of a field's declared type at parameters and earlier fields, is part of the interface because the laws are stated with it; the assembly must show it agrees with the reference run's reading of the declaration.

Planned construction (milestone 2, the model beyond the slices [Q2]): the stage construction of `Slice.lean` §4 on carriers, `stage (k+1) ps := Σ c, telescope of field carriers with recursive occurrences at stage k`, by recursion on `k` *as a function of the parameters*, so that non-uniform parameters (D71) cost nothing, and the carrier as the colimit (`Σ k, stage k ps` modulo the stage embeddings, a `Quot`). Nesting needs the nested earlier inductive's stages to be re-run at the new parameter; whether to translate nesting to mutual recursion (as Lean's kernel does) or to interleave the stages is the one open choice. `Prop`-sorted declarations are the truncation `Nonempty (car d ps)` of the same fixed point, so `False`, `True` and `And` need no separate clause.

The library's `Pair`, `False`, `True`, `And` are modelled by hand (`libModel`; its laws are left to provers). `Nat` and `Unit` are not declarations and mean `Nat` and `Unit` directly.

### data-generic: choices (`DataGeneric.lean`)

The generic construction of D4, branch `spine-data-generic`. The choices it made, and the obligations they leave the assembly:

- **The input is a signature of codes** (`Sig`), one per declaration in program order: the constructors' arities, the sort, which parameters are nestable, and for each field a code of its declared type (`PCode`) as a function of the parameters and the earlier fields. A code is `ext T` (a closed small type: everything mentioning neither the declaration nor a nestable parameter, so equations, type-function fields, `Nat`, and earlier inductives at fixed arguments), `par j` (nestable parameter `j`), `self fx tys` (an occurrence of the declaration: fixed parameters `fx`, and a type code `tys j` at each position, used at nestable positions, so non-uniform nested recursion like `NL(Pair(A, A))` is covered), or `nest e fx tys` (an occurrence of the earlier declaration `e`, whose type codes may contain the declaration). The assembly reads codes off the field-type terms and must show that a code read at the colimit (`interp`) is the reference run's reading of the term. That needs docs/18 (I1)–(I6) and three well-formedness facts: type codes only at nestable positions; `ext (tyOf s)` at positions taking a fixed parameter `s`; and the field-type term reading only earlier *closed* fields.
- **Masking.** A field's code sees the earlier fields through `mask`: a closed field's meaning, `err` for a recursive, nested or parameter-typed one. This is what makes the telescope independent of the stage, because a recursive field's meaning differs between stage `k` and the colimit. It is sound because no accepted field type reads such a field. Reading one would need the declaration, or a nestable parameter, written outside a whole field type, which (I1), (I2) and nestability forbid (`SelfEq`, `Loop` are rejected).
- **Nesting is read through the earlier declaration's own carrier, not translated to mutual recursion.** The run reads `List(Rose(A))` as `dm.tyM List [ty (dm.tyM Rose [A])]`, so the field's type must be `List`'s carrier at `Rose`'s carrier. A mutual translation gives an auxiliary type that is only isomorphic to it. Identifying the two would mean defining `List`'s carrier at a `Rose`-carrier parameter by recovering `A` from the carrier, which is D8's `paramsOf` problem again (carriers do not determine parameters). So stage `k + 1` of `Rose` holds `List`'s carrier at `Rose`'s stage `k`, and the colimit argument needs `List` to be functorial in its nestable parameters and finitary: an element over the colimit comes from some stage. That is the interface `NModel` (map, raw meaning relative to the leaves, a predicate on leaves, `lift`, `directed`). The construction *produces* one for every declaration (`nmodel`), so the program's declarations are modelled in order (`progModel`, `progEnv`), and `progEnv_car` says that a later `nest i` reads declaration `i`'s own carrier.
- **Leaf environments and blanking.** A carrier is built at parameters `ps` and a leaf environment `Z : Nat → TyM` (the nestable parameters' types). Codes see `ps` with the nestable positions blanked to `err`, so the carrier depends on a nestable parameter only through its `par` leaves, and is functorial in it with no hypothesis on the codes. The data model takes `Z = envOf ps`.
- **The colimit's equality is raw meaning, relative to a raw meaning of the leaves.** Members of different stages are identified when their raw meanings (`sraw`: constructor and fields' raw meanings, `Sem.ctor` trees) agree, read with the canonical leaf raw. A nested field's raw meaning reads its leaves through the outer declaration's raw meaning, so `NModel.raw` takes the leaf raw as an argument. The master lemma `sraw_rel` (equal raws under related leaf raws stay equal under any related pair) makes this well defined on the quotient and coherent under nesting.
- **`Prop`-sorted declarations** are the same fixed point. An occurrence of one stores `PLift (Nonempty _)`, so a field's meaning is `•` and `pack (fields x) = x` holds. The leaves of the hidden witness are reached existentially (`allLB`), which is what `lift` and `directed` need for a proposition nested in one with a recursive constructor.
- **Field types are cut to `small`** (`Type₀` carriers and propositions; anything else becomes `err`, which has no members), so that `pack` succeeds exactly on members (`gPack_isSome`). This agrees with the run wherever (I6) holds. libModel does the same with its parameters.
- **The rank is the first stage** (`crank`). The rank law is proved on the core carrier (`crank_self`): a field whose code is `self fx tys`, read at that occurrence, has a smaller rank. The interface's `rank_lt` uses the declared-occurrence form the lead adopted (the carrier-equality form is false for `Pair(Pair(Unit,Unit),Unit)`). `recArgs` returns the occurrence's parameters (`occFrom`: the fixed parameters, with the type codes' meanings at the nestable positions) only when the interface carrier there is literally the core carrier the field lives in. That guard is classical, and `gRecArgs_wf` is the bridge: for a well-formed occurrence (fixed parameters blank at the nestable positions, type codes `ext (tyOf s)` at the others) the guard holds. Nested paths (`Rose` → `List` → `Rose`) are not covered by `rank_lt`; that is the semantic [Rec]'s documented gap.
- **`fieldData`, `paramData` and `paramTy` are passed through from the signature.** They are the assembly's readings of the declared types (the structured hints of D8 revised), unused by the construction. `pack_congr` is not part of the interface (dropped with D8's structured hints).
- **Decision (spine, 2026-11-10): parameters carry their own structured hint.** `FieldsFaithful`'s data part is unprovable at a parameter-typed field (`Pair`'s `fst : A` at `A := List(Nat)`): the run's hint carries `("List", [⟦Nat⟧])` from the parameter's structured type, while `fieldData d ps` sees only the carrier, and recovering a declaration from a carrier is D8's problem (false for two declarations of equal carrier). So the parameter hint is to be recorded, not recovered: a parameter's `TyS` keeps its `data` (`Option (String × List TyS)`, D8(c)), and `fieldData` at a `par j` field returns parameter `j`'s data. The run already threads structured hints for fields; the parameters get the same treatment. To do in the assembly; not yet wired.
- **Assembled** as `genericModel (Γ : Prog)`, where `Prog := List (IndDecl × Sig)` is in program order. It covers a declaration that is the program's declaration of its name, with the signature's arities and sort. Declaration `i` is `declDM` at `progEnv` (the models before it). `#print axioms genericModel`: propext, Quot.sound, Classical.choice.

### D5. Code-dependent meanings go through `CodeMeaning` (`Value.lean`)

Globals, closures, Π-closures, sealed programs and deferred D82 types mean "what running code means", which is milestone 2's reference run (the meaning of code, part of [Q2]). `Value.mean` takes a `CodeMeaning` (`global`, `sealed`, `clo`, `pi`, `paramTy`), so the first-order meaning is fixed and checked now, and the reference run will define `Value.mean` and the run in one mutual structural recursion over `Term`/`Value` and prove it agrees with `Value.mean C` at its own `C` (the knot-tying lemma). The run never re-runs a callee's body (it applies the callee's meaning), so it is structural; a recursive `fix` means its guarded fixpoint by well-founded recursion on `DataModel.rank`.

### D6. The meaning of a state and its shape (`State.lean`)

`MState.mean ρ st : Mean` is `(positions, future ↦ position ↦ Sem, shape)`, as docs/27 Def. 2: a lent place means its final content `φ ℓ`, a holder its current content, `⊥` means `moved`. The shape (which position holds the borrow of which label) is a partial map thanks to (WF1). `Mean.semEnd r l` is [End] on meanings and is below (`semEnd_below`, proved); `Mean.forget` is a drop or a capture by move (proved below); `Mean.dependsOn m p l` is what the reference run's [Access] ends.

The reference run's [Access] will end exactly the labels a place's meaning depends on, where the checker ends every label whose loan *occurs* in the content; the step lemma is that the checker's extra ends are below and commute (by WF3's acyclicity).

**The relevance table** (which `MState` fields `⟦Ω⟧` reads) is `State.lean`'s module docstring, with `MState.Core` the relevant projection and `mean_core` the theorem that the rest is irrelevant: read are `env` (values, frame structure; stored types for membership), `inds`, `absTy`, `goal`, `neutrals` and `etaRefs` (conditions on `ρ`), and `globals` through `CodeMeaning.global`. Irrelevant: counters and bounds (`nextLoan`, `nextAbs`, `nextRecUid`, `depth`), caches and logs (`classCache`, `constDecls`, `cfg`, `locs`), and inputs of decisions (`refs`, `recStack`, `convStack`, the declared-type reader's flags, the run-mode flags, `placeLog`). `placeLog` was flagged and resolved: on branch `d84` (both 6400a1d3 and the redesign in progress) the drop at the join and a block's captures are decided statically by `Decide.jdMoves`, from syntax and declared types, and the arms' log is kept only for an internal assertion that never fires. So the log is irrelevant to the meaning and feeds no decision; the reference run's join reads `jdMoves` (to confirm against `origin/d84` when it is written).

### D7. Well-formedness and membership (`WF.lean`)

(WF1)–(WF4) and (WF7) are stated on `MState` as the plan has them, and (WF8), `&` only at the top of a type (D1); (WF5) is `ArgsLoanFree env ws`, a property of a call's argument array, not of a state; (WF6) is split: its naming half (every `σ` in Ω, Δ or the goal has a type in Δ; labels and `σ`s are below their counters) is `WF6`, its typing half is membership. `TypedFuture`: each live borrow's final content lies in its holder's declared content type. `TypedAssignment`: `ρ σ ∈ₛ ⟦Δ(σ)⟧_ρ`, plus the path condition for `neutrals` (`ρ σ = ⟦n⟧_ρ`) and `etaRefs`. `Membership`: under every typed future, every position with a stored type holds a `pmem` of it; Δ's types and the goal are types. `Good ρ st` is the hypothesis of the main theorem. Stored types are read under the constant future `err`, since no stored type holds a live loan (docs/27 Lemma 5; to be a WF clause or a lemma of the skeleton).

### D8. Constructor values without recorded parameters are read at the type of their position (`Value.lean`, `Data.lean`)

`ps = []` constructor values are reachable: `Machine.evalCtor`'s untyped path (around line 2331) builds `.ind ty c h evs ws` with `evs` the parameters *written* in the source; inferred parameters are filled only on the typed path, and untyped runs (sealed-program re-normalisation, callee bodies, D85's runtime) put such values into states. The checker reads their type from the position (D49 (4), `indValType?` when `ps.isEmpty`). A WF clause "constructor values record their parameters" would therefore be false (the lead's review, 2026-11-09).

Chosen: the lead's option (a). `Value.mean ρ φ hint v` reads a value *at a type*, and only a constructor value with `ps = []` of a parameterised type uses the hint: `DataModel.paramsOf d hint` picks, classically, parameters whose carrier is the hint's (`paramsOf_car`: `car d ps = A`), so the element is tagged with the position's carrier and membership holds. The hint is the binding's stored type (`Env.hintAt`, equal to `MState.posTyM` where there is one, `hintAt_posTyM`), a field's type at the earlier fields (`DataModel.fieldTy`, threaded through `Value.meanFields`), a parameter's type (`DataModel.paramTy`, through `Value.meanParams`), or an equation's type; a temporary's hint is `err`, and the step lemmas for in-flight values supply the type the context requires. Everything else ignores the hint, so docs/18's V2 holds in the sense that a constructor value's meaning is determined by its type, recorded or not. Not chosen: (b) inferring parameters from the fields (undetermined for `Nil`); (c) a checker change recording inferred parameters in untyped runs, which would be a separate, verdict-neutral lane and would let the hint go away; worth doing later for simplicity, not needed for soundness.

A subtlety to carry into milestone 2: two parameter lists with the same carrier must pack the same fields to `HEq` elements (a `pack_congr` law on `DataModel`, to add when the generic construction is written), so that the choice in `paramsOf` is immaterial.

### D10. The run is per-future (`Run.lean`; m2-proofs' counterexamples)

m2-proofs refuted the first substitution lemmas in Lean: the run read every position under the constant future and never recorded its own labels in `shape`, so a hole or inert loan read `err` and a borrow the run made could never be ended. Now `run K ρ φ hint t : SState → Option (Res × SState)` with `Res := Sem × TyS` is the run **at the future `φ`**: every read of a position evaluates its `SVal` at `φ` (a free label means `φ l`; a match on a free hole picks its arm at `φ`), the run's own labels are recorded in `shape` at the position that comes to hold the borrow (`pushBindShaped` for a `let`; a result's label travels in `TyS.label`), ended by `access`/`endLabel` (= `Mean.semEnd`) before they are read, and a `let`'s drop ends the label its binding holds. The meaning of a configuration `(Ω, t)` is `fun φ => run K ρ φ hint t (Ω's sstate)`, result and state read at `φ`; that is the reference Mean every step lemma compares with. A sealed program's run starts its label counter above its loans (`emptyState n`). `meanV`'s `.tPi` clause wraps in `.ty`; capture types are read at the ambient `φ` (types are future-free at reachable states, so `meanV_congr` uses the `hasLoan` form of its hypothesis, which looks inside `rd`). `CodeMeaning.global : String → Sem × TyS` (a global's Π-shape), and `piShapeOf` computes a closure's or Π-closure's shape from its term, used by `.val`, `codeMeaning.paramTy` and `Steps/Call.calleeRes`. `Decisions.joinMoves` takes the entry-moved set (`movedPlaces`), as d84's `jdMoves` does. (Superseded by D18: `codeMeaning K ρ φ` ignored its assignment and future arguments, on the belief that `Value.mean` is read only at the state's own; it is not, and `codeMeaning K` now passes both through.)

### D11. The join drop follows `Machine.dropAtJoin`; Prop constructors mean `⋆` (mono-lemmas, prog-decisions)

mono-lemmas showed `joinDrop_below` false at field places (a field set to `moved` makes the value a `ctor`, never below an `el0`) and listed four differences from d84's `dropAtJoin`. `joinDrop` now accesses the place first, leaves copy places (by the declared reading), proofs and places already `⊥` alone, ends a borrow held at a dropped root, and sets the place to `moved`; the match step lemma compares the checker's post-state with the run's (both after their drops), so it needs no "below its input" claim. `Sem.updAt`'s overlapping patterns mean it has no equation lemmas (unfold with `Sem.updAt.eq_def`); a prover who needs them should split the `Nat` case into its own function. prog-decisions found that a constructor of a `Prop`-sorted inductive went through `ctorM` where the checker gives `⋆` (D42): `run`'s `.ctor` and `meanV`/`Value.mean`'s `.ind` now mean `.proof` for `d.sort = 0`, the fields run as statements. m2-proofs' counterexample file is archived verbatim as `Ochr/Meaning/Regress/CE_82394c1a.lean` (not built; each example is to become a positive check against the current run).

Open: a bridge from `WF3 st.env` to mono-lemmas' semantic `SWF3 (st.sstate …)` needs a future-locality law on the run (a sealed program's, closure's or Π-closure's meaning reads the future only at the loans it contains) — `meanV_congr` in its `hasLoan` form is that law for values; the run-level form (`run φ t s = run φ' t s` when `φ`, `φ'` agree on `t`'s loans and the state's live and free labels) is to be stated in `Lemmas.lean`. prog-decisions reports a checker bug, not the spine's: `Decide.sortOf` reads a Π-term's domain through `declSort → declOf false`, so `Π(f : Π(x : Nat). Prop). Nat` gets declared sort 1 but computed sort 2, and `def T : Type₁ := Π(f : Π(x : Nat). Prop). Nat` is rejected with the INTERNAL [D55] message; pinned by `DecisionsSanity.piSort_nested` on their branch.

### D12. Closures at their declared sort; proof calls are `⋆` (prog-decisions' review)

The `.fix` clause built `el0 (piCar0 …)` whatever the Π's sort, so a proof-valued function and a polymorphic function (`id (A : Type) (x : A) : A`, in `Type₁`) meant elements outside their types' meanings. Now the clause reads the sort (`Decisions.piSort`, D55): at `Prop` the closure means `⋆` and its type is the proposition `piProp`; at `Type₀` it is `el0 (piCar0 …)`; at `Type₁`/`Type₂` its type is `ty1 (piCar1 …)`/`ty2 (piCar2 …)` but its *value* is `err` until a level-1/2 `mkTele` (parameters decoded at `el1`/`el2`, type arguments by `dec1`) is written: an open gap, visible rather than silent. A call whose class is "returns proofs" (`Decisions.flags`'s second component) yields `⋆` without applying anything, typed by the codomain at the arguments, as `Machine.callFn` does at class 2 (P5). **Closed by prog-decisions' `Apply1.lean` (landed eec3d961, wired in the following commit):** one level-generic construction (`Lvl` packaging el/enc/dec/ty and the `Sem` tag at each level; `piCarL`, `applyTeleL`, `mkTeleL`, `closureAt`, `piTyAt`, `applyFnL`) with β-laws (`applyTeleL_mkTeleL`, `applyFnL_closureL`) and round trips; `run`'s `.fix` builds the closure at its declared sort through `closureAt`, `.pi` gives `piTyAt`, and `callOf` dispatches on the callee's tag (`el0/el1/el2`). ### Conventions an implementer must keep

- **Totality and `err`**: every semantic function is total; an ill-formed input means `Sem.err`/`TyM.err`/`none` (the run fails with `none`). Never add a `partial` or an axiom; everything is `noncomputable` and uses `Classical` freely (`open Classical` in Apply/Places/Run).
- **Futures**: a position's meaning is `SVal := Future → Sem`; read a value that is future-free under `noFuture`; `Future.upd`/`updList` fix labels; ending a label is `endLabel` (the holder forgotten, every meaning reads the label as the holder's current content). A fresh label comes from `freshLoan`; a borrow result carries its label in `TyS.label` so a call can fix its lender's future.
- **Hints (D8)**: `run hint t` and `meanV φ hint v` read a value at the type its context expects; pass `.err` when there is none; only `ps = []` constructor values use it. Field hints come from `fieldTy`, parameter hints from `paramTy`, argument hints from the callee's shape.
- **Shapes (D9)**: a Π-type's shape travels in `TyS.shape`; a function value's result carries none (gap (ii) below).
- **Statements** run on a copy: `SM.onCopy`. Which terms are statements is `Decisions.flags`, never a check of the value.
- **Open recursion**: everything that runs code must be in `Run.lean`'s mutual block, structurally recursive on `Term`/`Value`; a call to `run` on a lambda-bound term (e.g. inside `List.map`) is rejected by the termination checker: write a mutual list helper (`runDoms`, `runArm`, `runFields`, …) instead. `Nat.rec` with a `run body` call inside its step is accepted (the `fix` clause's stages).
- **Checker names shadowed**: the run's `readPlace`/`borrowPlace` shadow `Ochr.readPlace`/`Ochr.borrowPlace`; qualify the checker's in statements.
- **No Mathlib**: `List.Forall₂` etc. are unavailable; the project imports Lean core only.

### The `fix` clause (filled) and its spec

A closure `fix self (x̄ : Ā) : B by xⱼ := body` formed in state `s` means `el0 (piCar0 ps [] PUnit out) F` (or `err`), where `ps := runDoms s ds` (each domain term run in `s` extended by the earlier parameters; `&A` marks a borrow parameter with content type `A`), `out` is the codomain term's meaning per prefix (`.ref U` for a borrow result), and `F := mkTele ps [] PUnit (fun fs => some ((), fs)) out g`. `g args` runs `body` in `s` extended by `self` (type `ty0 piT`, value `selfM`) and the parameters (each at its `dom` of the prefix; a borrow parameter's holder's value is the argument's content), at the codomain hint; then ends every label ≥ the label counter at formation (the frame pop ending the body's borrows) and reads each borrow parameter's holder for its final content; `retLabel` is the result's `TyS.label`. Non-recursive: `g := bodyAt .err`. Recursive: `g args := stage (rankOf args + 1) args` with `stage 0 := fun _ => none`, `stage (k+1) := bodyAt (closureOf (stage k))`, and `rankOf` the `DataModel.rank` of argument `j` through the carrier of its parameter type (a `Nat`'s value). Forming moves non-copy captured places (`Decisions.copy` of their reading). **Not done**: `SBinding.recBound` is unused (the guard is realised by the stages); a `WellFounded.fix` formulation was dropped because the carrier holds total functions only and a "restricted" element cannot be built. The stabilisation lemma for a decreasing body (stage `k > rank` agrees with stage `rank + 1`) is the semantic form of [Rec] and is a milestone-3 statement (`Steps/Call.lean`, `recCheck`'s accepting direction).

### The knot and what could go wrong

`codeMeaning K` packages `meanV K` as a `CodeMeaning`, reading at the assignment and future it is passed (D18; as first written it ignored them, a definition fault); `meanV_eq_mean` says `Value.mean K.dm (codeMeaning K) K.Γ ρ φ hint v = meanV K ρ φ hint v`. It is well founded because `meanV` is defined *inside* the mutual block by structural recursion (a sealed program's run is on the term inside the value; a closure's on the term inside the value), so `codeMeaning` is a plain definition after the block, not a fixpoint. Risks: (1) `K.C.global` must be the program meaning (`Program.lean`, implementer prog-decisions) and is the one truly external input; (2) `meanV`'s `.tPi`/`.clo` clauses run the term in `stateOf (capsState (capsVals φ caps) (capsTys φ rd))`, which has no declared readings beyond `rd`'s and no label counter, so a closure whose code reads a capture's declared type for copy-or-move must find it in `rd` (D82 says it does); (3) `codeMeaning.paramTy` reads the Π-type value's shape through `run … (.val P) emptyState`, which goes through `meanV (.tPi …)` and loses the shape (a `.val` result has `shape := none`): **this is wrong as written** and must be fixed by computing the shape from the `tPi`'s term as the `.pi` clause does (make a `piShapeOf` helper in the block returning `Option (List PiParam × PiOut)` for a `tPi caps (pi hs ds c) rd`, and use it both in `.pi`'s result and here). The same helper is what `Steps/Call.lean` needs to state the callee's shape from its type value.
