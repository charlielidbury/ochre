## Running

```
./setup.sh                 # once, online (a few minutes; Aeneas's Lean library takes ~8 min to build)
./grade.sh                 # grades the package itself: FAILs on the skeleton, naming the 3 holes
./grade.sh SOLUTION_DIR    # grades another directory (the authoritative grade: run it from the repo)
./make-sandbox.sh DEST     # a fresh sandbox for one trial
```

`grade.sh` never builds in the graded directory. It copies the pristine skeleton (from the repo, or from `grader/orig` inside a sandbox) to `.grade/work`, overlays exactly the files in `SOLUTION_FILES`, and then: checks the FIXED regions with `../../common/check_fixed.py`; scans the solution files for holes and forbidden constructs; runs `cargo test`; regenerates the model with `translate.sh`; runs `lake build`; and finally writes `GradeCheck.lean`, which restates every FIXED theorem in a context no solution code can influence (the skeleton's names opened, not the namespace entered) and checks the solution's theorem against it, plus `#print axioms` for each (only `propext`, `Classical.choice`, `Quot.sound` allowed); the same file inspects the environment and rejects any instance, axiom, opaque constant or meta-level declaration (a type mentioning `Lean.Elab`, `Lean.Meta`, `Lean.Environment`, `IO`, ...) from the solution module. Finally `lake env leanchecker` replays the library's modules through the kernel, because `#print axioms` is blind to a declaration added with `addDeclCore (doCheck := false)` (bench-controls' finding; validated here as cheat (e), which the first version of this grader passed). The last line starts with `GRADE: PASS` or `GRADE: FAIL`.

Forbidden constructs are listed in `ASSIGNMENT.md` §6 and implemented in `grader/package.json`. Beyond the protocol's list for `aeneas`, the grader also forbids, in Lean, new notation/macros/elaborators, `export`, instances and `unif_hint` (each can change how a FIXED statement elaborates), `#eval`/`run_cmd`-style commands, and meta-programming (`import Lean`, `open Lean`, elaborator and initialiser attributes, environment access, meta-level types); in Rust, copying (`clone`, `to_vec`, ...), `cfg`, `macro_rules!`, `include!` and raw pointers.

## The sandbox

`make-sandbox.sh DEST` copies, by explicit list, the package's own sources (and a pristine copy of them in `grader/orig`), `check_fixed.py`, `vendor/aeneas` (Aeneas's `backends/lean` pre-built, `documentation/`, `docs/user/`, the tutorial from `tests/lean/Tutorial` and `tests/src/tutorial`, README, licence), `vendor/charon-docs`, `vendor/lean-docs` (Theorem Proving in Lean 4 at `4e28129f`, Functional Programming in Lean at `0abeea54` and the Lean reference manual at `4f677697`: the `lean` condition's pins, so both Lean-based conditions have the same Lean documentation), `lean/.lake/packages` (Mathlib and dependencies, pre-built), and the Lean toolchain into `DEST/.elan`. `DEST/.tools` is a symlink to the Nix store path of the tools, and `DEST/.tools-closure` lists every store path the sandbox needs (the tools' closure plus the store paths NixOS's elan patches into the Lean toolchain). **The runner must expose exactly those store paths and no others**: this host's store also holds the full Aeneas source (the flake input), whose `tests/` holds Aeneas's own verified examples (a hashmap among them; no sort).

What the agent can and cannot reach (checked by `make-sandbox.sh`, which fails if an exclusion is violated):
- Not reachable: Aeneas's `tests/` (including `tests/lean/Hashmap/{Funs,Properties}.lean` and `tests/src/hashmap.rs`); none of the definitions distinctive of Aeneas's hashmap test (`allocate_slots`, `move_elements_from_list`, `insert_no_resize`, `try_resize`, `hash_key`) occurs in any `.lean` file of the sandbox, Mathlib or Lean core included; no `.lean` file in the tools closure; nothing from this repository outside the package (no Ochr sources, paper, notes, `competitors/`, `_reference/`).
- Reachable, as general library content every Lean or Rust condition has: Lean core's `Std.HashMap` and `List.mergeSort` with their lemmas, Mathlib's `List.Sorted`/`List.insertionSort`/`List.mergeSort` lemmas (57 files with hash-map or sort in the name across Mathlib, Batteries and Lean core); Functional Programming in Lean's chapter on an in-place insertion sort over `Array` (`book/FPLean/ProgramsProofs/InsertionSort.lean` and its examples; the `lean` condition ships the same); the Rust standard library's sources in the toolchain's `rust-src` component, including its (unverified) `HashMap` and slice sorts (`core/src/slice/sort/unstable/quicksort.rs`). One docstring in Aeneas's library (`Aeneas/Tactic/Step/Step.lean`, the `step` tactic's documentation) shows the *statement* shape of a `hashmap_insert_spec` with a ghost model, as an example of ghost variables; it contains no proof.

Validated on 2026-09-30: a sandbox built by `make-sandbox.sh` grades on its own with no network (`unshare -rn`) and an empty environment (`env -i PATH=$DEST/.tools/bin`).

## Fairness notes for this condition

- The signature is the natural Rust one, `pub fn quicksort(a: &mut [u64])`, and its model `quicksort (a : Slice U64) : Result (Slice U64)` is what Aeneas generates for it; nothing about the task is unnatural for Aeneas. `split_at_mut` and `swap` are supported and have `@[step]` specifications in the library.
- `sorted` and `perm` are stated over `s.val : List U64`, the list view of an Aeneas slice. `sorted` uses `l[i]!` (the `getElem!` form that `#setup_aeneas_simps` and Aeneas's list lemmas work with), guarded by `j < l.length`; `count` is recursion over the list. Mathlib's `List.Perm` and `List.Sorted` are reachable and an agent may prove the FIXED definitions equivalent to them.
- Q1 and Q2 are total (`⦃ ⦄`): the agent proves termination of the recursion (by the slice length) and of the partition loop, and the absence of `usize` underflow and out-of-bounds indexing. Ochr's version instead takes fuel and proves the fuel suffices.
- Q1 and Q2 are separate theorems, each with its own `⦃ ⦄`; an agent will naturally prove one combined lemma and derive both.
- The Rust bans `Vec`, `vec!` and `Box` (A3: O(1) auxiliary space) and library sorts, selection and `reverse`/`rotate` (A4); recursion depth is not checked.
