# Coursework: a verified in-place quicksort in Rust, with Aeneas

## 1. Overview

Implement quicksort on a slice of `u64` in Rust, in place, with the two recursive calls made on two disjoint borrowed sub-slices, and prove that the result is sorted and is a permutation of the input.

You verify your Rust with **Aeneas**. Charon compiles your crate to an intermediate language (LLBC), Aeneas translates that into a pure functional model in Lean 4, and you prove the properties in Lean about that model. The model is regenerated from your Rust every time you grade, so the proofs are always about the code you wrote.

You are done when `./grade.sh` prints `GRADE: PASS` and exits with status 0 (section 8).

## 3. What to build

### 3.1 Operation (FIXED signature, in `rust/src/lib.rs`)

```rust
pub fn quicksort(a: &mut [u64])
```

It sorts `a` in place, in ascending order, and returns nothing. The length of `a` never changes. You write the body, and you may add private helper functions (a partition function, for instance) anywhere outside the FIXED region.

### 3.2 Algorithm requirements (checked by a human reader, not by the grader)

- **A1 (partition).** Choose a pivot and partition the range with the Lomuto or the Hoare scheme. Say which in a comment at the partition function.
- **A2 (two disjoint recursive calls).** After partitioning, split the slice into two disjoint sub-slices that are borrowed separately (with `split_at_mut`, or reborrows in its style), and sort each by a recursive call. The pivot's final position, if the scheme has one, belongs to neither.
- **A3 (in place).** No copy of the array or of a sub-range is made (no copy out and copy back, no temporary array). Auxiliary space is O(1) beyond the recursion.
- **A4 (nothing extra).** No library sort, selection or permutation routine, and no other sorting algorithm as a fallback (for example insertion sort on small ranges).

## 4. What to prove

### 4.1 Definitions (FIXED, in `lean/Quicksort/Spec.lean`)

They are about the list of elements of a slice (`s.val : List U64` for `s : Slice U64`):

```lean
def sorted (l : List U64) : Prop :=
  ∀ i j, i < j → j < l.length → l[i]!.val ≤ l[j]!.val

def count (x : U64) : List U64 → Nat
  | [] => 0
  | y :: l => (if y = x then 1 else 0) + count x l

def perm (l₁ l₂ : List U64) : Prop :=
  ∀ x, count x l₁ = count x l₂
```

`sorted`: every element is at most every later element. `count x l`: the number of positions of `l` holding `x`. `perm`: every word occurs equally often in both lists.

### 4.2 Properties (FIXED statements, in `lean/Quicksort/Properties.lean`)

For every slice `a` with contents `a₀` before `quicksort(&mut a)` and `a₁` after:

| Id | Theorem | Statement |
|---|---|---|
| Q1 | `Q1_sorted` | `quicksort a ⦃ (a' : Slice U64) => sorted a'.val ⦄` |
| Q2 | `Q2_perm` | `quicksort a ⦃ (a' : Slice U64) => perm a'.val a.val ⦄` |

How to read them: `f x ⦃ (r : T) => P r ⦄` is Aeneas's total-correctness triple: `f x` terminates without panicking, and its result `r` satisfies `P r`. `quicksort` takes `&mut [u64]`, so its model `quicksort (a : Slice U64) : Result (Slice U64)` takes the slice's contents and returns the contents when the borrow ends. Both properties hold for every input, with no hypotheses.

In `Properties.lean` you may add definitions and lemmas anywhere outside the FIXED regions. Tagging your own lemmas `@[step]` lets the `step` tactic use them.

## 5. Tests

`rust/tests/spec.rs` (FIXED) holds the test vectors, transcribed mechanically. Each test sorts one array in place and compares it with the expected result:
- hand-picked cases: empty, one element, two elements in each order, duplicates, already sorted, reverse-sorted, all equal, and a short mixed array with repeated pivot values;
- 20 pseudo-random arrays of lengths 0 to 24, with values up to 99, some drawn from 0 to 3 so that duplicates are frequent.

Run them with `cd rust && cargo test` (grade.sh runs them too).

## 6. What is provided, and what is forbidden

Provided: everything in this directory (section 2).

Your solution is the two files listed in `SOLUTION_FILES`: `rust/src/lib.rs` and `lean/Quicksort/Properties.lean`. Edit them only outside the FIXED regions (the text between a `FIXED-BEGIN <id>` comment and the matching `FIXED-END <id>` comment, both included, must stay byte-identical). grade.sh takes exactly these two files from your directory and everything else from a pristine copy, so changes anywhere else (other files you create, the lakefile, `Cargo.toml`, `Spec.lean`, the vendored libraries, the generated model) have no effect on grading: put all your helper functions, definitions and lemmas in the two solution files.

Forbidden in your Rust (outside comments and strings):
- `todo!`, `unimplemented!` (holes);
- `unsafe`, raw pointers, `transmute`, `extern`;
- heap allocation: `Vec`, `vec!`, `Box`, library collections;
- copying: `clone`, `Clone`, `cloned`, `to_vec`, `to_owned`, `copy_from_slice`, `clone_from_slice`, `copy_within`;
- library sort, selection or permutation routines (`.sort*()`, `select_nth*`, `.reverse()`, `.rotate_left()`, `.rotate_right()`, `swap_with_slice`);
- `#[charon::...]` and `#[aeneas::...]` attributes, crate-level attributes `#![...]`, conditional compilation (`cfg`), `include!`, `macro_rules!`.

Forbidden in your Lean (outside comments and strings):
- `sorry` (holes), `admit`, `axiom`;
- `native_decide`, `decide +native`, `ofReduceBool`, `implemented_by`, `extern`, `unsafe`, `opaque`, `partial`;
- new syntax, notation, macros or elaborators (`macro`, `syntax`, `notation`, `infix`, `elab`, ...), `export`, instances (`instance`, `attribute [instance]`, `deriving instance`) and `unif_hint`, because they can change what a FIXED statement means;
- `#eval`, `#exit`, `run_cmd`, `run_tac`, `run_elab`, `run_meta`, `initialize`, and `debug.*` options.

Also forbidden: any other way of making a FIXED statement mean something else, or of making the proofs depend on axioms other than `propext`, `Classical.choice` and `Quot.sound` (grade.sh checks the axioms of every theorem).

## 7. Aeneas notes

- Machine arithmetic panics on overflow and underflow, in Rust and in the model (`fail`): `usize` subtraction below zero is a panic, so is an out-of-bounds index.
- `usize` in the model has a platform-dependent width (32 or 64 bits); slice lengths are at most `Usize.max`.
- `split_at_mut` translates to `core.slice.Slice.split_at_mut`, which returns the two halves and a backward function that puts them back together; its `@[step]` specification is in `vendor/aeneas/backends/lean/Aeneas/Std/Slice.lean`.
- Recursive functions and loops translate to definitions by `partial_fixpoint` and `loop`; a total-correctness triple about them needs a termination argument (induction on the length, or a loop measure; see `proof-strategies.md`).

## 8. How to check your work

Run `./grade.sh` in this directory. It:
1. checks that every FIXED region is byte-identical to the original;
2. lays your two solution files over a pristine copy of the skeleton in `.grade/work`;
3. scans them for holes and forbidden constructs (section 6);
4. runs the tests (`cargo test`);
5. regenerates the Lean model from your Rust (Charon, then Aeneas);
6. builds the Lean project (`lake build`);
7. restates every FIXED theorem in a fresh file, checks that your proof proves exactly that statement, and checks the axioms it depends on.

Each problem is printed on its own line, with the hole or construct it found; logs are in `.grade/`. The last line is the verdict: `GRADE: PASS (...)` or `GRADE: FAIL (...)`, followed by your solution's size (non-blank lines outside the FIXED regions; a secondary measure, reported for information). The exit status is 0 exactly when the verdict is `GRADE: PASS`.
