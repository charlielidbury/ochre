## 1. Decided, and why

- **What the checker does with an open value** (main after D112, `f7e46755`). A value is open when a dependent field's content does not fit its declared type at the current earlier fields; the state records no per-field type. A dependent field is a TREE field when its declared type reads (through type-function bodies, `Decide.typeDecl`) as a data inductive at every instance, else a LEAF field (`Decide.fieldIsLeaf`). A tree field is typed by what it holds when it does not fit (`depFieldType`), and its assignment is a strong update storing unchecked only a value whose declared type reads as a tree (`strongStorable`); anything else is a checked write. A leaf field, like a proof field, is invalidated to `⊥` by a write or borrow through an index its type mentions (`openWrite`, after an [Access] of a lent leaf), checked when assigned (with lent parts unknown: `lentLeafCheck`, `lentProofAssign`), never typed by content. [Entry] invalidates for every `&` capture on both paths. [Repack] (read or borrowed whole, a borrow's end in a typed run, [Return], captures, `Id`) checks closedness with lent parts unknown. Instance runs never repack.
- **Why route B (the checker changed, not the model)**: a leaf's meaning (`.el0 A a`: numbers, units, functions) is tagged only by its Lean carrier, which does not determine its code, so the model cannot type a leaf by content; `Records.leaf_read_type_blind` (kernel): at every data model the read type of a leaf ignores the leaf, while the checker read `5` at `Nat` and `()` at `Unit` under one index. Only trees describe themselves. The uniform variant (trees invalidated too) changes at least 22 suite verdicts (the either-order writes, D64's ruling). Measured and landed as D112 (DECISIONS entry on main); then rows asserting a borrow/proof/type/function is a checked write in tree and leaf fields (`93cc0bb5`, for D111).
- **D112 amended (main `c655e619`, `d1cd9941`)**: typing reads through a mark (`lent_g`, a field lent to a call's returned borrow) as paths and the repack do (`valType?`, `packedErr`, `depFieldType` via `Value.unmark`). Before D112 the red team's `A2`/`Boom` (a closed `False`) went through the fallback; after D112 the same blind spot rejected ordinary reads (`LeafLegit`, `TreeLegit`). Now a plain borrow and a call-returned borrow agree row by row (`DependentFields.MarkedFields`, 60 rows). Census (DECISIONS D112, amended): every content a typed run leaves in a dependent field has a readable type (constructor value: recorded parameters, (WF10); number, unit, closure: leaf fields only; unknown; stuck program, D97; loan, live by (WF2); marks, through; `⋆` only in proof and leaf fields; `⊥` its declared type), so "[Open] … whose type cannot be read" is an assertion with a census behind it.
- **Model rulings (orchestrator, 2026-11-21)**: whole reads and whole borrows are strict (fail unless the value is a closed member); a field read gives an open member; where the checker treats lent parts as unknowns the strict test holds at every typed future; borrow ends stay non-strict (sound with open members at positions and closedness tested at whole reads and returns; an ended label's content must be an open member of its content type). The type a read gives comes from the parent's TYPE (its declaration and record), never from a lookup of the value's name (`spine-model` `Strict/MemReadsCE.lean`: by-name lookup makes the read hypothesis uninhabited), except for a tree a strong update stored, which carries only its name.

## 2. The invariant (`OMem.lean`, standard axioms)

`OMem dm Γ s T`: `moved`; or `member t` (below, `MovedOf`, a whole member `t` of `T`); or a tree `.dat d.name r c fs` at `T = dm.tyR d r` (data sort) whose every field satisfies `OField dm Γ d r c i (fs.take i) f`: `moved`; `fits` (below a whole `t` fitting the declared shape `dm.sig.shape d r c i (e'.map small)` at a completion `e'` of the earlier fields: a leaf, or a closed tree); `sub` (a tree of the declaration `d'` that the parent's record names there, `.sub d' r''`, open at its own record `r'`); `byContent` (a tree of a declaration found by name in `Γ`, open at its own type: what a strong update stored). No whole open value need lie above an open one (`Records.below_no_member`), so the notion is structural, not "below a whole member".
- PROVED: `omem_of_pmem_member` (a partly moved member is an open member, by construction); `closed_iff_mem` (`Closed`: a tree each of whose fields fits its declared shape at the current earlier fields; closed is member, `mem_iff`); `field_cases` (the read clause, one step: a field of an open value is moved, a partly moved member of its declared shape's type, or an open member of the type its own tree names); cases at the hand model: `omem_belowAt`, `omem_belowMovedAt` (the reachable states of `Records`), `not_omem_junk` (the unit value in a `Fin1(0)` field, which `OpenIn` admits, `Records.open_admits_any`).
- GUESSES (not proved): (G1) a read along any path from an open member gives an open member of the type the read gives (induction on the path with `field_cases`; needs `readTy` below to agree with each case); (G2) every state the checker reaches, mapped to the model, has every binding an open member of its stored type (the checker-side fact behind it: after D112 every field's content is of the type its own content determines, trees by record, leaves by the declared type at the current earlier fields or `⊥`; tested on probes, not on recorded states).
