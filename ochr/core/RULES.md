## 0. Principles

- **P1 Evaluation, not rewriting.** One deterministic call-by-value machine. Definitional equality is "same normal form", normal forms being what the machine produces on symbolic inputs. The normal form of a function value is the observation of its generic call (as in [Def] and `Id`: its result together with the final contents of the generic owned places `cᵢ`), plus its captured values; so two functions are convertible only if they have the same effects (D30). A comparison that needs itself (a recursive function whose generic call is stuck on its own sealed call) answers "not convertible": sound and incomplete; assuming equality coinductively would identify any two recursive functions of the same type (lean-checker, v1.5 round).
- **P2 Erased terms leave no trace.** Types and proofs are erased at runtime. *Which* terms are erased is a syntactic property, never decided from a normal form (D28, D35): a function (top-level or local) returns types if its codomain term is syntactically a sort, and returns proofs if its codomain term's *declared* sort is `Prop` (the sort obtained by typing the codomain term from the declared types of its heads, without normalising it); a call is erased iff its callee's class says so. The class and the [Close] row (§3) are part of the function's *type* (D54): a Π-type records the class and row determined by its codomain term when it is formed, a function value has the class and row of its declared Π-type, and two Π-types are convertible only if their classes are equal and either both or neither return a borrow (as well as their parameter types and codomains, D48). There is no separate `Unit` row: since D59, values at `Unit` are η-normal (§4), so a stuck `Unit`-returning call yields `()` wherever its type is known to be `Unit`. So wherever a function is passed, stored or returned, the class read from the value at a call equals the class the static type promised, on every evaluation path. **Sorts are syntactic (D55).** Every term written where a type is expected (a binder's type, a codomain, a `let` annotation, the components of a Π-type, the type slots of `Eq`, `Id` and `J`, the parameter and field types of an inductive) must have a declared type (read from the declared types of its heads, without normalising, as above) that is syntactically a sort `Prop` or `Type_i`. A type whose sort is only known by computation (`T(Z)` for `T (n : Nat) : P(n)` with `P(n)` computing to `Prop`) is rejected there. The sort of a Π-type is read from its codomain's declared sort (`Prop` exactly when the codomain's declared sort is `Prop`, which is also exactly when its class is "returns proofs"). Since evaluation preserves declared types, a type's declared sort and computed sort coincide, so "is a proof" has one meaning: a term is a proof iff its type is a proposition, every value of a proposition is `⋆`, and conversion can never move a relevant value into a proposition. Any other term is erased iff it stands in a type position (an annotation, a Π domain or codomain, the type slots of `Eq`, `Id`, `J`, `let x : T`) or its declared type has sort `Prop`. A stuck block is erased exactly when *each of its arms* would be erased by this rule (not by the call rule applied to its computed codomain, and not by a type inferred from the arms, which is computed: lean-checker P2); an annotated `let x : T = match …` with `T` of declared sort `Prop` is erased as a whole, on both paths. Universes are not cumulative (`Prop` is not a subtype of `Type_0`); this is load-bearing. Erased terms so the machine evaluates them on a *private copy* of the environment, argument evaluation included, and discards the copy. A formed type is therefore a closed statement: everything it mentions from outside is captured by value (a Π-type is a closure over values, and may not capture a borrow), later mutation never changes it, and only a Π-type's parameters are bound later, at each call. A proof may mutate places it creates itself on its copy, but (D41) an erased term may not write, borrow or move a place that outlives it except by passing it to an erased call, and the machine checks this: an erased term that would do so is a type error. So running a proof and skipping it are indistinguishable, and the machine may skip it; and any disagreement between two evaluation paths about *whether* a term is erased becomes a type error on the path that erases it, never a closed proof of false. A term's declared type is read from its heads without normalising; a match some of whose arms are proofs and some not has no declared type, and a definition containing one is rejected, dead arms included (rule-audit item 10, one reader of declared types; 601c3ca9: rejected where it is written, since the machine reads the declared type of every term it runs).
- **P3 Reads move, except copies and erased reads (D53, adopted when the fuzzer's execution-oracle acceptance passed: 0 of 10⁶ accepted programs go wrong when run; the checker's old copy-on-read semantics is deleted).** Reading a place at runtime moves its content out: the place then holds a *ghost* of the value and is dead to runtime code. A borrow is always moved (the place becomes `⊥`). Data whose type is a *copy type* is copied instead: `Unit`, a sort, a proposition, an inductive declared `copy` (the library's `Word`, §8), a non-recursive inductive in `Type₀` whose fields are copy types, and a closure whose captures are copies. A read inside an erased term (P2: a type, a proof, a statement, `clone(p)`, a sealed program's final read) copies, and sees a ghost's value: erased uses of a moved value do not count, in whatever order they come. `clone(p)` copies any place explicitly. Reborrowing is explicit (`&*x`, `&p`).
- **P4 Close off stuck computations.** A call whose body is stuck on an abstract value is replaced by *sealed programs*: closed source programs that own their state, one for the result and one for the final content of each place the call borrowed.
- **P5 (merged into P2 in v1.3.)**
- **P6 `Id` observes.** `Id A t u` computes to `Eq` between the observations of `t` and `u`, each run on its own copy of the current environment.

## 1. Syntax

```
terms  t, u, A, B ::= x | Prop | Type_i
                    | Π(x₁:A₁ … xₙ:Aₙ). B                   n-ary dependent function type
                    | fix f (x₁:A₁ … xₙ:Aₙ) : B by xⱼ := t  n-ary function; `by xⱼ` names the decreasing parameter; without `by`, `f` is not in scope in `t` (a λ); `f` is never in scope in `Ā` or `B`
                    | t(u₁, …, uₙ)                          saturated call
                    | Nat | Z | S t | Unit | () | A × B | (t, u) | t.1 | t.2      notation for the library inductives Nat, Unit, Pair (D52); t.i is field i
                    | Eq A t u | refl | J(A, a, b, P, h, t)                       (Eq is primitive, in Prop)
                    | D(ā) | C(t₁, …, tₖ) | match p {}                                 inductive types (with parameters ā), constructors, zero-arm match
                    | &A                                      borrow type (A borrow-free)
                    | p | &p | p := t | let x = t; u | let x : A = t; u | t; u | clone(p)
                    | match p { Z => t, S y => u }            y is the sub-place p.1, not a copy
                    | C(t₁, …, tₖ) | match p { C₁(ȳ₁) => t₁, … }   general inductives: constructors; one arm per constructor, ȳ the field places p.g
                    | Id A t u
places p ::= x | *p | p.1 | p.g                              (p.g: field g of a constructor value)
declarations  [copy] inductive D (a₁ : A₁ …) : s := C₁(g₁ : B₁, …) | …   s ∈ {Type₀, Prop}; zero or more constructors; uniform parameters ā (D45, D46); fields first-order data or parameters (D36); `copy`: a copy type (D53, §8)
library       inductive False : Prop                              (no constructors)
              inductive True : Prop := I                          (refl is notation for I)
              inductive And (P : Prop) (Q : Prop) : Prop := Intro(l : P, r : Q)   (P ∧ Q, ⟨h, k⟩ are notation)
```

A Π-type whose codomain is `&T` must have at least one parameter of borrow type (D44). Scope: user-declared inductive types with several constructors and several fields, whose field types are first-order data (inductives already declared, including `Nat`, `Unit`, `Pair`, and the type being declared; no `Π` and no `&`: strict positivity in its simplest form, D36) (sub-places `p.f`; [Split] refines `σ` to `C(σ₁…σₖ)`; [Rec] strict subterms range over all fields), among them `Nat`, `Unit`, `Pair` and the Prop connectives. `&A` is the type of a variable, parameter or result only, never inside another type (no borrows inside data; closures capture no borrows). No shared borrows, no loops.

## 2. Runtime structures

```
values    v, w ::= C(ā; v̄) (Z, S v, (), (v, w), …) | ⋆ | closures | types | borrow_ℓ v | loan_ℓ | ⊥ | ghost(v) | n
neutrals  n    ::= σ | ⌈t⌉
environment Ω  ::= a stack of frames of bindings  x : A ↦ v
```

- `borrow_ℓ v`: a borrow; the borrowed content lives in the borrow (LLBC). `loan_ℓ`: the placeholder at the borrowed place. **A loan is a variable bound by its borrow**: it may occur anywhere inside a value, and more than once inside sealed programs.
- `σ`: an abstract value (Lean's fvar). `⌈t⌉`: a *sealed program*, a closed program whose run is stuck; a sealed program of sort `Prop` (e.g. a stuck call of a Prop-valued function such as `Le(σ, σ')`) is a type. `⋆`: the (irrelevant) value of a proof, e.g. of `refl`.
- `⊥`: a place that has been moved out of.
- A value is *borrow-free* if it contains no `borrow_ℓ` and no live `loan_ℓ` (inert loans, see [Seal], count as borrow-free).

## 3. The machine: ⟨Ω, t⟩ ⇓ ⟨Ω', v⟩, or stuck

- **[End ℓ]** Replace `borrow_ℓ v` by `⊥` and substitute `v` for every occurrence of `loan_ℓ`. Loans inside `v` travel with it. `v` must be whole: a ghost or `⊥` anywhere inside it is an error (D53: moving out through a borrow is allowed when the place is filled again before the borrow ends). The same holds for a borrow a function returns.
- **[Access]** Before reading, borrowing, assigning or matching a place `p`: end every borrow whose loan occurs on the path to `p`, at the head of `content(p)`, or anywhere inside a neutral at the head of `content(p)` (a loan's position inside a neutral is unknown, so it is treated as the head); before reading, borrowing or assigning `p`, also end every borrow whose loan occurs anywhere inside `content(p)`. This is the borrow checker: an ended borrower becomes `⊥`, and any later use of it is an error.
- **[Read]** `p`: content a borrow → move (`p ↦ ⊥`); inside an erased term (P2), or when the type of `p` is a copy type (P3) → copy (inside an erased term, a ghost's value); otherwise → move (`p ↦ ghost(v)`, D53). Reading `⊥` is an error, and so is reading at runtime a ghost or a value holding one (a place partly moved out), or `p.1` when the head of `content(p)` is not `S` (e.g. after the parent was reassigned). `clone(p)` is a read of `p` inside an erased term.
- **[Borrow]** `&p` ⇓ `borrow_ℓ v`, with `p ↦ loan_ℓ`, ℓ fresh. Borrowing a place that holds a ghost or `⊥` anywhere inside is an error.
- **[Assign]** `p := t`: evaluate `t` to `v`; drop the old content of `p` ([Drop]); `p ↦ v`; result `()`.
- **[Let]** `let x = t; u`: evaluate `t` to `v`, bind `x ↦ v`, run `u`, [Drop] `x`.
- **[Closure]** (D51, D53) `fix f (x̄:Ā):B … := b` ⇓ a closure over the values of its free places: values, never borrows; a captured proof keeps its declared type. Forming it at runtime moves the captured places whose types are not copy types; in an erased term it copies them. Its body may not move a captured value out: the closure may run again, so a runtime read of a captured value that is not a copy is an error (`clone` it). A closure is a copy exactly when its captures are.
- **[Drop]** Dropping a value: each borrow in it ends ([End]). A live loan in a dropped *owned* value ends its borrower when the borrower is held in a binding (a variable, or a place inside one), as a write through [Access] would, repeating for the loans the ended borrow's content brings in (D65 amended: a place may die while a borrow of it is never used again). When the borrower is a value in flight (a temporary, such as the borrow a block or a function is returning), the drop is an error: nothing may return a borrow of its own local.
- **[Call]** `f(u₁,…,uₙ)` with `f = fix f (x̄:Ā):B … := b`: evaluate the arguments left to right, each into a fresh temporary binding of the current frame (so that [Access] can see and end them); a head that is a place is read in place and not consumed (D53: a function can be called again); then push a frame `x̄ ↦ w̄` (moving the temporaries' contents), run `b`, pop the frame ([Drop] its bindings), return the result. A call to a function whose class (P2) is "returns proofs" or "returns types" is erased: by P2 it is typed on a private copy and leaves the environment unchanged; a proof call returns `⋆`. A call whose head is a neutral (an abstract function `σ_f`, or a sealed program) is stuck at once and closed off, except as the head call of a sealed program being normalised, where [Seal]'s guard applies and the sealed program stays as it is (D39). If `b` gets stuck on a neutral, use [Close].
- **[Match]** `match p {…}`: head of `content(p)` is `Z` → first arm; `S v` → second arm with `y := p.1`; a neutral → stuck. A ghost (the content was moved out, D53) is an error at runtime (`[Match] on p, which was moved out`); an erased term sees through the ghost to the value it left behind. Typing: a `Z`/`S` match requires the scrutinee's stored type to normalise to `Nat`, and a match on a declared inductive requires it to normalise to that inductive; a stuck type is rejected (fail-safe; M2, rule-audit item 2).
- **[Close]** The call `f(w̄)`, at the point where its arguments have been evaluated, has a stuck body. Precondition: every argument's content is loan-free (guaranteed by [Access]). Discard the partial run. Let `I` be the positions holding borrows, `wᵢ = borrow_ℓᵢ uᵢ`. With fixed names `cᵢ`, write `L := let cᵢ = uᵢ (i ∈ I)` and `C := f(ā)` with `aᵢ = &cᵢ` for i ∈ I, `aᵢ = wᵢ` otherwise. The call returns, and each `loan_ℓᵢ` is substituted (its borrow having been consumed), according to whether the *declared* result type `B` is syntactically a borrow `&T` (D59: a `Unit` result needs no row of its own, since `Eq Unit a b ≡ True`):

  | `B` | result | each `loan_ℓᵢ` becomes |
  |---|---|---|
  | not a borrow | `⌈L; C⌉` | `⌈L; C; cᵢ⌉` |
  | `&T` (fresh k) | `borrow_k ⌈L; let r = C; *r⌉` | `⌈L; let r = C; *r := loan_k; cᵢ⌉` |

  `f` is a top-level name, or, for a stuck block, the anonymous function below.
- **[Seal]** Values are kept in normal form. For a sealed program `⌈L; C; K⌉` with head call `C`: run it from the empty environment, with `C` itself not eligible for [Close] (calls made inside `C`'s body are). A loan whose borrow lives outside the run is *inert*: it behaves like an abstract value ([Access] does not end it, [Read] copies it, [Drop] does not complain). The run has runtime semantics (D53: its moves happen, and are checked), except its final read `K`, which is an observation and copies. If the run completes, the normal form is its value; if it gets stuck, it is the sealed program with its embedded values normalised; if it hits a borrow error, that is a type error at the point that triggered the normalisation. Substituting a refinement (`σ := Z`, `σ := S σ'`) or ending a loan re-normalises.
- **Stuck blocks.** A stuck match that is not the body of a call (in a type-level term, or a non-tail match in a checked program after [Split], §5) is closed off as a call to an anonymous function of its free places, which it captures as Rust infers closure captures, on maximal place prefixes: a place the block moves out of in any arm is passed by value (moved); otherwise a place it writes or borrows (appears under `&_` or left of `:=`) in any arm is passed as `&`, unless it is a proof, which is never borrowed (D48 (1)) and is passed by value (a write through a pattern variable of a matched proof, allowed only in a proof by D45, writes a fresh value, D49 (3)); otherwise a place it reads is read in place, not consumed, as the match inspects its place (D53). A part of a place that some arm moves out is moved in on its own, at that granularity (`q.1`, not `q`), and the rest of the place is still read in place. An occurrence inside a nested `λ` or Π-type counts as a read, whatever that function does with it: a closure captures a copy, so its writes and borrows are to that copy. A closure formed inside the block that reads, through one of the block's `&` parameters, a place the block writes captures the value behind that parameter, as it would capture the place itself if the match were not closed off (fuzz-port R2). Its result type is the match's type (annotate with `let x : T = …` if it cannot be inferred from the arms). Before captures are computed, every pattern variable is resolved to the sub-place it denotes (`p ↦ (*x).1`), so a write through a pattern variable is a write to the scrutinee's place (D32). Only matches whose arms have been checked by [Split] are closed off this way; this includes matches inside types, since types are type-checked like any other term (D33).

## 4. Observation and `Id`

- **Owners.** `owners(ℓ)` is a *set*: for each occurrence of `loan_ℓ`, follow it outward. An occurrence inside the content of `borrow_m` contributes `owners(m)`; one inside an owned binding `x` contributes `x`.
- **Footprint.** `W(t, u)`: after resolving pattern variables to the sub-places they denote, for every *free* place of `t` or `u` that appears under `&_`, on the left of `:=`, or is a borrow-typed variable, its owners (`{x}` for a place rooted at an owned variable `x`; `owners(ℓ)` for one rooted at a borrow variable holding `borrow_ℓ`). Observing only some owners of a hole is unsound (meta-model C2).
- **Observation.** `⟦t⟧_Ω^W`: on a private copy of `Ω`, run `t` (closing it off as a stuck block if needed) to `⟨Ω', v⟩`; if `v` is a borrow `borrow_k u` (a borrow-typed result, as when comparing borrow-returning functions by D30), first observe `u` as the result and write a fresh abstract value through the borrow (`*r := σ_new`), so that where the borrow points is observed through its owners (D38); end every borrow in `Ω'`, and return `(v, Ω'(k) for k ∈ W)` in canonical order (R6: owners of places written or borrowed first, then those reached only through a borrow, each group by first occurrence in `t, u`; not Ω's order, which closing off can change).
- **`Id` computes everywhere** (rule-audit item 9): wherever `Id` is evaluated, the machine included (a callee's body, a sealed program's re-run), it is observed as below; a stuck side is closed off as a stuck block, so an observation exists unless the side has an error.
- **`Id` computes.** With `⟦t⟧^W = (r, w₁ … wₖ)` and `⟦u⟧^W = (r', w'₁ … w'ₖ)`, `W = W(t,u) = {x₁ … xₖ}` in the canonical order above, both run from the same Ω on independent copies: `Id A t u ≡ And(Eq A r r', And(Eq T₁ w₁ w'₁, … Eq Tₖ wₖ w'ₖ))`, `Tᵢ` the type of `xᵢ` (when `W` is empty, just `Eq A r r'`). An observation is a tuple of the machine, not a `Pair` value, so `A` may be any borrow-free type, including a proposition or a universe (D52). `A` must be borrow-free.
- **`Eq` computes** (all in Prop):
  ```
  Eq D(ā) (C(ā; v₁ … vₖ)) (C(ā; w₁ … wₖ)) ≡ And(Eq B₁ v₁ w₁, … Eq Bₖ vₖ wₖ)   same constructor, Bᵢ its field types at ā (D52; k = 0: True, k = 1: the one equation)
  Eq A a b ≡ True       when a ≡ b
  Eq Unit () () ≡ True  (D59 refined: values at Unit are η-normal, see below)
  Eq D (C ā) (C' b̄) ≡ False   when C ≠ C' are distinct constructors of D (D47)
  And(True, P) ≡ P ≡ And(P, True)
  ```
  **η at `Unit` is a property of values, not of `Eq`** (D59 refined). A value is made η-normal, i.e. replaced by `()`, wherever its type is known to be `Unit`: a parameter or abstract value whose declared type (or its evaluated declared type) is `Unit`, and the result of a call whose declared codomain, or the call's own computed result type, is `Unit`. `Eq` then decides on values alone and never reads a type. A path on which a type is still neutral keeps the value un-normalised and is only more stuck, never differently decided.
  `refl : True` (it is `True`'s constructor `I`). `J(A, a, b, P, h, t) : P(b)` for `h : Eq A a b`, `t : P(a)` (endpoints explicit, since `Eq A a a` computes to `⊤`). `J` evaluates to `t` only when `a ≡ b`; otherwise it is stuck, a neutral closed off like any stuck term (D56, Lean's rule for `Eq.rec`). Typing ([T-J-stuck], rule-audit item 5): when the endpoints are not convertible, `t` is checked against `P(a)` on a private copy and the `J` is closed off as a stuck block of type `P(b)` whose code embeds the endpoints, motive and equation as values (they are erased), so it captures only `t`'s places; `t` is not run. `Eq`'s sides and `J`'s endpoints and motive run on the private copy of the type they belong to, as `Id`'s sides do: effects discarded, not confined (D63 item 6 reversed). A `J` whose motive is a proposition is a proof and is never run, so this only affects transport of data, and it means there is no equality reflection for open terms: a cast under a false hypothesis stays a stuck cast instead of producing a value of the wrong type. Each conversion identifies two propositions with the same truth value, so the proof-irrelevant set model of Lean validates it.

## 5. Typing

Typing is the machine on symbolic inputs, plus case splitting. The typing rules for the basic forms (read, borrow, assign, constructors, pairs, `refl`, `J`, `Eq`, `Id`, Π, universes) are the evident ones and are listed in the paper; the rules below are the non-standard ones.

- **[Call-type]** At the point where the arguments of `f(ā)` have been evaluated (the point [Close] restores to), with `f : Π(x̄:Ā). B`: push a frame binding each `xᵢ` to `aᵢ`'s value (a borrow argument moved into `xᵢ`), evaluate `B` there on a private copy, and pop. That is the call's type. Each `aᵢ` must have type `Aᵢ`, evaluated with the earlier parameters bound. The free variables of `B` other than `x̄` were captured when the Π-type was formed (P2).
- **[Def]** `fix f (x̄:Ā):B … := b` is checked at its *generic call*: an environment with a fresh owned place `cᵢ ↦ σᵢ` for each borrow parameter `xᵢ : &Tᵢ`, and the call `f(ā)` with `aᵢ = &cᵢ` for borrow parameters, `aᵢ = ⋆` for parameters whose type is a proposition (proof irrelevance: every proof value is ⋆, so sealed programs embedding proofs compare equal), and `aᵢ = σᵢ` otherwise. Parameter types are evaluated left to right with the earlier parameters bound, and stored with their bindings, where [Split] refines them. The goal is the [Call-type] of that call. The body runs in the pushed frame, which is then popped with [Drop]; the result's type must convert to the goal (as refined by splits).
- **[Split]** (A match's result type is the same in every arm after refinement, or given by an annotation `let x : T = match …`, which each arm is checked against, refined.) When the checked program matches on a place whose content head is an abstract `σ`: check each arm with the refinement `σ := Z` (resp. `S σ'`, σ' fresh) applied to Ω, the goal and all stored types. If the head is a neutral that is not an abstract value (a sealed program), first generalise it: record the refinement `⌈n⌉ := σ` for a fresh `σ` of the matched place's type, which replaces every occurrence of that closed program in Ω, the goal and all stored types, *and every occurrence later re-derived* when sealed programs are re-normalised (a sealed program is a closed deterministic computation, so every derivation of it denotes the same value), then split on `σ`. Refinements are thus knowledge about neutrals, abstract values and sealed programs alike (D34). Generalisation records belong to the arm that made them (reviewer-6 A1, checker 969e3254). They are dropped when that [Split] arm ends, because sibling arms are exclusive worlds in which the same program text can have a different type (it mentions a value the arm refined). A record made while forming a type on a private copy survives the copy, since a copy stays within its arm's world (D37). Fresh abstract values are never reused. A refinement itself is not: each arm starts from the same Ω, goal and stored types, the types of the abstract values that existed before the split included (only the types of values an arm or copy creates survive it). If the match is not in tail position (trailing drops do not count), the rest of the program is checked once, from the state in which the match is closed off as a stuck block (§3).
- **[Rec]** In the body of `fix f … by xⱼ`, including inside nested functions and block arms, `f` occurs only as the head of a call, and every recursive call passes, in position `j`, a value (or a borrow whose content is a value) that is a *strict subterm of `xⱼ`'s entry value* `σⱼ`, as refined so far.
- **[Rewrite]** (D60) `rewrite h in t`, checked against a goal `G` that is a proposition, with `h : Eq A a b`: generalise every occurrence of `b`'s normal form in `G` to a fresh `σ` (the replacement [Split] uses for a sealed program, D34, local to the goal and not recorded), substitute `a` for `σ` and re-normalise, giving `G'`; check `t : G'`. The term has type `G` and is a proof (erased, value `⋆`). `rewrite ← h in t` swaps `a` and `b`. It is `J(A, a, b, λz. G[z/b], h, t)` with the motive read off the goal. Its soundness is semantic: wherever `h` holds, `a` and `b` denote the same value, so `G'` and `G` denote the same proposition. It needs a known goal: tail position, a call's argument, or an annotated `let`. A rewrite that finds no occurrence is an error. **Destructuring `let`** (surface): `let ⟨x̄⟩ = p; u` and `let (x, y) = p; u` mean `match p { C(x̄) => u }` for the single-constructor `And`/`Pair`, with nested patterns and `_`; on a term, a temporary is bound first. If `b`'s normal form does not occur in `G`, the rewrite is a no-op and `t` is checked against `G` unchanged (rule-audit C22).
- **[Split-goal]** (D61) `split f in t` / `split f { C₁(x̄₁) => t₁, … }`, checked against a goal `G`. Walk `G`'s sealed programs in pre-order, left to right. For each one, follow its chain of stuck scrutinees (each link is the neutral its run got stuck on, or an abstract value a sibling arm's split already generalised, found through the generalisation records). Take the first link that is a sealed program whose head call is `f`. Generalise it to a fresh `σ` as [Split] does (D34, recorded), then split on `σ`, checking `t` (or each `tᵢ`) under each refinement. It is [Split] with the scrutinee found in the goal rather than written as a place, and adds nothing to the model. If no such link exists, it is an error.
- **Errors (the borrow checker):** reading `⊥`, a live loan in a dropped owned value, an argument not of the parameter's type.

- **[Abstract]** (D57) An inductive may be declared `abstract`. Its constructors, and matches whose arms name them, may occur in a runtime position (not erased, P2) only inside the body of an `implemented by "sym"` declaration of the same block. In erased positions they are unrestricted, so proofs reason about the model directly. A declaration whose body uses an abstract constructor at a runtime position must be `implemented by`, unless it is a *model function*: one with a parameter or result of unsized type (`[Unsized]` below). Runtime code can never produce an unsized value to call it with, so it only ever runs inside types, proofs and `implemented by` bodies (checker: `Abstraction.ViewVal`).
- **[Implemented-by]** (D57) `def f … := b implemented by "sym"`: the checker checks `b` and runs `b` everywhere, in types, proofs and ground runs alike, and never runs `sym`. The compiler calls `sym`. Agreement between `b` and `sym` is trusted: the arrays library's eight natives and their drop glue are the trusted base.
- **[Unsized]** (D57) An inductive may be declared `unsized`. `&A` is well formed for an unsized `A`, and an unsized type never instantiates a type parameter, so generic code that moves a `T` never moves a view (Rust's implicit `Sized`). In a runtime position outside an `implemented by` body, a place whose declared type is headed by an unsized declaration occurs only as `&p`: it is never read, moved, assigned, cloned or matched.

## 8. Inductive definitions (v2.0: D45–D47)

- **Declarations.** Constructors take the inductive's parameters as leading arguments in the core (`Nil(A)`, `Intro(P, Q; h, k)`), which surface syntax may omit when inferable from the fields or an annotation; constructor values record them (D49). `inductive D (a₁ : A₁ … aₘ : Aₘ) : s := C₁(ḡ₁ : B̄₁) | … | Cₙ(ḡₙ : B̄ₙ)`, `n ≥ 0`, `s ∈ {Type₀, Prop}`. Parameters are uniform (every constructor returns `D(ā)`; no indices). Field types are first-order data (declared inductives, among them `Nat`, `Unit` and `Pair`, and `D(ā)` itself) or parameters; no `Π`, no `&` (D36). `Nat := Z | S(pred : Nat)`, `Unit := Tt` and `Pair (A : Type₀) (B : Type₀) := Mk(fst : A, snd : B)` are ordinary library declarations (D52; `()`, `A × B`, `(a, b)`, `t.1`, `t.2` notation); `False`, `True`, `And` are library declarations (§1). `Eq` stays primitive: it computes observationally (§4) and the core has no indexed families. Declared `copy` (D53): every field's type is a copy type or `D` itself, and a read of a value of `D` copies it. The library declares `copy inductive Word := Zero | Succ(pred : Word)`, the numbers that code only computes with (keys, indices, lengths, counters); `Nat` stays the structure that in-place code walks and moves. Declaring `copy` is a statement about cost, not about the logic: copying never affects soundness, since erased reads copy anyway.
- **Prop inductives are erased.** A value of a type of sort `Prop` is a proof, and its value is `⋆` (proof irrelevance); a term of declared type `D(ā)` with `D : … → Prop` is erased (P2, D42).
- **Matching on a proof is by type (D45).** A `match` whose scrutinee's type — its stored type as refined by [Split], which must normalise to an inductive head `D(ā)`, a still-neutral type being a type error (D49) — has sort `Prop` does not inspect the scrutinee's content (which is always `⋆`): with zero constructors it has zero arms (`match p {}`) and is well typed at any result type; with one constructor its single arm binds proof fields as places holding `⋆` and data fields as places holding fresh abstract values (D49); with several constructors the match is erased and every arm must be a declared proof. A zero-arm match is unreachable in any closed run. In a proof position it is erased like any proof (its value is `⋆`). Anywhere else, reaching it is *stuck* (D58): it is a neutral, closed off like a match on an abstract value, never a value of the wrong type. That can only happen under a hypothesis made false by a refinement, e.g. while a sealed program is re-normalised. [Split] on such a scrutinee is likewise by type.
- **Subsingleton elimination (D45).** A `match` on a scrutinee of a `Prop` inductive may produce a result whose type is not a proposition only if the inductive has zero constructors, or exactly one constructor all of whose fields are propositions (Lean's rule; `False`, `True`, `And` qualify, `Or` would not). Otherwise proof irrelevance plus large elimination is inconsistent (e.g. distinguishing `Inl` from `Inr` of `Or(True, True)`).
- **Constructor disjointness (D47).** `Eq D (C ā) (C' b̄) ≡ False` for distinct constructors `C ≠ C'` of the same inductive (in particular `Eq Nat Z (S b) ≡ False`). Injectivity (D52): `Eq D (C ā) (C b̄) ≡ And(Eq …)` over the fields, so together `Eq` computes on constructor values by structure, as in observational type theory; it replaces v2.0's separate rule for pairs. A pair parameter is taken apart by `match p { Mk(a, b) => … }` like any inductive; there is no η rule for single-constructor types. The unit laws `And(True, P) ≡ P ≡ And(P, True)` make `True` and `And` kernel-known library types (as Lean's kernel knows `Nat`); this is the one non-uniform point.

## 9. Dependent fields (v2.1: D64)
- **[Ind], telescopes.** A field's type may mention the constructor's earlier fields: `inductive Vec (E : Type₀) := MkVec(n : Word, items : Array(E, n))`. [Ind] checks field `j`'s type with the parameters and the fields before `j` bound to fresh generic values (a proof field to `⋆`), as [Def] binds parameters, and rejects a field type that mentions field `j` itself or a later field. An earlier field occurs only as an argument inside a later field's type. A field that some later field's type mentions is an *index field*, read off the declaration. A constructor with one is *dependent*. A type with a dependent constructor is a copy type only if declared `copy`.
- **Type functions in field types.** A field type may be a call `F(ā)` of an earlier definition whose declared codomain is a sort (`Array(E, n)`; `Sorted(xs)`, a proof field). Its arguments are parameters, fields, numerals or first-order types, none mentioning the type being declared. It must not compute to a Π-type, a borrow type, a sort or an equation at the generic telescope. *Nesting:* a parameter of `D'` is nestable when it occurs in `D'`'s field types only as a whole field type, or as an argument of an inductive at one of that inductive's nestable parameters. The type being declared may occur in `D'(…)` only at `D'`'s nestable parameters. Without this condition, `NBox(A) := MkNBox(f : Neg(A))` with `Neg(A) := Π(x : A). Void`, followed by `Bad := MkBad(b : NBox(Bad))`, is D36's attack again (ledger `k4Nest`).
- **[Field].** The type of a field place `p.g` of a dependent constructor is its declared type, with the parameters taken from `p`'s type and each earlier field bound to the current content of `p`'s field (`type(p.items) = Array(E, content(p.n))`), except while the value is open ([Open]). [Split] refines `σ := C(σ₁ … σₖ)` with each `σᵢ` fresh at its type computed from `σ₁ … σᵢ₋₁`. [T-Ctor] checks each argument against its field type computed from the earlier arguments' values. A match on a proof binds every field of a dependent constructor as a local at its telescope type. [Assign] types the value it writes by the target place's type, as parameters and fields already are ("typed by position"); this is what types a sealed fill that holds an inert loan.
- **[Open].** Writing, borrowing or moving out a field of a value of a dependent constructor *opens* the value. While it is open, a field whose declared type mentions earlier fields takes its content's type whenever the content does not have its telescope type (an abstract value's stored type, a sealed program's type, a constructor value's type). Assigning such a data field is a strong update: the value is not checked against the field's type, and the field takes the value's type. A proof field cannot be typed by its content, which is `⋆`. So a write or borrow through an index field invalidates every proof field whose type mentions it: it becomes `⊥`, and reading it is an error until it is assigned again. An assignment to a proof field is checked against its type at the current contents. For users: re-prove after you mutate, before the value must be whole again.
- **[Repack].** At every whole-again point of the checked program, a value holding values of dependent constructors must have its type by their telescopes. Each such constructor value's fields are checked against their types computed from its own earlier fields, each leaf by its own type, and there must be no `⊥` or ghost inside. The points are:
  - a place read or moved whole, so also a borrow variable passed on;
  - a place borrowed whole;
  - a borrow of the value ending, including a borrow parameter's when the function returns;
  - the result of a function or a constant;
  - `Id`'s observed result and owners;
  - a stuck block's captures;
  - a closure's or a Π-type's captures.
  A failure is a type error at that point. `*v.0 := 2; *v.1 := [0,1]` is accepted in either order: `v` is open between the writes and packed at the return. The machine's own runs (the concrete calls a checked program makes, sealed re-runs) do not check [Repack], because they are instances of generically checked code (ledger `repack`: off, a length lie proves a closed False).
- **Injectivity, restricted.** For a dependent constructor `C`, `Eq D(ā) (C(ā; v̄)) (C(ā; w̄))` computes to the conjunction of its field equations only when every index field is convertible on both sides; the field types are then computed from `v̄`. Otherwise the equation stays as it is. This is fail-safe and incomplete: OTT's full rule needs a dependent conjunction (ledger `depInj`, policy). Proof fields are `⋆` on both sides and never block. [Close], sealed programs, observation and the set model (Σ-types) are unchanged.
