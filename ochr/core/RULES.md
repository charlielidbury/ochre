## 0. Principles

- **P1 Evaluation, not rewriting.** One deterministic call-by-value machine. Definitional equality is "same normal form", normal forms being what the machine produces on symbolic inputs. The normal form of a function value is the observation of its generic call (as in [Def] and `Id`: its result together with the final contents of the generic owned places `cᵢ`), plus its captured values; so two functions are convertible only if they have the same effects (D30). A comparison that needs itself (a recursive function whose generic call is stuck on its own sealed call) answers "not convertible": sound and incomplete; assuming equality coinductively would identify any two recursive functions of the same type (lean-checker, v1.5 round). `⊥` (a moved place) is a value of its own, "moved on every path" (D84, [Join]): it is convertible with itself only, so conversion and identity of normal forms need no rule for it (D83's [Conv-bot] is retired). A comparison keeps nothing but names (D103): on every exit it puts back the state it started from, keeping only the fresh names it made (fresh names are never reused, D37), and dropping the generalisation and η-records its private runs made and their changes to [Rec]'s candidates, since its result is a boolean, which can mention nothing it made.
- **P2 Erased terms leave no trace.** Types and proofs are erased at runtime. *Which* terms are erased is a syntactic property, never decided from a normal form (D28, D35): a function (top-level or local) returns types if its codomain term is syntactically a sort, and returns proofs if its codomain term's *declared* sort is `Prop` (the sort obtained by typing the codomain term from the declared types of its heads, without normalising it); a call is erased iff its callee's class says so. The class and the [Close] row (§3) are part of the function's *type* (D54): a Π-type records the class and row determined by its codomain term when it is formed, a function value has the class and row of its declared Π-type, and two Π-types are convertible only if their classes are equal and either both or neither return a borrow (as well as their parameter types and codomains, D48). There is no separate `Unit` row: since D59, values at `Unit` are η-normal (§4), so a stuck call yields `()` wherever its declared result type reads as `Unit` (D80). So wherever a function is passed, stored or returned, the class read from the value at a call equals the class the static type promised, on every evaluation path. **Sorts are syntactic (D55).** Every term written where a type is expected (a binder's type, a codomain, a `let` annotation, the components of a Π-type, the type slots of `Eq`, `Id` and `J`, the parameter and field types of an inductive) must have a declared type (read from the declared types of its heads, without normalising, as above) that is syntactically a sort `Prop` or `Type_i`. A type whose sort is only known by computation (`T(Z)` for `T (n : Nat) : P(n)` with `P(n)` computing to `Prop`) is rejected there. The sort of a Π-type is read from declared sorts: `Prop` exactly when its codomain's declared sort is `Prop` (which is also exactly when its class is "returns proofs": impredicativity), and otherwise the largest of the declared sorts of its parameter types and its codomain, so `Π(A : Type₀). A → A` is in `Type₁`, not `Type₀` (as the paper's appendix and the checker's `piSort` already say). Since evaluation preserves declared types, a type's declared sort and computed sort coincide, so "is a proof" has one meaning: a term is a proof iff its type is a proposition, every value of a proposition is `⋆`, and conversion can never move a relevant value into a proposition. Any other term is erased iff it stands in a type position (an annotation, a Π domain or codomain, the type slots of `Eq`, `Id`, `J`, `let x : T`) or its declared type has sort `Prop`. A stuck block is erased exactly when *each of its arms* would be erased by this rule (not by the call rule applied to its computed codomain, and not by a type inferred from the arms, which is computed: lean-checker P2); an annotated `let x : T = match …` with `T` of declared sort `Prop` is erased as a whole, on both paths. Universes are not cumulative (`Prop` is not a subtype of `Type_0`); this is load-bearing. Erased terms so the machine evaluates them on a *private copy* of the environment, argument evaluation included, and discards the copy. A formed type is therefore a closed statement: everything it mentions from outside is captured by value (a Π-type is a closure over values, and may not capture a borrow), later mutation never changes it, and only a Π-type's parameters are bound later, at each call. Every erased term, nested ones included, runs on its own private copy (D68), so whatever it writes, borrows or moves, its own places or ones that outlive it, is undone with the copy. So running a proof and skipping it are indistinguishable, and the machine may skip it. The two evaluation paths agree on *whether* a term is erased because that is decided from syntax and declared types alone (D28, D35, D55), and once it is erased neither path keeps any of its effects. (D41's confinement, which made an erased term's effect on an outer place a type error as a fail-safe for disagreements about erasure, is deleted: D69.) A term's declared type is read from its heads without normalising (an abstract value embedded in a term by the reading of its type frozen when it was made, D96); a match some of whose arms are proofs and some not has no declared type, and a definition containing one is rejected, dead arms included (rule-audit item 10, one reader of declared types; 601c3ca9: rejected where it is written, since the machine reads the declared type of every term it runs). A binding's class is read from its declared type's syntax alone (D77): a call of a type function (a global whose codomain is a sort) reads as the Π-type its body is written as, through `let`s and the arms of a match, a call of the function itself saying nothing new; arms that differ while one is a Π-type have no class, and a binding of such a type is rejected; a type parameter of the function stands for the call's argument read as a type, and a `let` naming a type for that type, so `IdTy(Π(x : &Nat). Prop)` with `IdTy (A : Type₁) : Type₁ := A` reads as that Π-type; a constant that is a type reads as its value's Π-type. Whether a statement argument runs in place (a borrow cannot run on a copy) is read from its declared type too: in place exactly when it is a borrow type. The same reader reads data (D80), for P3 and §4's η: `Unit`; an inductive with its type arguments as written, read as types (a field then reads as its declared field type at those arguments); a type function's call as its body's arms, `Unit` when every arm is, and otherwise the different data types they give (the type is one of them); a call of a global function as its declared codomain with each type parameter standing for its argument as written; `()` as `Unit`, an assignment as `Unit`, a constructor as its inductive at its written parameters. It never reads a value or an evaluated type, and anything it cannot see through (a type parameter, `Nat`, an unknown) is data it says nothing more about.
- **P3 Using a variable consumes it (D53; D68, one mental model).** Reading a place moves its content out (the place becomes `⊥`), in runtime code and in statements alike. Data whose type is a *copy type* is copied instead: `Unit`, a sort, a proposition (a Π-type into proofs included: by impredicativity it is one, so its values are proofs, D100), an inductive declared `copy` (the library's `Word`, §8), and a non-recursive inductive in `Type₀` with no dependent constructor whose fields are copy types at its arguments. Copy-ness is the place's *declared* type's, read by the reader of declared types (P2, D80), never the value's or an evaluated type's: a parameter's written type; a `let`'s annotation, or else its right-hand side's declared type (a call's declared codomain with its type arguments as written, a place's declared type); a field's declared type at its parent's; a capture's binding's. So a type parameter (`x : A` with `A : Type₀`) is never a copy type, whatever an instance substitutes for it, as a generic `T` in Rust is not `Copy` without a bound (Ochr has no `copy` bounds); a type function's call is a copy type exactly when every arm of its body is one; and a type the reader cannot see through is not one. A function type into data or types is not a copy type, so reading a place that holds such a function moves it, whatever it captured (a call through a place still does not consume it). Copy-ness agrees with erasure: every declared type that is a proposition is a copy type (D100). A borrow is always moved. A *statement* (a type, a proof, a side of `Eq` or `Id`, and each argument of a call that returns a type or a proof) runs on its own private copy of the state, by these same rules, and the copy is thrown away at its end: so a statement may move or write what it likes without affecting anything outside it, but inside one statement a value is used once, as in runtime code (`Add(clone(x), x)`, not `Add(x, x)`). An argument whose value holds a borrow runs in place instead (a copy's borrow would alias). `clone(p)` copies any place explicitly; its declared type is `p`'s, so `clone` of a proof is that proof, `⋆`, a proof (D116: a proposition is a copy, D100). Reborrowing is explicit (`&*x`, `&p`).
- **P4 Close off stuck computations.** A call whose body is stuck on an abstract value is replaced by *sealed programs*: closed source programs that own their state, one for the result and one for the final content of each place the call borrowed.
- **P5 (merged into P2 in v1.3.)**
- **P6 `Id` observes.** `Id(A, t, u)` computes to `Eq` between the observations of `t` and `u`, each run on its own copy of the current environment. The observation covers the places either side writes or borrows (a borrow variable passed whole counts; one only read through does not), and an owned place moved out (D68). It is formed only between sides that leave the same type-state ([Id-typestate], D84): the same places moved, the same borrow bindings consumed, re-pointed and left moved through, and no borrow held outside a side ended inside it, so what a program may do after one side, as far as moves and borrows go, it may do after the other. A move is definite (a match drops at its join what any arm moves, [Join]), so `⊥` is compared as a value of its own: `⊥ = ⊥` is `⊤`, and `⊥` against any value is `False`. (Until D84 an equation over `⊥` was stuck, since whether a stuck block's arm moved the place could differ between an abstract and a ground run.)

## 1. Syntax

```
terms  t, u, A, B ::= x | Prop | Type_i
                    | Π(x₁:A₁ … xₙ:Aₙ). B                   n-ary dependent function type
                    | fix f (x₁:A₁ … xₙ:Aₙ) : B by xⱼ := t  n-ary function; `by xⱼ` names the decreasing parameter; without `by`, `f` is not in scope in `t` (a λ); `f` is never in scope in `Ā` or `B`
                    | t(u₁, …, uₙ)                          saturated call
                    | Nat | Z | S(t) | Unit | () | A × B | (t, u)              notation for the library inductives Nat, Unit, Pair (D52)
                    | t.i                                     field i of a type with one constructor: `let C(y₀, …, yₙ) = t; yᵢ` ([Proj], D81)
                    | Eq(A, t, u) | refl | J(A, a, b, P, h, t)                       (Eq is primitive, in Prop)
                    | D(ā) | C(t₁, …, tₖ) | match p {}                                 inductive types (with parameters ā), constructors, zero-arm match
                    | &A                                      borrow type (A borrow-free)
                    | p | &p | p := t | let x = t; u | let x : A = t; u | t; u | clone(p)
                    | match p { Z => t, S y => u }            y is the sub-place p.0, not a copy
                    | C(t₁, …, tₖ) | match p { C₁(ȳ₁) => t₁, … }   general inductives: constructors; one arm per constructor, ȳ the field places p.g
                    | Id(A, t, u)
places p ::= x | *p | p.i | p.g                              (p.g: field g of a constructor value; p.i: field i of the one constructor of p's type, the place p.gᵢ, and p.0 of a number its predecessor, D81)
declarations  [copy] inductive D (a₁ : A₁ …) : s := C₁(g₁ : B₁, …) | …   s ∈ {Type₀, Prop}; zero or more constructors; uniform parameters ā (D45, D46); fields first-order data or parameters (D36); `copy`: a copy type (D53, §8)
library       inductive False : Prop                              (no constructors)
              inductive True : Prop := I                          (refl is notation for I)
              inductive And (P : Prop) (Q : Prop) : Prop := Intro(l : P, r : Q)   (P ∧ Q, ⟨h, k⟩ are notation)
```

A Π-type whose codomain is `&T` must have at least one parameter of borrow type (D44). Scope: user-declared inductive types with several constructors and several fields, whose field types are first-order data (inductives already declared, including `Nat`, `Unit`, `Pair`, and the type being declared; no `Π` and no `&`: strict positivity in its simplest form, D36) (sub-places `p.f`; [Split] refines `σ` to `C(σ₁…σₖ)`; [Rec] strict subterms range over all fields), among them `Nat`, `Unit`, `Pair` and the Prop connectives. `&A` is the type of a variable, parameter or result only, never inside another type (no borrows inside data; closures capture no borrows). No shared borrows, no loops.

## 2. Runtime structures

```
values    v, w ::= C(ā; v̄) (Z, S(v), (), (v, w), …) | ⋆ | closures | types | borrow_ℓ v | loan_ℓ | lent_ℓ v | ⊥ | n
neutrals  n    ::= σ | ⌈t⌉
environment Ω  ::= a stack of frames of bindings  x : A ↦ v
```

- **Every binding has its declared type `A`** (D82), in every run, the machine's included: a called body's parameters are bound at the callee's declared parameter types, evaluated left to right with the earlier parameters bound (as at the generic call, [Def]), and `f` at its Π-type; a closure's or Π-type's captures at the declared types recorded when it was formed ([Closure]); a `let` at its annotation, else at its right-hand side's type, computed as typing computes it (a call's: its declared codomain at its arguments); a sealed program's cells at the lent places' declared types ([Close]); a pattern variable, a field place, at its field's type in its parent's. [Split] refines stored types. The type of a place is read off these stored types, never off the place's value (the value's own type, `typeof`, is read only for a value embedded in a term). (The checker evaluates a declared type only when something reads it, D82.) **Every temporary has a stored type too** (D104): a value in flight (an argument while later ones are evaluated and until the callee's frame binds it (D115), a call's result while [Lend] renames its label, a constructor's field, the right-hand side of an assignment, a discarded value, a result across a `let`'s drop, the join or a frame's pop) is held with the type the machine has for it at the push, the type its evaluation returned or the declared type of the position it is headed for, which its caller holds (a call's type for a body's result across the frame's pop, a stuck block's domains for its call's arguments), and none where an untyped run computed none. In a typed run every temporary has one, but a proof token `⋆` whose proposition exists only on a private copy ([Open] of a lent proof field). No rule reads it: it is state kept so that "values have their types", the consistency proof's invariant, is a predicate on the checker's state alone and covers values in flight as it covers bindings. [Split] refines it as it refines a binding's.

- `borrow_ℓ v`: a borrow; the borrowed content lives in the borrow (LLBC). `loan_ℓ`: the placeholder at the borrowed place. **A loan is a variable bound by its borrow**: it may occur anywhere inside a value, and more than once inside sealed programs.
- **Fills** (D90). A place lent to a borrow `ℓ` that a call returned holds a *fill over* `ℓ`, in one of two forms that differ only as values: a sealed program whose text holds `loan_ℓ` ([Close]'s fill, an unknown function of the hole), or `lent_ℓ v`, a known function of the hole (`v` its content: `loan_ℓ` itself at the place the borrow points into, the content with the hole lower down where it points into a part, or with no hole). A value is marked `lent_ℓ v` only where it is not already a fill over `ℓ`. `lent_ℓ v` is transparent to paths (`content(p.g)` looks through it) and counts as an occurrence of `loan_ℓ` everywhere loans are counted ([Access], [Drop], owners, [Close]'s precondition); it never reaches a value that is read, compared or observed, since [Access] ends `ℓ` first.
- `σ`: an abstract value (Lean's fvar). `⌈t⌉`: a *sealed program*, a closed program whose run is stuck; a sealed program of sort `Prop` (e.g. a stuck call of a Prop-valued function such as `Le(σ, σ')`) is a type. `⋆`: the (irrelevant) value of a proof, e.g. of `refl`.
- `⊥`: a place that has been moved out of.
- A value is *borrow-free* if it contains no `borrow_ℓ` and no live `loan_ℓ` (inert loans, see [Seal], count as borrow-free).

## 3. The machine: ⟨Ω, t⟩ ⇓ ⟨Ω', v⟩, or stuck

- **[End ℓ]** Replace `borrow_ℓ v` by `⊥` and substitute `v` for every occurrence of `loan_ℓ`. Loans inside `v` travel with it. Each `lent_ℓ w` becomes `w` lent to the live borrows whose loans `v` holds (a reborrow of `*ℓ` that outlives `ℓ` keeps every place `ℓ` was lent lent to it, as the generic call's fills then hold that reborrow's loan; D90), or plain `w` if there are none. `v` must be whole: `⊥` anywhere inside it is an error (D53: moving out through a borrow is allowed when the place is filled again before the borrow ends). The same holds for a borrow a function returns, and for the borrows an observation ends ([Obs], P6): a side of `Id` that leaves a borrow's content moved out is rejected there, as the same code is when it runs (D98).
- **[Access]** Before reading, borrowing, assigning or matching a place `p`: end every borrow whose loan occurs on the path to `p`, at the head of `content(p)`, or anywhere inside a neutral at the head of `content(p)` (a loan's position inside a neutral is unknown, so it is treated as the head); a `lent_ℓ` mark counts as a loan of `ℓ` where it stands, and the holes of a sealed program on the path to `p` (`p` below it, at an unknown position inside it) are on the path (D90); before reading or borrowing `p`, also end every borrow whose loan occurs anywhere inside `content(p)`. **Before assigning `p`** (D67), end the loans on the path to `p` and those in the part of `content(p)` that `p` owns, i.e. not inside the content of a borrow `content(p)` holds; a loan behind such a borrow, one inside a neutral there included, is left alone: [Drop] of the old content ends that borrow ([End ℓ]), carrying the loan back to its owner, where it stays live. So `x := &(*x).f` moves a cursor down, and `let y = &(*x).0; x := other; *y := 0` is accepted (as in Rust, a reborrow of `*x` is bounded by the reference `x` held, not the variable `x`). Loans inside a neutral in the owned part are still ended (fail-safe). This is the borrow checker: an ended borrower becomes `⊥`, and any later use of it is an error. An access never ends a borrow that a value in flight holds (a temporary: a call's earlier argument, an arm's result across the join, a result across a `let`'s drop or a frame's pop): that is rejected (D106), outside a statement's private copy, whose ends are discarded with it.
- **[Read]** `p`: content a borrow → move (`p ↦ ⊥`); when the declared type of `p` reads as a copy type (P3, D80), or inside `clone(p)` → copy; otherwise → move (`p ↦ ⊥`, D53), in a statement as anywhere (D68: the statement runs on its own copy). Reading `⊥` is an error, and so is reading a value holding one (a place partly moved out), or `p.0` when the head of `content(p)` is not `S` (e.g. after the parent was reassigned).
- **[Borrow]** `&p` ⇓ `borrow_ℓ v`, with `p ↦ loan_ℓ`, ℓ fresh. Borrowing a place that holds `⊥` anywhere inside is an error.
- **[Assign]** `p := t`: evaluate `t` to `v`; drop the old content of `p` ([Drop]); `p ↦ v`; result `()`.
- **[Let]** `let x = t; u`: evaluate `t` to `v`, bind `x ↦ v`, run `u`, [Drop] `x`.
- **[Closure]** (D51, D53, D80) `fix f (x̄:Ā):B … := b` ⇓ a closure over the values of its free places: values, never borrows; each captured value is recorded with its binding's declared type (a captured proof keeps its declared type), which the closure's body reads it by, as a Π-type's parameter types and codomain do. Forming it moves the captured places whose declared types are not copy types (P3), in a statement too (D68). Its body may not move a captured value out: the closure may run again, so a read of a captured value whose recorded declared type is not a copy type is an error (`clone` it), except where the body is itself a statement (a Π-type's codomain, a closure returning a type or a proof), which runs on its own copy each time (D68). 
- **[Drop]** Dropping a value: each borrow in it ends ([End]). A live loan in a dropped *owned* value ends its borrower when the borrower is held in a binding (a variable, or a place inside one), as a write through [Access] would, repeating for the loans the ended borrow's content brings in (D65 amended: a place may die while a borrow of it is never used again). When the borrower is a value in flight (a temporary, such as the borrow a block or a function is returning), the drop is an error: nothing may return a borrow of its own local. More generally (D106), the drop of a `let`'s binding while the `let`'s result is in flight, and each drop of a frame's pop while the body's result is, ends no borrow a value in flight holds, however it would end it; if it would, the definition is rejected (`[Drop] x dies while a value in flight borrows it`). (`t; u`'s drop of `t`'s value and a call's ending of its unrun borrow arguments end the very value they drop, and are not such steps.) A borrow is a whole position's value and never lies below one's root (D48), and every loan outside a sealed program is live; the checker asserts both where a place is overwritten, a binding or a discarded value is dropped (and so where a frame is popped), and where a place is read (internal errors, D111): a borrow stored inside a value would end with nothing (overwriting it found no borrow to end) and leave its lender a loan forever.
- **[Call]** `f(u₁,…,uₙ)` with `f = fix f (x̄:Ā):B … := b`: evaluate the arguments left to right, each into a fresh temporary binding of the current frame (so that [Access] can see them); an argument whose evaluation ends a borrow an earlier argument holds is rejected at that access ([Access], D106; before, at the call point), a statement argument's run on its own copy excepted; a head that is a place is read in place and not consumed (D53: a function can be called again); then push a frame `x̄ : Ā ↦ w̄` (moving the temporaries' contents: the head and the arguments stay temporaries of the caller's frame, in Ω, through everything the call does before its frame binds them, its type, [Rec]'s check, [Lend]'s marks, a proof call's ends and [Close], which takes them into its sealed programs, D115), each `Aᵢ` the declared parameter type evaluated with the earlier parameters bound (D82), run `b`, pop the frame ([Drop] its bindings), return the result. A call to a function whose class (P2) is "returns proofs" or "returns types" is erased: by P2 it is typed on a private copy and leaves the environment unchanged; a proof call returns `⋆`. A call whose head is a neutral (an abstract function `σ_f`, or a sealed program) is stuck at once and closed off, except as the head call of a sealed program being normalised, where [Seal]'s guard applies and the sealed program stays as it is (D39). If `b` gets stuck on a neutral, use [Close]. **A call whose declared result is a borrow lends every place its borrow arguments lend** (D90): before the call, every place lent to a borrow argument (its loan, a fill over it, or a mark) is marked for a label reserved then, which no borrow holds while the call runs (the callee cannot reach its caller's places, [Frame] F4); afterwards the borrow the call returns, `borrow_k w`, is ended into that label (D99): every `loan_k` and mark `lent_k` becomes the reserved label's (a mark collapsing into a sealed fill over it already there), and the result is `borrow_g w`, whether the call ran or closed off. So a call's result never has a label made before the call, though a body may return a borrow argument. So the borrows live after a call, and the places they lend, do not depend on whether it was stuck: Rust's reading of `fn f<'a>(x: &'a mut A, y: &'a mut B) -> &'a mut C`, one region per call.
- **[Match]** `match p {…}`: head of `content(p)` is `Z` → first arm; `S(v)` → second arm with `y := p.0`; a neutral → stuck. `⊥` (the content was moved out, D53) is an error (`[Match] on p, which was moved out`). The arm ends with [Join].
- **[Join]** (D84) A match leaves moved, on every path, what any of its arms moves: the moved places after it are the lattice join of the arms' end states (moved ⊔ whole = moved), each arm's net of its own refills, read from the match's syntax and declared types, never from a run. An arm's moves are the places it reads whose declared type is not a copy type (P3), the borrow variables it reads whole, through a local borrow `let r = &q` the borrowed place, and, whether or not its run reaches them, every variable a function or Π-type in it captures (not a copy) and every borrow variable it names whole; a statement (an erased term) moves nothing outside its copy. Each place is taken at its *grain*: a field step is kept only through a value whose declared type reads as an inductive with one constructor, not computed by a match (a type function's arms, a match written where a type is expected); through anything else, and wherever the match uses the place whole other than as its scrutinee, the move is of the place whole. So the generic call, where a stuck match closes off as a block that takes these places by move (below), and every instance, where one arm runs, agree. The arm that runs drops, at its end, every such place it left whole: as a by-move argument is read ([Access] ends its borrowers; a borrow is ended; a copy stays), after its own drops and before the match's value is used, which it holds as a temporary; no drop at the join ends a borrow a value in flight holds (the arm's result, or a value in flight around the match), whether through the dropped value's own loans or through an access of a lent prefix the drop reaches it by ([Access], D106; before D106 only the first was checked, and `JoinPrefix.TK` returned `⊥` at a borrow type until D53 rejected it for another reason). Matches in tail position join the same way on every path: on a known constructor, in a call's run of the body, and in each world of their split at the generic call, whose arm is checked to the body's end (D119; before it the split's worlds did not join, so the generic call ended with places whole that every instance, and the consistency proof's reference run, end with moved). So does `J`'s transported term (its one arm). A match on a value of a type with one constructor has no join (D93): with one arm there is no other path to agree with, so it leaves exactly what its arm leaves. **Entry** (D90): a match not in tail position (tail position as `checkTail` recurses: a body, a `let`'s body, a sequence's tail, an arm of a match in tail position, the one arm of a match on a proof; untyped runs track it too), and `J`'s transported term wherever `J` computes, first accesses, in the block's order, every place the stuck block it would close off as captures (K1, `blockCaptures`), ending their borrowers, whichever arm runs; if the match's declared type is a borrow, its result is lent the places the block takes by `&` and those its by-move borrow variables lend, as the block's [Close] lends them (rule 1). A tail match is split at the generic call, never closed off, so it has no entry; nor has a match on a value of a type with one constructor, which is never closed off either (D93). A place holding a fill over a live borrow is reached by ending that borrow first, as the arm's match does (D29), whichever form the fill has; generalising a sealed fill without ending it lost its hole (D90's `G1`). A place the join drops is dropped where it exists, once its parent has been reached (an unknown or sealed value of a type with one constructor refined, a lent one's borrowers ended), whatever made it exist; if it does not exist and its longest existing prefix holds `⊥` or `⋆`, nothing is dropped; otherwise the definition is rejected there, naming the place (D94): an arm that does not run is never checked, so it may name a field its constructor lacks, and the join's set is read from syntax. (Before D94 the longest existing prefix was dropped whole.) A move through `*` is decided before any run (D101): each `*` in a moved place must be of a place declared a borrow (`&T`), or the definition is rejected (`[Join] an arm of the match moves a place through * of a place not declared a borrow`), as Rust type-checks every arm; `*` of a proof, a proof field or a number in an arm that does not run was accepted before. Rust's type state after a conditional move is "moved"; Ochr, with no destructors, drops at the join. Typing: a `Z`/`S` match requires the scrutinee's stored type to normalise to `Nat`, and a match on a declared inductive requires it to normalise to that inductive; a stuck type is rejected (fail-safe; M2, rule-audit item 2).
- **[Proj]** (D81) `t.i`, for `t` of a type with exactly one constructor `C(g₀ : A₀, …, gₙ : Aₙ)`, is `let C(y₀, …, yₙ) = t; yᵢ`. On a place `p`, `p.i` is the field place `p.gᵢ` that the pattern variable `yᵢ` names: a term that reads, assigns or borrows `p.i`, or matches on it, runs as the one-arm match `match p { C(ȳ) => … }` naming it, so a proof is matched by its type (D45) and an abstract value is refined in place to `C` ([Split] with one arm, D93), never closed off. Any other term `t` is bound first, `let x = t; x.i`. `t.i` has `t`'s class: of a proof only a proof field (D45: a data field of a proof is a large elimination from a non-subsingleton), of data only a data field (a proof field of data is named by a match); so the erasure pre-pass reads `p.i` as a proof exactly when `p` is one. On a number, `p.0` is the predecessor place (`Nat` has two constructors; `p.0` exists only where the content is `S(v)`). `Pair` is not special: `.0` and `.1` are its fields because it has one constructor.
- **[Close]** The call `f(w̄)`, at the point where its arguments have been evaluated, has a stuck body. Precondition: every argument's content is loan-free (guaranteed by [Access]). Discard the partial run. Let `I` be the positions holding borrows, `wᵢ = borrow_ℓᵢ uᵢ`. With fixed names `cᵢ`, write `L := let cᵢ : Tᵢ = uᵢ (i ∈ I)`, `Tᵢ` the lent place's declared type (the argument `wᵢ`'s type is `&Tᵢ`; D82: a re-run of the program is typed by declaration like any run; sealed programs are printed without the cells' types), and `C := f(ā)` with `aᵢ = &cᵢ` for i ∈ I, `aᵢ = wᵢ` otherwise. The call returns, and each `loan_ℓᵢ` is substituted (its borrow having been consumed), according to whether the *declared* result type `B` is syntactically a borrow `&T` (D59: a `Unit` result needs no row of its own, since `Eq(Unit, a, b) ≡ True`):

  | `B` | result | each `loan_ℓᵢ` becomes |
  |---|---|---|
  | not a borrow | `⌈L; C⌉` | `⌈L; C; cᵢ⌉` |
  | `&T` (fresh k) | `borrow_k ⌈L; let r = C; *r⌉` | `⌈L; let r = C; *r := loan_k; cᵢ⌉` |

  η at `Unit` (§4, D80): the result is `()` when the call's declared result type reads as `Unit`, and `loan_ℓᵢ` becomes `()` when the place it lends is declared `Unit`, read off the call as written (the argument `&c` with `c`'s declared type reading `Unit`, or a borrow variable declared `&Unit`), never because `uᵢ` happens to be `()`.

  Each borrow argument `ℓᵢ` is consumed: its marks are removed (rule 1 has marked its places for the result if the row is `&T`). `f` is a top-level name, or, for a stuck block, the anonymous function below.
- **[Seal]** Values are kept in normal form. For a sealed program `⌈L; C; K⌉` with head call `C`: run it from the empty environment, with `C` itself not eligible for [Close] (calls made inside `C`'s body are). A program whose text holds a loan is not run (D97): a hole of a borrow that is live, or about to be returned by the call that made it, means its run could not be observed (its place is lent, and an access ends the borrow first, D90) and would write the hole in a state that does not hold the borrow; it stays sealed and runs when [End] has filled its last hole. Where its type is needed it is read off its text (the cell it reads, or its head's declared codomain). The run has runtime semantics (D53: its moves happen, and are checked), except its final read `K`, which is an observation and copies. If the run completes, the normal form is its value; if it gets stuck, it is the sealed program with its embedded values normalised; if it hits a borrow error, that is a type error at the point that triggered the normalisation. Substituting a refinement (`σ := Z`, `σ := S(σ')`) or ending a loan re-normalises a program with no hole left. A fill (a sealed program over live holes) is left alone: a refinement or a generalisation substitutes into its text, and it stays a fill over the same holes, its place lent to the same borrows.
- **Stuck blocks.** A stuck match that is not the body of a call (in a type-level term, or a non-tail match in a checked program after [Split], §5) is closed off as a call to an anonymous function of its free places, which it captures as Rust infers closure captures, on maximal place prefixes: a place the block moves out of in any arm, the join's ([Join], D84; the arms' runs are kept as an assertion that they agree), is passed by value (moved); otherwise a place it writes or borrows (appears under `&_` or left of `:=`) in any arm is passed as `&`, unless it is a proof, which is never borrowed (D48 (1)) and is passed by value (a write through a pattern variable of a matched proof, allowed only in a proof by D45, writes a fresh value, D49 (3)); otherwise a place it reads is read in place, not consumed, as the match inspects its place (D53). A part of a place that some arm moves out is moved in on its own, at that granularity (`q.0`, not `q`), and the rest of the place is still read in place; the granularity is the join's grain, so an abstract or sealed value of a type with one constructor is refined to it (D68, D84), and a lent one is reached by ending its borrowers, as the arm reaches it. An occurrence inside a nested `λ` or Π-type counts as a read, whatever that function does with it: a closure captures a copy, so its writes and borrows are to that copy. A closure formed inside the block that reads, through one of the block's `&` parameters, a place the block writes captures the value behind that parameter, as it would capture the place itself if the match were not closed off (fuzz-port R2). Its result type is the match's type (annotate with `let x : T = …` if it cannot be inferred from the arms). Each parameter is typed by its place's type and declared as its place (D80): the block's re-run reads it, copy or not, as the direct path reads the place, whatever a refinement makes of the type, and the block's result is `()` exactly when the match's declared type (its arms') reads as `Unit` (§4). Before captures are computed, every pattern variable is resolved to the sub-place it denotes (`p ↦ (*x).0`), so a write through a pattern variable is a write to the scrutinee's place (D32). The block's captures are computed first, from syntax and declared types (they do not depend on the arms' runs), and the block accesses them all, in order, before its arms are checked and before it takes any (D90, D91): otherwise it took a read-only capture through a borrow that a later capture's access ended, and its arm read a copy the direct run's arm, after the entry, cannot (`EK`), and it checked its arms in a state where borrows the entry ends were still live, which a direct run's arm never sees (`BlockEntry.IA`). An arm whose result borrows a place the block takes by move is an error (D87): that parameter dies where the arm returns, as a function's does (D65), and when the match runs directly [Join] drops the place at the end of the arm, with the same message. Only matches whose arms have been checked by [Split] are closed off this way; this includes matches inside types, since types are type-checked like any other term (D33). A match on a value of a type with one constructor is never closed off in a typed run (D93: §5, [Split]). After its entry and before its arms, a block refines in place each capture's prefix that holds an unknown (or a sealed program) of a type with one constructor, as it refines a moved place, so a captured field (`&c.0`) is a place when the block's call takes it; a fill over a live borrow is never generalised, the entry having ended that borrow first.
- **Runtime: the erased program** (D85). Running an accepted program is the machine's untyped run of a closed call of an accepted global, its proof arguments `⋆`, in *runtime mode*, which only the runtime's entry point enters (`runCall`, `Ochr/Runtime.lean`), never the checker. It has the rules of this section, with one difference:
  - **[J-run]** `J(A, a, b, P, h, t)` evaluates to `t`, unconditionally. `A`, `a`, `b`, `P` and `h` are statements (a type slot, the endpoints, the motive, the proof), which the erased program does not have, so none of them runs and nothing is compared: an erased cast is the identity. It is sound when the proof parameters' types are true: `h` then means a proof of `Eq(A, a, b)`, so `a` and `b` mean the same, and `t`, a value of `P(a)`, is a value of `P(b)` (docs/29; Lean: `Model.Safety.castRT_safe`). The checker keeps [J] and [J-stuck] (§4) in all its runs, its untyped ones included (callee bodies, [Seal]'s re-runs, private copies), so what it accepts is unchanged. At runtime [J-stuck] would stop a well-typed program at two encodings of one function (`λn. n` against `λn. match n { Z => Z, S m => S(m) }`), which no conversion identifies.

## 4. Observation and `Id`

- **Owners.** `owners(ℓ)` is a *set*: for each occurrence of `loan_ℓ` or `lent_ℓ` (D90), follow it outward. An occurrence inside the content of `borrow_m` contributes `owners(m)`; one inside an owned binding `x` contributes `x`.
- **Footprint.** `W(t, u)`: after resolving pattern variables to the sub-places they denote, for every *free* place of `t` or `u` that appears under `&_`, on the left of `:=`, or is a borrow-typed variable, its owners (`{x}` for a place rooted at an owned variable `x`; `owners(ℓ)` for one rooted at a borrow variable holding `borrow_ℓ`). Observing only some owners of a hole is unsound (meta-model C2). A place only read is not in the footprint: whether a side moves it is the type-state's ([Id-typestate]), not the observation's.
- **Observation.** `Obs^W_Ω(t)`: on a private copy of `Ω`, run `t` (closing it off as a stuck block if needed) to `⟨Ω', v⟩`; if `v` is a borrow `borrow_k u` (a borrow-typed result, as when comparing borrow-returning functions by D30), first observe `u` as the result and write a fresh abstract value through the borrow (`*r := σ_new`), so that where the borrow points is observed through its owners (D38); end every borrow in `Ω'`, and return `(v, Ω'(k) for k ∈ W)`, and what each re-pointed binding points to ([Obs-ref]), in canonical order (R6: owners of places written or borrowed first, then those reached only through a borrow, each group by first occurrence in `t, u`; not Ω's order, which closing off can change).
- **[Obs-ref]** (D84, D113) For each borrow binding in the *re-pointed* set of the sides' type-state (below; the same for both sides), of declared type `&T`, one fresh abstract value `σ_y : T` is made, and each side's observation treats `y`, after the side runs and before its borrows end, as [Obs-borrow] treats a borrow result (D38): `y`'s content, what it points to as the side left it, is taken out of the borrow as one more component of the observation, and `σ_y` is put in its place, so that the ends carry `σ_y` to the owners of `y`'s loan. The content is moved out of the borrow, not written through it (no [Access]): a reborrow of `*y` by a second re-pointed binding stays live until the ends, which fill the component with what that binding leaves. Every place a side borrows has its owners in the footprint, so the observation shows where `y` points and what it points to after each side: `Id(Unit, (y := &x; ()), (y := &z; ()))` computes to `Eq(Nat, σ_y, x) ∧ Eq(Nat, z, σ_y) ∧ Eq(Nat, x, z)`, not provable, the same target with the same writes on both sides to `⊤`, and `Id(Unit, y := &x, (y := &x; *y := 5))` to `Eq(Nat, x, 5)` (D113: D84 wrote `σ_y` through `y`, over the `5`, and that `Id` was `⊤`, although the continuation `y := &w; x` tells the sides apart). The set is read from syntax and declared types (`Decide.typeState`), never from a run.
- **[Id-typestate]** (D84) `Id(A, t, u)` is well formed only if `t` and `u` leave the same *type-state*, `TS(t) = TS(u)`. `TS(s)` is read from the syntax of `s` and the declared types of the bindings outside it, never from a run (`Decide.typeState`), in the frame where the `Id` is formed. It has four components, each a set of places of that frame at [Join]'s grain (§3), compared as sets, two places being equal only when they are the same place (`x.0` and `x` differ):
  - *moved*: the owned places `s` leaves moved: the net moves of [Join]'s analysis of `s` as a whole (its reads of places whose declared type is not a copy type, net of its refills, each match joined, the captures of the functions it forms and of the blocks its matches close off as, local borrows followed; an erased term moves nothing outside its copy), less the places of the next two components;
  - *consumed*: the borrow bindings (declared `&T`) that `s` moves whole: passed whole to a call, bound by a `let`, returned, captured, or taken by a match (K1(b): a borrow binding an arm reads or assigns whole). A reborrow `&*y` consumes nothing;
  - *re-pointed*: the borrow bindings that `s` assigns whole (`y := …`), outside erased terms, and does not consume;
  - *left open*: the places behind a borrow binding (`*y`, `(*y).0`, …) that `s` leaves moved, not refilled.

  An ill-formed `Id` is an error naming the first component that differs and a place in one set and not the other: `[Id-typestate] the left side of Id moves x, the right side does not (clone it, or move it on both sides)`; for a consumed borrow the hint is the explicit reborrow, `AddM(&*x, 0)` for `AddM(x, 0)`.
  *No ending.* While a side runs, ending a borrow that a binding or a temporary of the frame held when the `Id` was formed is an error (`[Id-typestate] a side of Id ends the borrow y, …`), whether by [Access] of what it borrows or [Drop] of what it points to, unless the binding is one the side *consumes* (D114: its type-state's, read from syntax). A consumed binding is moved on every path, so no continuation uses it after either side, and where its borrow ends depends on the path: a call's parameter ends it at one instance, a stuck block's at the generic call, the join's drop at an instance whose arm does not use it. Asking who held the borrow as it ended made the check differ by path (`A1 (n) (x : &Nat) : Id(Unit, match n { Z => Eat(x), S _ => () }, …)` was accepted and its instance `A1(1, &c)` rejected). Assigning over the binding re-points it instead, which the components compare. This check is made in the run, since which borrows the frame holds is the machine's state, not syntax. A binding the side does not consume is never dropped by it, only ended by an access; since D90 every run ends the same borrows at the same points, so the clause rejects alike on every path (before D90, `Pick`'s borrow ended at an unknown `n` was still held at `n = 1`, where a side ended it: `StaticEnds.EI`).
  *Why.* A program that is accepted with `t` must not get a move or borrow error from `u` in its place. These are all the ways a side changes what the rest of its frame may use. By D48 a borrow is held only by a borrow binding or a temporary, never inside data, and `A` is borrow-free, so the only loan a side makes that outlives it is a re-pointed binding. The rest a context can see is the result and the footprint's contents, which `Id` compares, and where a re-pointed binding points and what it points to, which [Obs-ref] compares.
- **`Id` computes everywhere** (rule-audit item 9, D82): wherever `Id` is evaluated, the machine included (a callee's body, a sealed program's re-run), it is observed as below, each side running with the typing judgement from the start (every binding there has its declared type), so a stuck match in a side is split and closed off as a stuck block, and an observation exists unless the side has an error. An owner's type `Tᵢ` below is its binding's declared type.
- **`Id` computes.** With `Obs^W(t) = (r, w₁ … wₖ)` and `Obs^W(u) = (r', w'₁ … w'ₖ)`, `W = W(t,u) = {x₁ … xₖ}` in the canonical order above, both run from the same Ω on independent copies: `Id(A, t, u) ≡ And(Eq(A, r, r'), And(Eq(T₁, w₁, w'₁), … Eq(Tₖ, wₖ, w'ₖ)))`, `Tᵢ` the type of `xᵢ`, followed by `Eq(T_y, c_y, c'_y)` for each re-pointed binding `y : &T_y`, `c_y` and `c'_y` what it points to after each side ([Obs-ref], D113) (when there are no owners and no re-pointed bindings, just `Eq(A, r, r')`). An observation is a tuple of the machine, not a `Pair` value, so `A` may be any borrow-free type, including a proposition or a universe (D52). `A` must be borrow-free.
- **`Eq` computes** (all in Prop):
  ```
  Eq(D(ā), C(ā; v₁ … vₖ), C(ā; w₁ … wₖ)) ≡ And(Eq(B₁, v₁, w₁), … Eq(Bₖ, vₖ, wₖ))   same constructor, Bᵢ its field types at ā (D52; k = 0: True, k = 1: the one equation)
  Eq(A, a, b) ≡ True       when a ≡ b
  Eq(Unit, (), ()) ≡ True  (D59 refined: values at Unit are η-normal, see below)
  Eq(D, C ā, C' b̄) ≡ False   when C ≠ C' are distinct constructors of D (D47)
  Eq(A, ⊥, v) ≡ Eq(A, v, ⊥) ≡ False   when v is not ⊥ (D84: ⊥ is a value of its own, "moved"; Eq(A, ⊥, ⊥) ≡ True by the second line)
  And(True, P) ≡ P ≡ And(P, True)
  ```
  **η at `Unit` is a property of values, not of `Eq`** (D59 refined, D80). A value is made η-normal, i.e. replaced by `()`, exactly where its *declared* type reads as `Unit` (P2's reader: `Unit`, or a type function every arm of whose body is `Unit`, such as `UU(n)` with `UU(Z) = UU(S _) = Unit`), never because a computed type is `Unit`. The positions: (1) a parameter whose declared type reads as `Unit` (the content of one declared `&Unit`), at the generic call, at every call, and wherever a Π-type's parameters are instantiated generically (conversion, [T-Pi]); (2) the result of a call whose declared result type, read off the call as written (the head's declared codomain, a global's with its type arguments as written; a stuck block's match's declared type), reads as `Unit`, whether the call runs or closes off; (3) [Close]'s fill of a lent place declared `Unit` (§3). A fresh abstract value made for anything else (a field of a split or η-refined value, a hole) is not normalised, and neither is a value under a `let` annotation or `Eq`'s and `Id`'s type slots: each keeps what it was given. So both evaluation paths normalise at the same positions, by syntax. `Eq` decides on values alone and never reads a type.
  `refl : True` (it is `True`'s constructor `I`). `J(A, a, b, P, h, t) : P(b)` for `h : Eq(A, a, b)`, `t : P(a)` (endpoints explicit, since `Eq(A, a, a)` computes to `⊤`). `J` evaluates to `t` only when `a ≡ b`; otherwise it is stuck, a neutral closed off like any stuck term (D56, Lean's rule for `Eq.rec`). This is the checker's rule; the runtime's is [J-run] (§3, D85). Typing ([T-J-stuck], rule-audit item 5): when the endpoints are not convertible, `t` is checked against `P(a)` on a private copy and the `J` is closed off as a stuck block of type `P(b)` whose code embeds the endpoints, motive and equation as values (they are erased), so it captures only `t`'s places; `t` is not run, and the places the block takes by borrow are checked whole where `t` ends, as a stuck match's are at the end of each arm (D75). `Eq`'s sides and `J`'s endpoints and motive each run on their own private copy, as `Id`'s sides do: effects discarded (D63 item 6 reversed; D68). A `J` whose motive is a proposition is a proof and is never run, so this only affects transport of data, and it means there is no equality reflection for open terms: a cast under a false hypothesis stays a stuck cast instead of producing a value of the wrong type. Each conversion identifies two propositions with the same truth value, so the proof-irrelevant set model of Lean validates it.

## 5. Typing

Typing is the machine on symbolic inputs, plus case splitting. Conversely the machine carries the same types (D82): every binding has its declared type, and a term's type is computed as typing computes it, a call's being its declared codomain at its arguments ([Call-type] without its argument checks). The two differ only where a run is stuck (the machine closes off, typing splits) and in the checks typing makes of the program (argument and field types, [Repack], D66), which the machine does not repeat for code that was checked where it was defined. The typing rules for the basic forms (read, borrow, assign, constructors, pairs, `refl`, `J`, `Eq`, `Id`, Π, universes) are the evident ones and are listed in the paper; the rules below are the non-standard ones.

- **[Call-type]** At the point where the arguments of `f(ā)` have been evaluated (the point [Close] restores to), with `f : Π(x̄:Ā). B`: push a frame binding each `xᵢ` to `aᵢ`'s value (a borrow argument moved into `xᵢ`: on the copy, the temporary or binding that held it is left `⊥`, so the borrow keeps one holder, D92), evaluate `B` there on a private copy, and pop. That is the call's type. Each `aᵢ` must have type `Aᵢ`, evaluated with the earlier parameters bound. The free variables of `B` other than `x̄` were captured when the Π-type was formed (P2).
- **[Def]** `fix f (x̄:Ā):B … := b` is checked at its *generic call*: an environment with a fresh owned place `cᵢ ↦ σᵢ` for each borrow parameter `xᵢ : &Tᵢ`, and the call `f(ā)` with `aᵢ = &cᵢ` for borrow parameters, `aᵢ = ⋆` for parameters whose type is a proposition (proof irrelevance: every proof value is ⋆, so sealed programs embedding proofs compare equal), and `aᵢ = σᵢ` otherwise. Parameter types are evaluated left to right with the earlier parameters bound, and stored with their bindings, where [Split] refines them. The goal is the [Call-type] of that call. The body runs in the pushed frame, which is then popped with [Drop]; the result's type must convert to the goal (as refined by splits). **Declared names** (D118): every declaration ([Def], [Const], an inductive declaration) is rejected before anything runs if its terms (parameter, field and result types, body) name a constant or an inductive type not in Σ at that point (an inductive type's own name in its fields aside; a function's own name in its body is its bound `self`), read from syntax, so code that no run reaches is held to it too: `unknown constant c` / `unknown inductive type D`, located at the innermost written term around the name.
- **[Split]** (A match's result type is the same in every arm after refinement, or given by an annotation `let x : T = match …`, which each arm is checked against, refined.) When the checked program matches on a place whose content head is an abstract `σ`: check each arm with the refinement `σ := Z` (resp. `S(σ')`, σ' fresh) applied to Ω, the goal and all stored types. If `σ`'s type has exactly one constructor `C` (D93), the split has one arm and is made in place: `σ := C(σ̄)` is applied to Ω, the goal and all stored types in the current world (its fields the ones this world already named for `σ`, else fresh, recorded as an η-refinement, D68, D79), and the one arm runs directly, as at an instance, never closed off as a block, with no entry and no join, whether or not the match is in tail position. If the head is a neutral that is not an abstract value (a sealed program), first generalise it: record the refinement `⌈n⌉ := σ` for a fresh `σ` of the matched place's type, which replaces every occurrence of that closed program in Ω, the goal and all stored types, *and every occurrence later re-derived* when sealed programs are re-normalised (an occurrence of that program is one equal to it exactly, its constructors' recorded parameters and its binder names included, D108: the record is a key, not a comparison) (a sealed program is a closed deterministic computation, so every derivation of it denotes the same value), then split on `σ`. Refinements are thus knowledge about neutrals, abstract values and sealed programs alike (D34). Generalisation records belong to the arm that made them (reviewer-6 A1, checker 969e3254). They are dropped when that [Split] arm ends, because sibling arms are exclusive worlds in which the same program text can have a different type (it mentions a value the arm refined). A record made while forming a type on a private copy survives the copy, since a copy stays within its arm's world (D37). Fresh abstract values are never reused. An η-refinement of a one-constructor abstract value (D68) belongs to its arm too, like a generalisation record (D79): its constructor follows from the value's type alone, but its fields are fresh abstract values whose types are read in the arm's world, where they can mention what the arm refined (a value parameter, or an earlier field of a dependent constructor), so a sibling arm takes the value apart afresh. Both kinds of record survive a private copy (notes/split-model.md; the checker's `enterWorld`/`exitWorld` are the one place this is decided). A refinement itself is not: each arm starts from the same Ω, goal and stored types, the types of the abstract values that existed before the split included (only the types of values an arm or copy creates survive it). If the match is in tail position, each arm is checked to the end of the body, and its world ends with the match's [Join], as an instance's arm does (D119). If the match is not in tail position (trailing drops do not count) and its type has several constructors, each arm is checked from the state after the stuck block's entry (§3, D91), and the rest of the program is checked once, from the state in which the match is closed off as a stuck block (§3).
- **[Rec]** In the body of `fix f … by xⱼ`, including inside nested functions and block arms, `f` occurs only as the head of a call, and every recursive call passes, in position `j`, a value (or a borrow whose content is a value) that is a *strict subterm of `xⱼ`'s entry value* `σⱼ`, as refined so far. A call is recursive when its head is the name `f` binds for itself or a nested function's capture of that name: read from syntax, never by comparing function values, which a refinement changes inside a local function's captures (D78).
- **[Rewrite]** (D60) `rewrite h in t`, checked against a goal `G` that is a proposition, with `h : Eq(A, a, b)`: generalise every occurrence of `b`'s normal form in `G` to a fresh `σ` (the replacement [Split] uses for a sealed program, D34, local to the goal and not recorded), substitute `a` for `σ` and re-normalise, giving `G'`; check `t : G'`. The term has type `G` and is a proof (erased, value `⋆`). `rewrite ← h in t` swaps `a` and `b`. It is `J(A, a, b, λz. G[z/b], h, t)` with the motive read off the goal. Its soundness is semantic: wherever `h` holds, `a` and `b` denote the same value, so `G'` and `G` denote the same proposition. It needs a known goal: tail position, a call's argument, or an annotated `let`. A rewrite that finds no occurrence is an error. **Destructuring `let`** (surface): `let C(x̄) = p; u` means `match p { C(x̄) => u }` for a `C` whose inductive has exactly one constructor (`let ⟨x̄⟩ = p; u` is And's `Intro`, `let (x, y) = p; u` Pair's `Mk`), with nested patterns and `_`; on a term, a temporary is bound first. Likewise surface notation, with no rule of its own: `match t { … }` on a term `t` that is not a place is `let x = t; match x { … }` with `x` fresh, and `if c { a } else { b }` is `match c { true => a, false => b }` on `Bool`, `true` and `false` resolved by name (no `else`: `else { () }`). If `b`'s normal form does not occur in `G`, the rewrite is a no-op and `t` is checked against `G` unchanged (rule-audit C22).
- **[Split-goal]** (D61) `split f in t` / `split f { C₁(x̄₁) => t₁, … }`, checked against a goal `G`. Walk `G`'s sealed programs in pre-order, left to right. For each one, follow its chain of stuck scrutinees (each link is the neutral its run got stuck on, or an abstract value a sibling arm's split already generalised, found through the generalisation records). Take the first link that is a sealed program whose head call is `f`. Generalise it to a fresh `σ` as [Split] does (D34, recorded), then split on `σ`, checking `t` (or each `tᵢ`) under each refinement. It is [Split] with the scrutinee found in the goal rather than written as a place, and adds nothing to the model. If no such link exists, it is an error.
- **Errors (the borrow checker):** reading `⊥`, a live loan in a dropped owned value, an argument not of the parameter's type.

- **[Abstract]** (D57) An inductive may be declared `abstract`. Its constructors, and matches whose arms name them, may occur in a runtime position (not erased, P2) only inside the body of an `implemented by "sym"` declaration of the same block. In erased positions they are unrestricted, so proofs reason about the model directly. A declaration whose body uses an abstract constructor at a runtime position must be `implemented by`, unless it is a *model function*: one with a parameter or result of unsized type (`[Unsized]` below). Runtime code can never produce an unsized value to call it with, so it only ever runs inside types, proofs and `implemented by` bodies (checker: `Abstraction.ViewVal`).
- **[Implemented-by]** (D57) `def f … := b implemented by "sym"`: the checker checks `b` and runs `b` everywhere, in types, proofs and ground runs alike, and never runs `sym`. The compiler calls `sym`. Agreement between `b` and `sym` is trusted: the arrays library's five natives and their drop glue are the trusted base.
- **[Unsized]** (D57) An inductive may be declared `unsized`. `&A` is well formed for an unsized `A`, and an unsized type never instantiates a type parameter, so generic code that moves a `T` never moves a view (Rust's implicit `Sized`). In a runtime position outside an `implemented by` body, a place whose declared type is headed by an unsized declaration occurs only as `&p`: it is never read, moved, assigned, cloned or matched.

## 6. Metatheory to establish

**Borrow ends agree on every path** (D90, the alignment property, stated in DECISIONS D90 for the consistency proof): at corresponding points of a definition's generic call and of any instance, the arms of the blocks the generic call closes off included (D91), the same borrows are live, held at the same positions, and lend the same places (as fills of possibly different forms), and the same places are moved. Canonical observation (independence from loan-ending order); frame lemma; refinement commutes with closing off (deriver-e2-v1 H6); model into CIC with proof-irrelevant Prop and propext (backward functions appear only there); consistency; adequacy (the symbolic machine commutes with substitution, so concrete runs agree with symbolic normal forms); `Id` adequacy over typed contexts, with D84's resource lemma (equal type-states and a proof of `Id` make every move and borrow error the type-state compares the same for both fillings).

## 8. Inductive definitions (v2.0: D45–D47)

- **Declarations.** Constructors take the inductive's parameters as leading arguments in the core (`Nil(A)`, `Intro(P, Q; h, k)`), which surface syntax may omit when inferable from the fields or an annotation; constructor values record them (D49). An omitted parameter is inferred from a field's type only where it stands there, at any depth, as an argument at a position declared `Prop` or `Type₀`, or declared a type in `Prop` or `Type₀` (a proposition or a type of data, a proof, a number, a data value), or as the field's whole type; one that stands only at positions of a higher universe (a type in `Type₁`, a value of such a type, a function into a universe) is not inferred from the fields, and must be written or come from the expected type (D105: the semantic model reads a parameter back from a value's type only there; decided from the declarations, `Decide.inferablePos`). An untyped run (a called body, a sealed program's re-run, the runtime) infers omitted parameters as typing does and records them too: from the fields' types (D88), and where the fields do not determine them (a constructor with no fields, a phantom parameter, only proof fields, or fields whose types a type function computes) from the type its context declares, as typing's hint: a body's declared codomain at its arguments for its tail (through `let`, `;` and match arms), a `let` annotation, a call's parameter type, an enclosing constructor's field type (D89). `inductive D (a₁ : A₁ … aₘ : Aₘ) : s := C₁(ḡ₁ : B̄₁) | … | Cₙ(ḡₙ : B̄ₙ)`, `n ≥ 0`, `s ∈ {Type₀, Prop}`. Every constructor returns `D(ā)`; there are no indices. A parameter whose declared type is syntactically a sort is a *type parameter*, any other a *value parameter* (D71); in `D(ā)` and `C(ā; t̄)` an argument at a type parameter is a type position, one at a value parameter an erased position. No parameter has a borrow type (D71). Field types are first-order data (declared inductives, among them `Nat`, `Unit` and `Pair`, and `D` itself), parameters, or equations `Eq(T, a, b)` with `T` first-order data, which are proof fields (D71); no `Π`, no `&` (D36). An occurrence of `D` in a field type may take any arguments: first-order types at type parameters, erased terms over the parameters and earlier fields at value parameters (non-uniform recursion, D71). No argument of an occurrence of `D` at a value parameter, and no part of an equation field, mentions `D`; an argument at a type parameter may mention `D` only if that parameter is nestable in `D` (§9's nesting condition, which covers `D`'s own occurrences: `DD(A) := DLeaf | DNode(x : DD(DD(A)))`); a parameter an equation field mentions is not nestable. A variable counts as mentioning what its declared type mentions (D120): no equation, type function's argument or argument at a value parameter, `D`'s own occurrences included, reads a variable whose type mentions `D` (`Pt(D2, x)` with `x : D2`; `Eq(Nat, match xs { … }, 1)` with `xs : List(LD)`), and a parameter read so (`ws : List(A)`, a field `y : A`, a value parameter `a : A`) is not nestable. An inductive `M(…)` one of whose arguments mentions `D`, at any depth, has `D`'s sort, and a parameter passed to a declaration of the other sort is not nestable (D121: a nested occurrence passes only through declarations of its own sort; `Q(PP(D))` with `PP : Prop` in a type of data, `Wrap(QW)` with `Wrap` data in a proposition, are rejected; `Q : Prop := MkQ(h : And(Q, True))` is accepted). So a family indexed by values is *Forded*: `Vec(A, n) := VNil(h : Eq(Nat, n, Z)) | VCons(m : Nat, x : A, xs : Vec(A, m), h : Eq(Nat, n, S(m)))`. `Nat := Z | S(pred : Nat)`, `Unit := Tt` and `Pair (A : Type₀) (B : Type₀) := Mk(fst : A, snd : B)` are ordinary library declarations (D52; `()`, `A × B`, `(a, b)` notation; a pair's fields `t.0`, `t.1` are [Proj]'s, D81); `False`, `True`, `And` are library declarations (§1). `Eq` stays primitive: it computes observationally (§4), and Forded families rely on it. Declared `copy` (D53): every field's type is a copy type or `D` itself, and a read of a value of `D` copies it. The library declares `copy inductive Word := Zero | Succ(pred : Word)`, the numbers that code only computes with (keys, indices, lengths, counters); `Nat` stays the structure that in-place code walks and moves. Declaring `copy` is a statement about cost, not about the logic: copying never affects soundness, since erased reads copy anyway.
- **Prop inductives are erased.** A value of a type of sort `Prop` is a proof, and its value is `⋆` (proof irrelevance); a term of declared type `D(ā)` with `D : … → Prop` is erased (P2, D42).
- **Matching on a proof is by type (D45).** A `match` whose scrutinee's type — its stored type as refined by [Split], which must normalise to an inductive head `D(ā)`, a still-neutral type being a type error (D49) — has sort `Prop` does not inspect the scrutinee's content (which is always `⋆`): with zero constructors it has zero arms (`match p {}`) and is well typed at any result type; with one constructor its single arm binds proof fields as places holding `⋆` and data fields as places holding fresh abstract values (D49); with several constructors the match is erased and every arm must be a declared proof. A zero-arm match is unreachable in any closed run. In a proof position it is erased like any proof (its value is `⋆`). Anywhere else, reaching it is *stuck* (D58): it is a neutral, closed off like a match on an abstract value, never a value of the wrong type. That can only happen under a hypothesis made false by a refinement, e.g. while a sealed program is re-normalised. [Split] on such a scrutinee is likewise by type.
- **Subsingleton elimination (D45).** A `match` on a scrutinee of a `Prop` inductive may produce a result whose type is not a proposition only if the inductive has zero constructors, or exactly one constructor all of whose fields are propositions (Lean's rule; `False`, `True`, `And` qualify, `Or` would not). Otherwise proof irrelevance plus large elimination is inconsistent (e.g. distinguishing `Inl` from `Inr` of `Or(True, True)`).
- **Constructor disjointness (D47).** `Eq(D, C ā, C' b̄) ≡ False` for distinct constructors `C ≠ C'` of the same inductive (in particular `Eq(Nat, Z, S(b)) ≡ False`). Injectivity (D52): `Eq(D, C ā, C b̄) ≡ And(Eq …)` over the fields, so together `Eq` computes on constructor values by structure, as in observational type theory; it replaces v2.0's separate rule for pairs. A pair parameter is taken apart by `match p { Mk(a, b) => … }` like any inductive; there is no η rule for single-constructor types. The unit laws `And(True, P) ≡ P ≡ And(P, True)` make `True` and `And` kernel-known library types (as Lean's kernel knows `Nat`); this is the one non-uniform point.

## 9. Dependent fields (v2.1: D64)
- **[Ind], telescopes.** A field's type may mention the constructor's earlier fields: `inductive Vec (E : Type₀) := MkVec(n : Word, items : Array(E, n))`. [Ind] checks field `j`'s type with the parameters and the fields before `j` bound to fresh generic values (a proof field to `⋆`), as [Def] binds parameters, and rejects a field type that mentions field `j` itself or a later field. An earlier field occurs only as an argument inside a later field's type. A field that some later field's type mentions is an *index field*, read off the declaration. A constructor with one is *dependent*. A type with a dependent constructor is a copy type only if declared `copy`.
- **Type functions in field types.** A field type may be a call `F(ā)` of an earlier definition whose declared codomain is a sort (`Array(E, n)`; `Sorted(xs)`, a proof field). Its arguments are parameters, fields, numerals or first-order types, none mentioning the type being declared. It must not compute to a Π-type, a borrow type, a sort or an equation at the generic telescope. *Nesting (D107):* the nestable parameters `N(D')` of an inductive `D'` are the greatest set of its type parameters each of which occurs in `D'`'s field types only as a whole field type, or inside an argument of an inductive `M(…)` at a parameter in `N(M)`, nestably again inside that argument; for `D'`'s own occurrences `M = D'` and the parameter must be in the set itself. A parameter passed to a type function, an equation, a value argument or a `Π`, or carried to a parameter outside the set, is not nestable; so is one read in those positions through a variable whose declared type mentions it (D120: `ws : List(A)` read by an equation), and one passed to a declaration of the other sort than the inductive's own (D121: `PP(A)` in a type of data). A value parameter is never nestable. `N(D')` is computed when `D'` is declared, from its fields and the stored sets of earlier inductives, by starting from every type parameter and removing those that occur elsewhere until nothing changes, and stored with the declaration. The type being declared `D` may occur in `M(…)` only at a parameter in `N(M)`, `M = D` included, with `N(D)` computed from the fields being declared. Without the condition, `NBox(A) := MkNBox(f : Neg(A))` with `Neg(A) := Π(x : A). Void`, followed by `Bad := MkBad(b : NBox(Bad))`, is D36's attack again (`DepFields.Boom2`); without it at `D`'s own occurrences, `Q(A, n) := MkQ(z : Q(Q(A, n), 1), e : Eq(Nat, n, 0)) | Stop(f : Neg(A, n))`, with `Neg(A, n)` a function type only at a successor, makes `Q(Unit, 0)` the type `Q(Unit, 0) → False` (`PositivitySelf`); and counting an own occurrence as nestable at any position lets `E(A, B, n) := MkE(z : E(B, A, 1), …) | StopE(f : Neg(A, n))` carry `B` to `Neg` (`PositivitySwap`). While `D` is checked its entry in Σ has no constructors, and a reader of the entry would answer as if `D` were empty. So a term in a field type that reads `D`'s constructors (a match on a value of `D`, with or without arms, by type for a proposition; a field projection of one; a constructor of `D`) is rejected: they are not known yet. A value argument may contain such a term without naming `D` (`W(let k : False = match b {}; k)` with `b : D`). A decision that reads them and cannot reject answers conservatively: not a copy unless declared `copy`, not a subsingleton, not a type with one constructor.
- **[Field].** The type of a field place `p.g` of a dependent constructor is its declared type, with the parameters taken from `p`'s type and each earlier field bound to the current content of `p`'s field (`type(p.items) = Array(E, content(p.n))`), except while the value is open ([Open]). A lent field's content is its borrow's content, and a marked field's the content it marks: the frame in which the type is computed binds what each earlier field stands for, never a loan, so computing a type ends no borrow (D117). [Split] refines `σ := C(σ₁ … σₖ)` with each `σᵢ` fresh at its type computed from `σ₁ … σᵢ₋₁`. [T-Ctor] checks each argument against its field type computed from the earlier arguments' values. A match on a proof binds every field of a dependent constructor as a local at its telescope type. [Assign] types the value it writes by the target place's type, as parameters and fields already are ("typed by position"); this is what types a sealed fill that holds an inert loan.
- **[Open].** Writing, borrowing or moving out a field of a value of a dependent constructor *opens* the value. A field whose declared type mentions earlier fields is a *tree field* when that type, read through the bodies of the type functions it calls, is a data inductive at every instance (`Fin1(n)` is `Void` or `One`, `Array(E, n)` an `ArrayOf`), and a *leaf field* otherwise (`Payload(b)` that is `Nat` or `Unit`, a function type at some instances, a type parameter) (D112). While the value is open, a tree field takes its content's type whenever the content does not have its telescope type (an abstract value's stored type, a sealed program's type, a constructor value's type; through a loan, its borrow's content, and through a mark, `lent_g`, the content it marks): a constructor value records its declaration and parameters, so it says which type it is a value of. Assigning a tree field is a strong update: the value is not checked against the field's type, and the field takes the value's type. Only a value whose content determines its type may be stored so (D110, D112): one whose declared type reads as a data inductive, decided from the right-hand side's declared type; anything else (a proof, a borrow, a type, a function, a number, the unit value) is instead checked against the field's declared type at the current contents of the earlier fields, as any other write is, and fails there unless it has that type. (Before D110 any value was stored: `⋆` read at the field's declared type after its index was rewritten, and a zero-arm match on it proved `False`; a borrow stored inside the value left its lender a loan nothing would fill.) A data field never holds `⋆`; one that did would be an internal error. A proof field cannot be typed by its content, which is `⋆`, and a leaf field is never typed by its content: a number, the unit value or a function does not say which instance of its field's type it was written at (and the set model reads a leaf at its field's declared type, D112). So a write or borrow through an index field invalidates every proof field and every leaf field whose type mentions it: it becomes `⊥` (a lent leaf's borrows end first, as a write to it would end them), and reading it is an error until it is assigned again. A capture by `&` at a match's entry ([Entry]) invalidates in the same way, on every path, as the stuck block's borrow of the place does when the match closes off (D112). An assignment to a proof field or a leaf field is checked against its type at the current contents. While part of the value is lent (a live loan in its fields), it is checked on a private copy in which each such borrow holds a fresh abstract value of its type (D64 amended; D112 for a leaf): the borrow may still write there, not through a field place, so nothing would invalidate the field again, and [Repack] cannot check a proof, so the proof (or leaf) must hold whatever the borrow leaves. For users: re-prove after you mutate, write a leaf's index before the leaf, and take out of a leaf what you need before its index changes.
- **[Repack], from two principles (D76).** *(W)* A value may be open only while the code that opened it runs: wherever it passes to code that relies on its type, every value of a dependent constructor inside it must have its type by its telescope (its fields checked against their types computed from its own earlier fields, each leaf by its own type), with no `⊥` inside. *(P)* The generic path treats a neutral of a dependent type as whole ([Repack] does not look inside an abstract value or a sealed program, and [Split] splits one by its telescope), so whatever produces a neutral must have checked whole the value it stands for. An abstract value stands for an argument (whole by (W) where it was passed), a field of a refined neutral, a generalised sealed program, or, at a hole, any value of its type (an axiom). A sealed program is a call ([Close]) of a function value, and every function value a checked program calls is its caller's abstract value or was formed by checking its body to its return. **[Return]:** where a checked body returns, its result and every place it holds by borrow must be whole. [Def] and [Fix] check it at the body's return (the borrow parameters' borrows then end); a stuck block is an anonymous function of its captures ([Block]), so it returns at the end of each arm: a match's arms ([Split]) and the transported term of a `J` closed off by [T-J-stuck]. Its borrow parameters are the places it takes by `&`, checked with the arm's result in the state the arm ends in, its result held. The checker forms every block in one function, `closeBlock`, which runs the arms itself and checks each return with `bodyReturns`, the same check `checkFix` makes, so a block cannot be formed without it (D72 and D75 were two producers that had forgotten it). The whole-again points follow:
  - by (W): a place read or moved whole, so also a borrow variable passed on; a place borrowed whole; the captures of a stuck block, a closure or a Π-type; `Id`'s observed result and owners;
  - by (P) at [Return]: a borrow of the value ending (a borrow parameter's when its function or block returns); the result of a function, a constant or a block's arm.
  A part of the value that is still lent (a live loan inside it) is checked as a fresh abstract value of its type, not as what its borrow holds now, since the borrow may still write any such value (D73): returning `&n` from a value whose `x : Fin1(n)` is rejected; returning a borrow of a field nothing depends on is not.
  A failure is a type error at that point. `*v.0 := 2; *v.0 := [0,1]` is accepted in either order: `v` is open between the writes and packed at the return. The machine's own runs (the concrete calls a checked program makes, sealed re-runs) do not check [Repack], because they are instances of generically checked code (without it, a length lie proves a closed False).
- **Injectivity, restricted.** For a dependent constructor `C`, `Eq(D(ā), C(ā; v̄), C(ā; w̄))` computes to the conjunction of its field equations only when every index field is convertible on both sides; the field types are then computed from `v̄`. Otherwise the equation stays as it is. This is fail-safe and incomplete: OTT's full rule needs a dependent conjunction (policy: fail-safe). Proof fields are `⋆` on both sides and never block. [Close], sealed programs, observation and the set model (Σ-types) are unchanged.
