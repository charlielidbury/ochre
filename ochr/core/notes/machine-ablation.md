# Machine ablation: which edge cases in `Machine.lean` are needed, and why

Written 2026-11-05 by the `ablation` fork, at the coordinator's request, after the user asked for `Machine.lean` to be searched for awkward edge cases like the `[Close]` `()` refill, and for each to be checked for necessity. The question behind it: every special case in the machine is a case the consistency proof must handle, and the user wants as few as possible ("complexity breeds incorrectness and lemmas not holding").

## Method

- **Switches.** Branch `probe-ablation` (commit `8b9466c5`, worktree `/home/charlielidbury/repos/ochre-ablation`, never to be merged) adds `Config.ablate : List String` and one switch at each of 34 edge cases in `Machine.lean` and `Decide.lean` (the probe's commit message says 35; it is 34). A switched-off edge case behaves as if its special case were not there: a check is skipped, a special result is replaced by the general one.
- **Runner.** `lake exe ablate k1 k2+k3 …` checks every registered program and case study (`Registry.programs ++ caseStudies`, 1,844 verdicts) once per argument, with the named switches off, and lists every declaration whose verdict differs from its expectation. With no switch off, 0 change. A run takes about 50 seconds, so no rebuild per ablation.
- **One at a time.** Each switch was run alone, plus the combinations named below.

**Limits.**
- Verdicts only. A rejection whose message or location changed is not seen, so a check that is backed up by another check (the program is still rejected, for a different reason) shows 0 changes.
- Registered programs only: scratch files, the fuzzer and the paper's displays are not run.
- A zero change on a soundness guard means the suite has no test for it, not that it can go.

Kinds of change: **soundness** = a `reject def` became accepted (a guard lost its witness); **completeness** = a true statement became rejected; **termination** = a check became undecided (out of fuel).

## The η breakdown

With the three η switches off together (#1, #3, #4), 46 verdicts change. 17 are knock-ons, failing only because a definition they use was rejected: `Functions.RunUH`, `Trees.SizeInsert`, `InPlaceTrees` `SizeInsert`, `SizeInsertRw`, `PolyLists` `AppendNilL`, `Closed`, and eleven in `Quicksort` (from `SwapIsSwapSV` and `ScanPerm`). The 29 roots:

- **19: an `Id` or `Eq` whose result part is a stuck `Unit`-returning call**, as in `Eq(Unit, ⌈let c1 = σ0; AddM(&c1, 0)⌉, ())`: `Nats.AddS`; `Numbers` `AddZero`, `AddZero'`; `ClosingOff` `RowUnit`, `RowI`; `Equality` `IdIsConj`, `IdIsEq`, `EqIsId`, `MovedBothSidesOk`; `Rewriting.RwSplit`; `Recursion.CallSite`; `Functions` `TwiceNoop`, `TwiceMZero'`, `RunU`; `InPlaceTrees.InsertMIsInsert`; `PolyLists.AppendNil`; `ArrayLemmas.SwapIsSwapSV`; `ArrayBench.B1Join`; `Quicksort.ScanPerm`. Only the result part fails, so writing the observed side as `(…; ())` should restore each one, as the user suggested. Not verified by rewriting them.
- **10: tests of η itself**: `UnitEta`, `UnitEtaUU`, `UnitNotConv`, `Numbers.UnitStill`, `ConvModel.UUEq` (from #4), and `StuckResultUnit`, `StuckResultArgs`, `ConvUnitRes`, `ConvUnitWritten`, `ComputedUnit` (from #3).

Alone, #3 changes 41 (24 roots), #4 changes 5, #1 changes 0, and #2 changes the 4 `ClosingOff` tests that the declared-copy lane's rule R2 is about.

Per-switch outputs (every changed verdict with its message) are in the ablation fork's scratchpad, `abl/<switch>.txt`; re-run any of them with `lake exe ablate <switch>` on `probe-ablation`.
